## 0. 日志抓取指引（与 overlay-frame-visibility §0 同源：测试期间实时抓取）

1. 手机连 Mac，**Console.app 选中设备**，搜索框输入
   `subsystem:com.david.Zhixia category:capture`，勾选 **Include Debug Messages**
   （`cropGate` / `stickyOverride` 均为 debug 级），点「开始」**开始流式抓取**；
2. 保持抓取开启，依次执行下述场景动作；
3. 每个场景结束后立刻在 Console 检索本场景相关日志（前缀见下表），
   确认可读后再进入下一场景；
4. 全部场景结束后 `File → Save` 导出留存，按场景分段命名。

| 日志前缀 | 含义 | 本轮验收看什么 |
|---|---|---|
| `cropGate displayedArea=… stillArea=… iou=… acceptedStill=…` | 快门时刻门禁：呈现框 vs 静帧重检的 IoU 与采纳方向（文档模式每次拍摄一行） | Case A：分歧快门 `iou < 0.70`、`acceptedStill=false`（成片=呈现框，整书候选被拒）；平整回归：典型 `iou ≥ 0.70`、`acceptedStill=true`（静帧精修保留）；搜索态手动拍 `iou=-1`（无呈现框，静帧自由检测照旧） |
| `stickyOverride iou=…` | live 双候选振荡帧：粘滞改写回锚点相似候选（仅改写帧出现） | Case B：取景跳动期可检索到（止跳在工作），锁定后消失；平整场景偶发或无 |
| `detectionTier path=live/still tier=…` | 候选择优层级 | 既有前缀，回归对照（粘滞后 tier/selectedArea 为生效值） |
| `suspiciousLock … autoCapture=suppressed` | 可疑锁定门禁抑制自动快门 | 既有前缀，回归对照 |

注：`cropGate` 的 `iou=-1` 表示无可测对（呈现框或静帧结果缺失）；**证件模式与相册导入
不产生 `cropGate` 日志**（例外路径走旧链，见 §4.2 契约）。

## A. Case A 重验：折页拍右页 ×3 形态（R4 修复核心 / FR-001~005）

**步骤**：复用 SC-001 场景（书翻到中间、左边折起，取景右页），换 **×3 种折页形态**；
每种形态等实线整框**锁定**后任其自动快门（或在确认窗内手动快门）拍摄 1 张，进预览
核对成片裁切范围；随后回 Console 检索该次快门的 `cropGate` 行。

**通过标准**：
- 成片**不含左侧折起部分**——裁切与屏幕所见锁定框一致（呈现框 = 裁切基准，R4 修复）；
- 分歧快门的 `cropGate` 行满足 **`iou < 0.70` 且 `acceptedStill=false`**
  （静帧整书候选被门禁拒绝，不覆盖呈现框）；
- 整框可见、确认窗中止、预览四角调框等上轮已过能力**不回归**。

**失败时看**：成片仍含折起部分 → 门禁未生效（对照 `CropGateAtShutterTests` /
`CropConsistencyGateTests` 是否绿 + `cropGate` 行的 `acceptedStill` 值）；整框不可见 →
坐标契约回归（转 overlay-frame-visibility OFV-001 重验）；门禁行缺失 → 核对拍摄走的是
文档模式（证件/导入路径无此日志属预期）。

## B. Case B 重验：摊开书从中线取景（R5 修复核心 / FR-006~007，FR-008）

**步骤**：摊开书平铺，从中线取景只拍右页（上轮「实线一直在跳」的场景）；观察取景框
至**稳定锁定（≤5s）**，任其自动快门 1 张；另起一轮，在取景框刚稳定未满确认窗的
**跟踪态手动快门抢拍** 1 张；两张国预览核对。随后检索本场景 `stickyOverride` 日志。
最后把右页**明显移出视场**（改对整书），观察框跟随切换的时延。

**通过标准**：
- 取景框 **≤5s 稳定不再跳动**（双候选振荡被粘滞吸收：先稳者胜）；
- 锁定自动拍成片 = **右页**（不含左页）；
- 跟踪态手动拍成片 = **拍摄瞬间屏幕呈现框所框范围**（呈现帧抢拍语义，FR-008）；
- 取景跳动期间可检索到 **`stickyOverride`** 行（止跳证据），锁定后不再出现；
- 右页移出视场后框 **≤0.5s 跟随切换**到新候选（3 帧逃逸 ≈0.2s@15fps + 检测间隙，
  不粘死旧位置）。

**失败时看**：仍持续跳动 → 粘滞未生效（对照 `CandidateStickyTests` 是否绿 +
`stickyOverride` 是否出现）；框粘死不跟随 → 逃逸路径失效（对照
`CandidateStickyTests/escapesAfterMissLimit`）；成片与呈现框不一致 → 转 A 失败链路
（`cropGate` 行取证）。

## 验收结果记录（2026-09-21，wysiwyg-crop 修复版）

**结果**：Case A ✗、Case B ✗、平整回归（SC-002/SC-003）✓。`cropGate` /
`stickyOverride` 日志行**未取得**（本轮测试未导出 Console.app 日志），以下为代码级
初步假设，待日志或新周期取证定案：

1. **Case B 止跳失效——粘滞 v1「池交替」盲区（高置信，代码可证）**：
   `CandidateSticky.apply` 仅当**当前候选池中存在**与锚相似（IoU ≥0.60）的候选时才
   改写；若 VNDetectRectangles 逐帧**交替检出**（第 N 帧只出右页、第 N+1 帧只出
   整书），无相似帧走「miss + 返回新选择」分支 → 呈现仍逐帧交替 = 持续跳动。
   v1 设计假设振荡=双候选**同池共存**择优交替；真机行为可能是**池交替**（存在性
   交替）。跟踪态手动拍成片含左页大半与该假设自洽：快门瞬间呈现框可能正处
   「整书」帧或无框帧。修复方向：miss 帧内**保持旧锚返回**（hold-through-miss），
   连续 missLimit 帧才逃逸——与 QuadSmoother 的 miss 语义对齐。
2. **Case A 含折页——两个待区分假设（需 `cropGate` 行定案）**：
   - H1 显示侧：粘滞「先稳者胜」可能先锁**整书外轮廓**（折页后外轮廓更接近纯
     矩形，检测器偏好强），呈现框本身含折起 → 门禁判定一致（IoU ≥0.70）→
     成片=整书。此时门禁按契约工作，错在**锁定对象**而非「所见非所得」；
   - H2 门禁侧：呈现锁右页但门禁误纳静帧（IoU 边界）或路径未命中。
   定案证据：分歧快门的 `cropGate iou=… acceptedStill=…` 行 + 用户当时呈现框
   所框内容的口述。
3. **转向决策**：用户同轮提出**整体对标 WPS 扫描**（取景拍照 + 版面还原两部分
   技术调研与优化，含两份 docx 对比取证：`docs/Word_WPS_*.docx` vs
   `docs/Zhixia-*.docx`），Case A/B 修复纳入新方案统筹，不再孤立打补丁。
   对比取证结论与调研报告见后续 `docs/` 新文档。
