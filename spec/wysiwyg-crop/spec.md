# Feature Specification: 所见即所得裁切（wysiwyg-crop）

**Created**: 2026-09-21  
**Status**: Draft  
**Input**: overlay-frame-visibility 真机验收反馈 + 用户澄清决策：
- Case A：折页书翻到中间、左侧折起，想拍右侧书页——屏幕实线整框出现并**锁定在右侧书页内容上**（所见正确），但快门成片**含左侧折起部分**（所得错误）
- Case B：摊开书从中线取景只拍右页——实线整框**持续跳动**（始终未锁定），手动拍一张，成片**倾斜且含左页部分**
- 代码取证根因：R4（主因）快门时刻静帧重检测结果**无条件优先**于屏幕呈现框（`detected ?? imageQuad ?? .fullImage`），折页/摊开书场景静帧选出整书外轮廓直接覆盖 live 锁定的右页框；R5（次因）右页 vs 整书双候选逐帧交替胜出，超 smoother areaJump 重置阈值 → 轨道反复重置、框跳动、永不锁定
- 决策①（R5 处理方式）：**仅止跳，先稳者胜**——候选粘滞消除振荡，不加「意图猜测」类候选偏好启发式；锁错候选靠既有缓解链路（看得见 + 确认窗内可移开中止 + 预览四角调框）
- 决策②（R4 门禁范围）：**全状态统一门禁**——有呈现框（跟踪/锁定态）即按呈现框裁切，静帧仅阈值内精修；无呈现框（搜索态）静帧自由检测
- SC-005 上轮失证教训：验收日志必须**测试期间实时抓取**

## Overview

快门成片必须与取景屏幕所见一致（WYSIWYG）。本周期修复两个违背该原则的根因：R4——快门时刻静帧重检测结果无条件覆盖屏幕呈现的取景框，导致折页/摊开书场景「锁的是右页、裁的是整书」；R5——摊开书双候选（右页 vs 整书外轮廓）逐帧交替胜出，取景框持续跳动且无法锁定。配套用单元测试钉死门禁与止跳语义，并按更新协议重验真机场景。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 锁定框即裁切框（Priority: P1）

折页厚书翻到中间、左侧折起，用户想拍右侧书页。取景器实线整框出现并锁定在右侧书页内容上；此时自动或手动快门，成片应恰好是屏幕上锁定的右页内容——不含左侧折起部分、不含整书外轮廓。

**Why this priority**: 这是「所见即所得」的核心承诺，也是上轮验收 Case A 的直接失败点。锁定态是用户明确确认过的取景意图，裁切违背它等于扫描结果不可信。

**Independent Test**: 折页书拍右页 ×3 形态，锁定右页框后快门，检查成片裁切范围；仅实现本故事即可消除 Case A。

**Acceptance Scenarios**:

1. **Given** 折页书左侧折起、实线框锁定右侧书页，**When** 确认窗计满自动快门，**Then** 成片为右侧书页内容，不含折起部分
2. **Given** 同上锁定态，**When** 用户手动按快门，**Then** 成片同样为锁定的右页框内容
3. **Given** 快门照片上静帧检测找到整书外轮廓（与锁定框显著不同），**When** 生成裁切，**Then** 锁定框优先、整书框被弃用

---

### User Story 2 - 呈现框即裁切框·全状态统一（Priority: P1）

摊开书从中线取景只拍右页，取景框呈现右页但尚未锁定（或用户不等锁定直接手动快门）。此时手动快门的成片应等于屏幕此刻呈现的框——而非静帧检测自行选择的整书外轮廓。仅当屏幕没有任何呈现框（搜索态）时，静帧检测才自由决定裁切框。

**Why this priority**: 上轮 Case B 的手动拍发生在未锁定态；若门禁只覆盖锁定态，抢拍场景仍会裁出整书。全状态统一才完整兑现 WYSIWYG。

**Independent Test**: 跟随态（未锁定）下对呈现框手动快门，检查成片与呈现框一致；搜索态手动快门行为与现状一致。

**Acceptance Scenarios**:

1. **Given** 取景框跟随右页（跟踪态、未锁定），**When** 手动快门，**Then** 成片按呈现的右页框裁切
2. **Given** 搜索态（屏幕无取景框），**When** 手动快门，**Then** 静帧检测自由选择裁切框（维持现状）
3. **Given** 平整文档，静帧检测与呈现框本就一致，**When** 快门，**Then** 静帧高分辨率精修照常生效（精度不回归）

---

### User Story 3 - 双候选止跳（Priority: P1）

摊开书从中线取景，右页矩形与整书外轮廓两个候选逐帧交替成为最优，导致实线整框持续跳动、永不锁定。本周期让跟随中的候选在合理范围内优先延续：框应稳定贴住其中一个候选（先稳定者胜），并在既定锁定时长内完成锁定，不再反复跳动。锁定到的若是用户不想要的候选（如整书），靠既有的「看得见 + 确认窗内可移开中止 + 预览四角调框」缓解——本周期不猜测用户意图。

**Why this priority**: 框跳动直接毁掉取景体验与锁定可能性，是 Case B 的另一半根因；不稳定则用户被迫抢拍，放大 R4 问题。

**Independent Test**: 摊开书从中线取景 5 秒内观察：框不持续跳动、稳定跟随某一候选；连续多次取景不出现交替振荡。

**Acceptance Scenarios**:

1. **Given** 摊开书从中线取景（双候选场景），**When** 持续取景 ≤5s，**Then** 实线框稳定跟随单一候选，无逐帧交替跳动
2. **Given** 跟随某候选中，**When** 该候选持续存在且稳定，**Then** 按既有锁定时长正常进入锁定态
3. **Given** 跟随某候选中，**When** 用户明显改变取景（候选离开视场/新候选显著更优），**Then** 跟随切换，不粘死旧位置

---

### User Story 4 - 平整文档精度不回归（Priority: P1）

静帧高分辨率重检测对平整文档的裁切精修（贴边吸附、透视校正）是既有价值（SC-003 所见即可裁 ≥4/5、SC-002 近拍不裁边都依赖它）。门禁引入后，一致场景下精修必须原样保留——只有显著偏离时才弃用静帧结果。

**Why this priority**: 修复不能以回归既有通过项为代价；SC-002/SC-003 是上轮刚验收通过的资产。

**Independent Test**: 既有平整文档验收场景重验（SC-002 ×10+近拍、SC-003 ×5）+ 既有单测全绿（断言零修改）。

**Acceptance Scenarios**:

1. **Given** 平整 A4 取景锁定，**When** 自动快门，**Then** 成片裁切精度与修复前一致（按边缘裁切）
2. **Given** 全量单元测试，**When** 运行，**Then** 既有 302 用例断言零修改全绿，基线只增不减

---

### User Story 5 - 验收闭环与日志证据（Priority: P2）

门禁决策（一致性度量值、采纳/弃用）与止跳行为需有可追溯日志；真机验收按更新协议重跑 Case A/B 及平整回归场景，且本轮必须用 Console.app 实时抓取日志（上轮 SC-005 因未实时抓取而失证）。

**Why this priority**: 上轮验收因日志缺失无法量化检测行为；可追溯性是后续诊断效率的保障。

**Independent Test**: 验收期间 Console.app 可检索到门禁决策日志；验收清单结果回填。

**Acceptance Scenarios**:

1. **Given** 快门发生且静帧检测结果与呈现框不一致，**When** 查看设备日志，**Then** 可检索到门禁弃用记录（含一致性度量值）
2. **Given** 真机验收完成，**When** 汇总，**Then** Case A/B 通过 + 平整回归通过 + 日志归档

### Edge Cases

- 快门瞬间恰逢轨道重置/检测帧间隙（呈现框短暂陈旧）：门禁取框来源需明确（plan 定义，如取 smoother 最近输出），不应因瞬时缺口退回静帧自由检测
- 同一文档的轻微透视/精修差异（静帧与呈现框小偏差）：必须判为一致并采纳精修，不能误伤 US4
- 粘滞期间候选消失（翻页/遮挡/移出视场）：必须回落搜索态，禁止粘死已消失的候选
- 确认窗与门禁协同：自动快门天然发生在锁定态（门禁适用）；手动快门任何状态适用门禁规则
- idCard 模式呈现框为固定窗口：本周期不改 idCard 路径，其行为保持现状
- 相册导入（无 live 呈现框）：静帧自由检测，行为不变

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 快门裁切一致性门禁——快门时刻若存在呈现框（跟踪/锁定态），裁切框 MUST 以呈现框为基准
- **FR-002**: 静帧检测结果仅在「与呈现框一致（量化阈值内）」时 MAY 作为精修采纳；一致性度量与阈值在 plan 定义，折页整书框 vs 右页框级别的显著偏离 MUST 判为不一致
- **FR-003**: 不一致时呈现框 MUST 优先（静帧结果弃用）；一致时静帧精修结果优先（保平整精度）
- **FR-004**: 搜索态（无呈现框）快门 MUST 维持现状：静帧自由检测
- **FR-005**: idCard 模式与相册导入路径行为 MUST 不变
- **FR-006**: 候选粘滞——live 跟随中当前候选在合理范围内 MUST 优先延续，双候选交替不得引起轨道反复重置与框跳动
- **FR-007**: 粘滞 MUST 有逃逸路径：候选消失或新候选显著更优时切换/回落，不得粘死
- **FR-008**: 门禁与粘滞语义 MUST 由新增单元测试钉死；既有测试断言零修改；测试基线 302 只增不减
- **FR-009**: 门禁决策 MUST 留诊断日志（呈现框、静帧框、一致性度量、采纳/弃用），测试期间可实时抓取
- **FR-010**: 真机验收协议 MUST 更新并执行：Case A/B 重验 + 平整回归（SC-002/003）+ Console.app 实时日志（SC-005 补证）

### Key Entities

- **呈现框（displayed quad）**: 屏幕当前呈现的取景框（照片归一化空间）；跟踪态为 smoother 输出，锁定态为锁定 quad，搜索态为空
- **静帧检测框（still-detected quad）**: 快门时刻对高清静帧重检测（可含贴边吸附）得到的结果
- **一致性判定（consistency gate）**: 呈现框与静帧检测框之间的一致性度量与阈值判定，决定精修采纳或弃用
- **候选粘滞（candidate stickiness）**: live 跟随中当前候选的延续优先机制，含延续容差与逃逸条件

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Case A 重验——折页书拍右页 ×3 形态，锁定右页框后快门，成片 100% 不含折起部分
- **SC-002**: Case B 重验——摊开书从中线取景 ≤5s 框稳定不跳；呈现右页框时手动快门，成片 = 呈现框内容
- **SC-003**: 平整回归——SC-002 平整 ×10 ≥8 一次锁对、近拍不裁边；SC-003 ≥4/5 按边缘裁切（与上轮持平）
- **SC-004**: 单测基线 302 → 只增不减、0 failed、known issue 豁免保持；新增门禁/粘滞用例全绿
- **SC-005**: 日志证据——验收期间 Console.app 实时抓取，门禁决策日志（含度量值）可检索并归档

## Assumptions

- 一致性度量与阈值（IoU / 顶点距离 / 混合）由 plan 阶段定义；spec 只约束「同文档小偏差判一致、整书 vs 单页级偏离判不一致」
- 候选粘滞的延续容差与逃逸条件由 plan 阶段定义；止跳不引入「意图猜测」类启发式（用户决策①）
- 检测器本体（三级检测链、参数集）不改动；止跳在轨道/候选选择层实现
- R3（折页曲边非矩形）仍是检测器物理上限，不在本周期范围；其缓解链路（可见 + 可中止 + 预览调框）在 R4 修复后真正闭合
- 既有节奏参数不变：15fps 检测、0.55s 锁定、0.4s（6 帧）确认窗、QuadSmoother 其余参数
- 目标设备与构建签名路径不变（iPhone 13「菀墨」，DEVELOPMENT_TEAM=VV865TW6B3）
