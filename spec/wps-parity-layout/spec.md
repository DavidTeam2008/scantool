# Feature Specification: 版面还原对标 WPS（wps-parity-layout）

**Created**: 2026-09-22  
**Status**: Draft  
**Input**: 调研报告 `docs/11-wps-parity-research.md` 评审通过；用户决策：① restored 档降级为可选「高保真」档（不退役）；② v1 表格聚类器退役（几何通路不再产表）；③ 丢字若属 OCR 行级漏识，以哨兵日志证据为通过标准。

## Overview

将扫描件的 Word 导出默认产物从「底图+遮罩+文本框」像素合成（restored 档）切换为与 WPS 扫描同族的流式可编辑文档（段落按阅读序、图片区域抠图内联、原生表格），并根治三类质量缺陷：假表格（v1 无锚点聚类器）、静默丢字（表格/条码框内行剔除与边缘规则误剔）、段落碎片化。像素合成档降级为用户可选的「高保真」档保留。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 默认导出即干净流式文档 (Priority: P1)

用户扫描一页练习册并导出 Word：打开即是流式可编辑文档——标题、说明、练习、故事按阅读顺序排列成段，图片区域以抠图内联，没有任何假表格；不再需要在两档间手动挑选来规避乱版。

**Why this priority**: 「布局乱 + 假表格」是对标 WPS 的最直接痛点（2026-09-21 docx 取证：14 行假表格 + 碎片化文本框）；默认档位决定所有用户的默认体验。

**Independent Test**: 用语法练习页样本（金标准输入）导出默认 Word，断言流式段落结构、零假表格、阅读序与 WPS 产物一致。

**Acceptance Scenarios**:

1. **Given** 金标准语法页已扫描入库，**When** 用户在还原页直接点导出，**Then** 生成 docx 为流式文档（阅读序段落/行内图/原生表），不再是底图铺底+遮罩+文本框合成结构
2. **Given** 同一页在 iOS 26+ 真机解析，**When** 通路决策发生，**Then** 系统结构化识别优先生效（或失败原因可在日志检索）；散排文字页不产出表格
3. **Given** 散排编号填空文本（"(9)…(18)" 类），**When** 几何回退通路解析，**Then** 不产出任何表格（v1 退役，宁缺毋假）

---

### User Story 2 - 不再丢字 (Priority: P1)

用户导出后核对内容：页面上肉眼可见的每一句文字，要么出现在导出文本中，要么有可检索的哨兵日志说明其被判定为 OCR 漏识；不再出现「掩码盖掉原文、文本框又没生成」式静默丢失（如 2026-09-21 丢失的 "wrong bus!"）。

**Why this priority**: 文字完整性是文档还原的底线信任问题，静默丢字不可接受。

**Independent Test**: 用语法练习页导出并逐句对照原文：核对故事结尾 "wrong bus!" 的存在性，或哨兵日志给出明确漏识证据。

**Acceptance Scenarios**:

1. **Given** 落入表格/条码区域的文字行，**When** 解析剔除发生，**Then** 该行文字进入对应结构（单元格/条码说明）或文字层，不静默丢弃
2. **Given** 页面中的正文短句（≤10 字符，如 "wrong bus!"），**When** 页眉/页脚/边缘剔除规则运行，**Then** 正文短句不被误剔
3. **Given** 原页存在墨迹但文字层无对应文本的区域，**When** 导出执行，**Then** 丢字哨兵在日志输出该区域与原因分类，且不阻断导出

---

### User Story 3 - 大图形区域完整内联 (Priority: P2)

用户扫描含漫画条/插图的页面：流式文档中漫画条整块抠图内联在正确阅读位置（对标 WPS 对 1021×2496 漫画条的处理），不被拆碎、不被误判为文字或表格。

**Why this priority**: 图文混排页是 WPS 对标的第三类验收样本；漫画条类细长大图形是当前检测能力的未验证区。

**Independent Test**: 用图文混排页导出，检查漫画条区域为单张完整内联图且位置正确。

**Acceptance Scenarios**:

1. **Given** 含细长竖条大图形的页面，**When** 流式档生成，**Then** 该图形整块抠图内联于阅读序原位
2. **Given** 图形区域与邻近文字列，**When** 区域分类，**Then** 图形不吞并文字列、文字不混入图形

---

### User Story 4 - 段落成段可读 (Priority: P2)

导出文本的段落粒度对齐 WPS：同块连续行合并成段（行距/缩进聚类），不再是逐行碎段（2026-09-21 取证：碎片化 83 段 vs WPS 成段 42 段量级）。

**Why this priority**: 段落粒度直接决定「像不像一个正常文档」，是观感对标的核心指标之一。

**Independent Test**: 语法页导出段落结构对照金标准（WPS 产物）：段落数与顺序对照表。

**Acceptance Scenarios**:

1. **Given** 同一文字块的连续行（行距小于块间距），**When** 段落聚类，**Then** 合并为一个段落
2. **Given** 金标准对照度量，**When** 统计段落数，**Then** 收敛至金标准 ±30% 量级

---

### User Story 5 - 高保真档可选保留 (Priority: P2)

需要像素级保真的用户可在预览/导出时切换到「高保真」档（原 restored 像素合成）；默认始终为流式档。

**Why this priority**: restored 档仍有「所见即扫描原样」的价值场景；降级保留满足小众需求且不拖累默认体验。

**Independent Test**: 切换档位后，预览与导出一致反映所选档。

**Acceptance Scenarios**:

1. **Given** 还原预览页，**When** 用户切换档位为「高保真」，**Then** 预览显示像素合成版面，导出产物同档
2. **Given** 用户未做任何选择，**When** 进入还原页，**Then** 默认档为流式

---

### Edge Cases

- 结构化识别在 iOS 26+ 真机失败/超时 → 几何回退 + 明确原因日志（通路决策可观测）
- 低版本 iOS（<26）设备 → 几何通路，无表格产出（宁缺毋假，用户已决策）
- 老版本已保存的还原文档在新版本打开 → 档位语义兼容，不崩溃不错乱
- 多页文档混合页型（真表格页 + 散排页）→ 逐页独立通路决策
- 漫画条与窄文字列空间相邻 → 区域分类不混淆
- restored 档既有测试资产（约千行级）→ 处置策略不破坏 317 基线

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 默认导出与预览档 MUST 为流式重建文档（阅读序段落、行内图片、原生表格）；像素合成档降级为用户可选「高保真」档
- **FR-002**: iOS 26+ 设备解析 MUST 优先使用系统结构化文档识别；不可用/失败时 MUST 记录明确原因（通路决策日志）并回退几何通路
- **FR-003**: 几何回退通路 MUST NOT 产出表格（v1 聚类器退役）；表格仅可来自结构化识别或锚点驱动的 v2 检测
- **FR-004**: 落入表格/条码区域的文字行 MUST NOT 被静默丢弃——必须进入单元格、条码说明或文字层之一
- **FR-005**: 页眉/页脚/边缘剔除规则 MUST NOT 误剔正文短句（收紧字符数边界与位置约束）
- **FR-006**: 导出前 MUST 执行墨迹-文本对账：原页有墨迹但文字层无对应文本的区域输出丢字哨兵日志（区域+原因分类），不阻断导出
- **FR-007**: 大图形区域（细长漫画条类）MUST 整块抠图内联于流式档阅读序原位
- **FR-008**: 段落聚类 MUST 将同块连续行合并成段，段落粒度以金标准对照收敛
- **FR-009**: 预览与导出 MUST 提供一致的「流式（默认）/高保真」档位选择
- **FR-010**: 既有导出安全约束 MUST 保持（非法字符清洗、损坏文件防护、高保真档每页单图约束）

### Key Entities *(include if feature involves data)*

- **导出档位**: flow（流式，默认）/ highFidelity（高保真，像素合成）；用户可选，同时作用于预览与导出
- **通路决策**: 每页解析时结构化/几何通路的选择结果与失败原因，日志可观测
- **丢字哨兵**: 墨迹区域与文字层对账产出的缺口报告（区域、原因分类：结构吞噬/边缘误剔/OCR 漏识）
- **金标准样本**: 语法练习页原图 + WPS 导出产物 + 智侠 2026-09-21 产物对照（`docs/` 取证资产）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 金标准语法页默认导出：零假表格（w:tbl 仅当页面确有真表）；阅读序与 WPS 产物逐段一致
- **SC-002**: "wrong bus!" 类故事结尾文本出现在导出文本中，或丢字哨兵日志给出明确 OCR 漏识证据
- **SC-003**: 真表格样本页（营养成分表类）导出：真表格完整保留（v1 退役不误伤）
- **SC-004**: 图文混排页：大图形区域单张完整内联、阅读位置正确
- **SC-005**: 语法页导出段落粒度收敛至金标准 ±30% 量级
- **SC-006**: iOS 26+ 真机解析通路决策日志可检索，结构化通路对金标准样本生效（或失败原因明确）
- **SC-007**: 单测基线 317 只增不减

## Assumptions

- 本周期范围仅还原文档链（docx 导出）；PDF 导出与 capture 链不动（capture 对标归周期 2 wps-parity-capture）
- restored 档降级为可选「高保真」档保留（不退役）；其测试资产处置在 Phase 2/3 规划
- "wrong bus!" 若确认为 OCR 行级漏识（检测器物理上限），以哨兵日志证据为该点通过标准（用户已决策）
- 低版本 iOS 设备无表格产出可接受（宁缺毋假，用户已决策）
- 真机验收依赖用户提供样本：语法页原图、真表格页、图文混排页（不阻塞开发阶段，验收前到位）
- 金标准 = `docs/11-wps-parity-research.md` 取证的两份 docx + 用户提供的原图
- 全局铁律不变：`ServiceProtocols` 协议签名不变、Domain 纯函数无 I/O、纯离线、既有测试断言零修改
