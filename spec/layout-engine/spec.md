# Feature Specification: 版面布局引擎（Layout Engine）

**Created**: 2026-09-18
**Status**: Draft
**Input**: User description: "版面还原功能：内容版面比较复杂时，预览和导出的 word 会乱掉，文字区域有偏移，比较乱，文字区域重叠，字挤在一起，没法看。可以先布局好，然后把文字放在合适的区域。"（layout-restore 真机验收缺陷迭代；5 项澄清决策已确认：完整引擎一轮到位 / 文字完整优先 / 行几何保真 / 表格行高封顶+实测列宽 / 目录 spec/layout-engine）

## Overview

版面还原档在复杂版面（多栏、表格、图文混排）下出现三类症状：文字区域偏移、区域互相重叠、字挤在一起不可读。诊断确认的根因是：字号/行距由页高常数推导而从不实测（实测中位行高在三处算出后即丢弃）、两个渲染器都允许文字溢出区域（预览无裁剪、Word 无自适应）、块内行几何在聚类时被丢弃后按默认行距均匀重排、块区域天然可能相交且全链路无碰撞消解、表格两端行为相反（预览截断 vs Word 无界增长）、字号钳制基准双端不一致。

本特性新增**版面布局引擎**：在文档解析层对一页的全部版面元素做一次确定性区域布局——区域碰撞消解、基于实测行高/行距的字号校准、行几何保真、放不下时的"缩字号→扩区域"溢出阶梯、表格几何修复。预览、Word 导出、覆盖层三方消费同一份布局结果，从源头保证双端同构。结构化档与可搜索 PDF 零回归。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 区域布局消解（Priority: P1）

用户扫描复杂版面（双栏教材/试卷：双栏正文 + 跨栏标题 + 表格 + 插图），打开还原预览：每个文字区域互不重叠、没有文字压在表格上、没有文字叠在插图上形成"底座原字迹 + 上层重排文本"的双影；导出 Word 与预览同构。

**Why this priority**: 用户报告的核心症状（区域重叠、乱）直接由此消除；布局结果是字号校准、行几何、溢出阶梯的地基，其余故事都建立在"区域已消解"之上。

**Independent Test**: 合成复杂夹具（双栏 + 表格 + 插图）→ 解析 → 断言消解后文字块/表格块区域两两不相交、预览与 Word 与覆盖层消费同一区域集合、阅读顺序不变。

**Acceptance Scenarios**:

1. **Given** 双栏 + 表格混排页，**When** 版面还原，**Then** 任意两个文字块、文字块与表格、表格与表格区域不相交，且块序（阅读顺序）与消解前一致
2. **Given** 文字行与表格边缘骑跨（识别框相交但行中点在表外），**When** 消解，**Then** 该行所在区域与表格不相交且文字内容保留
3. **Given** 分栏失败产生的横贯整页宽行（跨栏内容），**When** 消解，**Then** 不产生与两栏内容同时相交的块，各栏内容完整
4. **Given** 图上的正常说明文字（高置信），**When** 消解，**Then** 允许文字区域与插图相交（说明字叠图语义，文字层在前），不判定为重叠缺陷

---

### User Story 2 - 实测字号与行距（Priority: P2）

用户扫描密集小字页（试卷/练习册），预览与 Word 中的字号贴近原始大小，不再被放大 1.5~1.8 倍导致换行增多、行高超标、文字溢出区域；同一产物在预览与 Word 中字号的相对页高比例一致（钳制基准统一），标题层级保留。

**Why this priority**: "字挤在一起"的主因；与 US1 并列构成可见性最大的两项修复，但依赖 US1 的区域结果承载扩展。

**Independent Test**: 合成密集页夹具（实测行高 ≈ 页高 1.0%）→ 断言字号由实测行高推导且不超过实测行高的既定放大系数；同一产物双端字号/页高比例相等。

**Acceptance Scenarios**:

1. **Given** 密集页（实测中位行高 < 页高 1.4%），**When** 版面还原，**Then** 正文字号不超过实测中位行高的 1.2 倍比例
2. **Given** 同一解析产物分别渲染预览与导出 Word，**When** 对比，**Then** 两端字号/页高比例一致（钳制上限不再一端触发另一端不触发）
3. **Given** 含标题的页面，**When** 版面还原，**Then** 标题与正文的相对字号层级保留

---

### User Story 3 - 行几何保真（Priority: P3）

块内多行文字按原始行间距与行首水平位置呈现：原缩进保留、疏密不一的行距保留，不再因"默认行距均匀重排"造成块内水平漂移与垂直累积漂移；Word 中文字保持可编辑的段落形态。

**Why this priority**: "文字区域有偏移"的主因；在区域与字号正确之后，块内保真决定最终观感。

**Independent Test**: 夹具构造含 3 行不同行距、不同行首偏移的块 → 断言预览与 Word 按实测行距与行首偏移还原（数值断言）；断言 Word 中该块为普通可编辑段落（非逐行浮动对象）。

**Acceptance Scenarios**:

1. **Given** 块内行距疏密不一（如列表项与段中标题相邻），**When** 渲染，**Then** 行间距按实测值还原，不从第二行起累积漂移
2. **Given** 块内各行行首参差（缩进/居中标题），**When** 渲染，**Then** 行首水平位置按实测偏移还原
3. **Given** 版面还原档的任意文字块，**When** 在 Word 中点击，**Then** 文字为可编辑段落（不采用逐行绝对定位的浮动对象）

---

### User Story 4 - 溢出阶梯（Priority: P4）

个别 OCR 识别框明显小于实际文字量时（错检/紧凑排版），区域先缩小字号（至下限），仍放不下则向下扩展吸收空白带；文字永不截断，预览与 Word 行为同构。

**Why this priority**: 保证"任何页面文字零丢失"的兜底闭环；出现频率低于前三者但决定下限体验。

**Independent Test**: 夹具构造"文字量大于识别框"的块 → 断言走阶梯后无截断、向下扩展只吸收空白带且不侵入下方元素。

**Acceptance Scenarios**:

1. **Given** 块内文字按实测字号超出识别框高度，**When** 布局，**Then** 先降字号至下限，仍未放下则区域向下扩展吸收空白带
2. **Given** 扩展方向存在空白带，**When** 区域扩展，**Then** 扩展后不与下方元素相交
3. **Given** 字号已到下限且空白带耗尽仍放不下（极端错检），**When** 布局，**Then** 保持文字完整不截断，记录结构化日志

---

### User Story 5 - 表格几何（Priority: P5）

Word 中的表格不再无界增长下坠压住下方文字；列宽按实测列边界分配（不再一律均分）；预览表格网格按同一列宽绘制，不再因截断丢字；双端遮挡关系一致。

**Why this priority**: 表格是复杂版面的高频元素，但修复面相对独立，可最后收口。

**Independent Test**: nutrition 表格夹具 → Word 断言行高受表格区域约束、列宽按实测分配（结构化识别通路）；预览断言网格列宽与 Word 同比例。

**Acceptance Scenarios**:

1. **Given** 单元格内容较多的表格，**When** 导出 Word，**Then** 默认行高受表格区域约束不无界增长，放不下时先缩字号、仍放不下行高按需增长且预览同构，内容不截断
2. **Given** 结构化识别通路（含列边界信息）的表格，**When** 双端渲染，**Then** 列宽按实测列边界分配，预览与 Word 同比例
3. **Given** 几何回退通路（无列信息）的表格，**When** 渲染，**Then** 列宽均分兜底，行为不劣化

---

### Edge Cases

- **三栏或栏间距过窄的页面**（现有分栏器最多切一刀）：引擎仍须产出不相交布局——跨栏行作为整宽区域处理，各栏内容让位且完整保留
- **表格区域与插图区域相交**：按确定性优先级消解并记录日志（优先级在方案阶段定死），双方内容均不丢失
- **整页无文字**（纯图页）：布局退化为现有行为，零扰动
- **简单版面**（单栏纯文本）：布局结果不劣化现状（简单页零扰动原则）
- **极端密集页**（实测行高小于字号下限对应行高）：接受字号下限带来的轻微溢出，走溢出阶梯兜底

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 版面还原档下，系统 MUST 保证同一页任意两个文字块、文字块与表格块、表格块与表格块的区域不相交（碰撞消解），且消解不改变块的阅读顺序
- **FR-002**: 文字块与图片/条码/艺术字区域相交时，系统 MUST 按"图上说明文字"语义保留（文字层在前），不计为重叠缺陷；表格与图片区域 MUST NOT 相交
- **FR-003**: 系统 MUST 保证凡有上层文本块的区域，覆盖层遮住底座上的原始字迹并覆盖文字的实际渲染范围（含行距还原与溢出阶梯后的实际占位），预览与 Word 一致
- **FR-004**: 系统 MUST 以实测行高推导字号与行距（页高比例常数仅作无实测数据时的兜底）；同一解析产物在预览与 Word 中的字号/页高比例 MUST 一致（钳制基准统一），标题相对层级保留
- **FR-005**: 系统 MUST 按实测数据还原块内行间距与行首水平偏移；Word 中的文字 MUST 保持可编辑段落形态（禁止逐行浮动定位）
- **FR-006**: 区域内文字放不下时，系统 MUST 依序执行：①降字号至下限 ②区域向下扩展吸收空白带；文字 MUST NOT 截断；极端情形（下限+空白带耗尽）MUST 保持文字完整并记录结构化日志
- **FR-007**: 表格列宽 MUST 按实测列边界分配（结构化识别通路）；无列信息的回退通路按均分兜底；预览与 Word MUST 使用同一列宽比例
- **FR-008**: Word 表格默认行高 MUST 受表格区域约束；单元格放不下时先缩字号、仍放不下行高按需增长，且预览 MUST 同构；内容 MUST NOT 截断
- **FR-009**: 同一解析产物在预览与 Word 中的元素区域集合、字号相对比例、行距、溢出行为、表格遮挡关系 MUST 一致（双端同构）
- **FR-010**: 同一解析输入 MUST 产出完全相同的区域布局结果（确定性与可复现性）
- **FR-011**: 布局计算引入的额外耗时 MUST ≤ 100ms/页（主流 iPhone 基线），不阻塞预览首帧
- **FR-012**: 结构化档、可搜索 PDF、全文搜索、既有版面还原能力（底座/覆盖/乱码治理/条码单份/浮动文本框可编辑）MUST 零回归；既有全量测试保持通过

### Key Entities *(include if feature involves data)*

- **区域布局（RegionLayout）**：一页全部元素的最终区域集合及消解记录（原始识别框 → 布局区域）；预览、Word 导出、覆盖层共同消费的唯一布局真源
- **实测版面度量（MeasuredLayoutMetrics）**：页级与块级的实测中位行高、行间距分布；字号与行距的推导依据
- **行几何（LineGeometry）**：块内每行的文本、行高、行间距、行首水平偏移；行级保真的数据载体
- **表格几何（TableGeometry）**：列宽比例与行高分配，随表格块承载；双端渲染与布局消解共用

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 复杂版面整洁率——双栏+表格+插图混排样张，预览与 Word 中 100% 文字块无区域相交、无溢出侵入邻块（夹具断言）；真机实拍复杂版面页面 ≥90% 无肉眼可见重叠/拥挤
- **SC-002**: 双端同构——同一产物预览与 Word 并排对比，元素位置与字号观感一致；Word 文字可点击编辑
- **SC-003**: 密集页保真——密集小字页字号与原版面行高的相对比例偏差 ≤ 20%（现状为放大约 50%~80%）
- **SC-004**: 文字完整性——任意页面文字零截断（放不下走溢出阶梯，不丢字）
- **SC-005**: 零回归——既有全量测试全部通过（212 passed + 1 known issue 基线只增不减），结构化档行为不变
- **SC-006**: 性能——复杂页布局阶段耗时 ≤ 100ms/页，还原预览无可感知卡顿

## Assumptions

- 合并单元格（跨列/跨行还原）本轮不做：列宽按最小列边界分配，合并单元格内容归首格（维持现状）
- 对齐方式不做显式检测：居中/右对齐通过行首水平偏移近似还原
- 逐行绝对定位（每行独立浮动对象）不做，保 Word 编辑体验
- 布局引擎仅服务版面还原档；结构化档块序与内容不变；布局在解析层一次完成，渲染层只消费不重算（切档不重跑解析的既有约束不变）
- iOS 26 结构化识别通路提供列边界信息；几何回退通路（无列信息）走均分兜底
- 字号下限取 6~7pt（与现有 7pt 下限一致或更保守一档，方案阶段定死）
