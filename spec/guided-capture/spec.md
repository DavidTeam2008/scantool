# Spec: 引导取景（guided-capture）

**状态**：待实施（spec 定稿；代码 / 单测 / 真机验收未开始）
**前置**：`spec/frame-truth`（冻结直裁 / 无效框承诺）、`spec/wysiwyg-crop`
（快门一致性门禁）、`spec/scan-enhance`（拍后拆分 / 增强）
**诊断来源**：`docs/15-capture-recovery-assessment.md`（2026-10-21 代码级复核）
**目标设备**：iPhone 13 · iOS 26.7（真机）；模拟器只用于单测与构图验证

## 背景

折页书只拍右页的主场景连续多个周期未达效。复核结论不是「检测还不够准」，
而是管线缺少**“我要拍右页”的意图**：`DetectionStrategy.bestCandidate` 的
包含降权（×0.35）与面积×居中×方正评分天然偏向整书；`CandidateSticky`
“先稳者胜”会把整书稳定下来；`QuadSmoother` 的锁定判据又是逐帧差而非累计
漂移。结果是**稳定地锁错**，拍后 `SpreadSplitter` 再用亮度剖面猜书脊，误判
就静默裁掉内容。

本周期把意图交给用户：**引导框画在屏幕上，用户框住什么，成片就是什么**。
自动检测降级为“一次自动对位”的辅助；自动模式完整保留，作为设置项与回退
路径。WYSIWYG 从“门禁仲裁”变成构造性事实，不再依赖候选池是否恰好选中右页。

2026-10-21 WPS 万能扫描录屏评估（`docs/15` §十一）补充了竞品证据：WPS 使用
**自动跟随页面的单实线框** + 手动快门 + 拍后重裁/滤镜，而不是固定引导框；
其成片可能比预览框更紧，且框会在右页/整页间切换。本周期仍以“引导框=成片”
为主契约，不引入静默拍后重裁；我们的固定引导框是**替代范式**，用一次对位换
确定性，不是 WPS 同款复刻。WPS 式自动裁边/滤镜作为 T040/T041 后续项。

## 用户故事

- **US1**（P1）折页书右页：用户切到引导模式，屏幕上出现常驻框；拖动四角
  框住右页后按快门，成片只含框内内容，左页/折痕/背景不入片。翻页后框保持，
  重新对位 ≤3s 即可再拍。
- **US2**（P1）所见即所得：引导框是屏幕上的可见边界；框外内容不可能进入
  成片；屏幕边缘标记测试中，标记不得出现在成片里。屏幕 ↔ 照片映射可解释、
  可记录、可回放。
- **US3**（P1）可取证：一次失败会话能导出诊断包（原图 + 最近帧 + 全部候选
  四角/分数 + 引导框/画布/裁切 + 时间戳），并用一条命令重放出同样的指标，
  不再靠猜。
- **US4**（P1）拍后可修正：自动模式拍下整书时，Review 只显示**拆分提案**
  （分割线可见、可拖），用户选“整页 / 左页 / 右页”后才应用；0 次静默误裁，
  可撤销。
- **US5**（P1）不回归、可回退：自动模式、证件模式、相册导入、导出、纯离线
  均保持现状；引导模式可随时切回自动；`ServiceProtocols` 既有签名零改动。

## 功能需求

### FR-001 取景模式与意图

- 新增 `CaptureMode`：`.auto`（现有路径） / `.guided`（本周期新路径）。
- 新增 `CaptureIntent`：`.rightPage` / `.leftPage` / `.wholePage`，只决定
  引导框初始位置与默认宽高比，不改变自动模式检测。
- 两者经 `PreferencesStore` 持久化；默认 `captureMode = .auto`、
  `captureIntent = .rightPage`。默认模式翻转只能在 SC-008 的真机 A/B 决策后
  发生，并记录在 `tasks.md`。
- 拍摄页提供“自动 / 引导”切换（文档模式可见；证件模式隐藏），以及右页 /
  左页 / 整页的意图选择（引导模式可见）。
- 证件模式（`ScanMode.idCard`）强制走现有路径，引导 UI 不出现。

### FR-002 引导框 UI 与手势

- 文档模式 + 引导模式下显示 `GuideOverlayView`：四条边 + 四个 44pt 命中区
  的角手柄；实线白色 + 暗描边，不使用自动模式的红/白状态语言，避免“锁定”
  错觉。
- 四角可独立拖动；拖动时保持四边形凸性、最小面积（照片空间 `area ≥ 0.02`，
  任一边在屏幕短边 ≥8%）；无效拖动拒绝并保留上一有效框。
- 提供“重置”和“自动对位”两个按钮；重置回到 `CaptureIntent` 默认框。
- 引导模式隐藏自动四态提示（寻找/靠近/后退/对准），改为固定提示“拖动四角
  框住页面”；快门可用性只由画布就绪与框有效性决定。
- 默认框以**屏幕比例**定义，再映射到照片空间，保证初始框完全落在可见预览
  内：右页 `x 0.50…0.98 / y 0.12…0.92`，左页 `x 0.02…0.50`，整页
  `x 0.04…0.96 / y 0.06…0.94`。
- 框在翻页、连续拍摄之间保持；切换模式、证件模式、会话结束或画布几何
  失效时重置。

### FR-003 引导框是唯一帧来源

- 引导模式下**不逐帧运行** `VisionEdgeDetector` / `CandidateSticky` /
  `QuadSmoother` / 冻结锁定状态机；帧流只用于预览与一次显式自动对位。
- 框的位置只能由三类事件改变：用户拖动、用户点“自动对位”、用户点“重置”。
- 禁止任何“系统觉得更准”而自动移动引导框的行为；快门瞬间不再改框。

### FR-004 屏幕 ↔ 照片画布映射

- 新增 `OverlaySpaceMap` 的逆映射：屏幕点 → 视频归一化 → 照片归一化；
  与现有 `screenQuad(fromPhotoQuad:)` 构成 round-trip。
- 引导框的规范存储是**照片空间** `Quad`；屏幕渲染由现有解析链正向映射，
  拖动时用逆映射写回。屏幕空间只做交互，照片空间才是裁切真值。
- `previewSize` 未测量、`videoAspect/photoAspect` 非法或 round-trip 误差
  > 短边 0.5% 时，引导拍摄禁用（快门置灰 + 提示“取景准备中”），不得用
  恒等映射兜底。
- `previewSize`、`geometry`、`videoFramePlacement`、round-trip 误差、
  解析值 vs `CameraPreviewAttaching.overlayTransform` 探针偏差写入
  `canvasMap` 日志；探针只作对照，不作渲染真值。
- 若真机探针与解析值持续偏差 >0.5%，以实际预览 `videoFormat` 修正解析链；
  不得在引导路径里重新引入“探针失效 → 恒等映射”。

### FR-005 引导拍摄 = 引导框

- 引导模式 `capture()` 直接使用按下快门瞬间的 `guidePhotoQuad` 作为
  `PageDraft.quad`；**不调用** still 重检、不调用 `CropConsistencyGate` 仲裁、
  不跑拆分。
- 不复制 WPS 的“拍后静默重裁”：WPS 成片可能比预览框更紧，而本路径要求
  成片与屏幕框严格同源。WPS 式效果只允许在 Review 以可见提案/Toast + 撤销
  实现（T041，后续），不得在快门后换框。
- 保存完整原图；裁切在渲染/整理阶段按 `draft.quad` 执行，因此成片与屏幕
  框严格同源。
- `PageDraft.userAdjustedQuad = true`（复用现有字段）表示“用户已定框”，
  使 `ReviewViewModel.refineQuads` 跳过自动重检/拆分；不新增持久化字段。
- `cropQuad tag=guide`、`cropGate stillArea=-1 iou=-1 acceptedStill=false`、
  `guidedCapture` 记录意图、框四角、画布误差与耗时。
- 引导模式禁用自动快门；快门只由用户触发。

### FR-006 一次自动对位与松手吸附

- “自动对位”只在用户点击时运行一次 detector（用最近一帧），把候选经
  视频→照片换算、钳制到可见域后作为新引导框；无候选时 no-op 并提示，
  不改变当前框。
- 角拖动松手后允许一次 `EdgeSnapper` 吸附：先把照片框换算到视频空间，
  对最近帧吸附后再换算回照片空间；限幅 ≤ 短边 3%，结果立即上屏；吸附失败/
  产生退化框时保留用户框。
- 自动对位可撤销（一次撤销回到对位前框）；不得连续逐帧吸附。
- 自动对位与吸附都记 `guideAdjust` 日志（before/after、shift、拒绝原因）。

### FR-007 诊断 trace 与回放

- Debug 构建新增 `CaptureTrace` 环形缓冲（默认最近 10s）：
  - 每帧：`timestamp`、phase、directive、previewSize、geometry；
  - 候选：全部 viable + top 8（按面积/分数），硬上限 16；超过时记
    `droppedCount`，不静默丢 viable；每条记四角、面积、score、containment、
    tier、是否 viable；另记总数与最大面积；
  - sticky 输出/ disposition、smoother 输出、冻结框、`imageQuad`；
  - 引导框（照片/屏幕）、canvas round-trip 误差、crop 四角。
- 一键导出诊断包（用户主动分享）：JSON + 原图 + 最近 5s 低分辨率帧 +
  当前截图；纯本地，不联网。
- `CaptureCorpusTests` 重放 12–20 个标注场景，输出四角误差、禁止内容入片率、
  锁定延迟、状态转换次数；一条 `make test-only T=CaptureCorpusTests` 可跑。
- trace 仅 debug 生效；release 不采集、不增加每帧分配。

### FR-008 Review 拆分提案（安全网）

- 拆分路径不再在 `appear()` 里静默改写 `drafts[index].quad`；既有的身份锚定
  静帧精修保留（IoU≥0.85 且面积≤拍摄框×1.10，不扩出拍摄框），只有拆分区
  改为提案。
- 对未标记 `userAdjustedQuad` 的页，计算 `SplitProposal`：
  `u`、来源（leftFold / spine）、prominence/continuity、置信度、
  `quadBefore`、`quadAfter`；找不到时 proposal 为 nil。
- Review UI 显示可见分割线（可拖）与“整页 / 左页 / 右页”选择；只有用户
  选择后才应用；应用后可撤销回 `quadBefore`。proposal 为 nil 时仍提供
  “手动拆分”入口（默认 `u=0.5`），允许拖线后选择。
- 低置信（`confidence < 0.5`，公式见 plan D5）提案用虚线/弱提示，不自动应用；
  仍允许手动拖线。
- 适配场景：自动模式整书、导入的整书、历史页；引导模式页面因
  `userAdjustedQuad=true` 默认不进入提案；切换页/改框/删除后清空 proposal。
- 记 `reviewSplit` 日志（proposal、选择、应用/撤销、耗时）。

### FR-009 非回归与回退

- 自动模式**拍摄路径**（检测/粘滞/平滑/冻结/快门）本周期零改动；
  `CaptureMode.auto` 的取景行为与当前基线一致。Review 拆分确认是跨模式的
  安全修正（见 FR-008），不属于拍摄路径。
- 证件模式、相册导入、导出、OCR/还原、条码路径不变。
- 不修改 `Services/ServiceProtocols.swift` 既有协议签名；需要新诊断能力时
  新增协议/闭包，不动旧签名。
- 纯离线：trace 导出、Review 留样均本地；不新增网络依赖。
- 引导模式失败时可一键切回自动；设置持久化但可重置。

### FR-010 测试治理

- 区分契约测试（WYSIWYG、不可见内容不入片、无效框不自动拍、证件/导入/
  导出）与调参测试（阈值/帧数/分数）。
- 基线 **444 = 443 passed + 1 expected failure + 0 failed**；新增测试只增
  不减。引导路径是增量，预期不需要方向性翻转；若 Review 拆分语义改变，
  逐条记录在 `tasks.md`。
- 必须覆盖：映射 round-trip、引导裁切、无效拖动、自动对位 no-op、引导
  不触发 detector、Review 提案不静默改 quad、拆分应用/撤销。

## 成功标准

- **SC-001** 折页书右页：20/20 引导拍摄（10 右页 + 5 摊开 + 5 平整 A4）
  成片只含引导框内容；右页子集 0 张含左页主体/折痕/框外背景；框四角与
  屏幕框误差 ≤ 短边 0.5%。
- **SC-002** 效率：首次对位 + 拍摄 ≤5s；翻页后重复拍摄 ≤3s；引导模式
  拍摄路径无 detector/sticky/smoother 调用。
- **SC-003** 稳定：引导框在无用户输入时零自动移动；无抖动/漂移；快门前后
  框不变。
- **SC-004** 画布：屏幕左缘标记测试中标记 0 次进入成片；round-trip 误差
  ≤ 短边 0.5%；`canvasMap` 可解释每个轴的偏差。
- **SC-005** 取证：一次失败会话可导出诊断包；`CaptureCorpusTests` 一条命令
  输出四项指标；全部 viable 候选四角落盘。
- **SC-006** 拆分：0 次静默误裁；10/10 可一键修正；8/10 自动提案的 `u`
  误差 ≤2%；应用/撤销后 `draft.quad` 可验证。
- **SC-007** 回归：`make test` 全绿（基线 444 + 新增，0 failed）；自动模式
  既有用例零翻转；证件/导入/导出/条码真机不回归。
- **SC-008** 决策：完成引导 vs 自动各 20 张 A/B，填写
  `device-acceptance.md`；默认模式翻转有明确数据依据并记录。

## 边界与例外

- 首帧 `previewSize == .zero` 或 geometry 未就绪：引导拍摄禁用，不猜映射。
- 视频与照片宽高比不同：引导框映射到照片的可见子集；框外照片内容不得
  因“照片更大”而进入成片。
- 用户把框拖成自交/近退化/过小：拒绝该次拖动，保留上一有效框；UI 给出
  轻提示，不弹窗打断。
- 用户框内仍包含左页/折痕：这是用户意图，成片忠实执行；Review 可再调。
  系统不得在快门后“纠正”。
- 翻页后页面位置变化：框保持，用户重新对位；若框完全离开页面，提示
  “重新对位”，但不自动移动。
- 低光/曲面/反光导致自动对位无候选：no-op，保留手框；不阻塞拍摄。
- 设备仅竖屏（Info.plist 已锁定 Portrait）；若未来支持旋转，画布几何
  变化时重置引导框。
- 引导模式不自动拆分；整书拆分只在 Review 由用户确认。
- WPS 参考：其成片可能比预览框更紧、并裁掉左卷边；本周期引导路径不允许
  这种静默变化。若后续启用 T041，必须满足“只裁框内、由用户按钮按需触发、
  可见提示、可撤销”，且不得改变 SC-001 的“框外 0 内容”。
- 自动模式仍可能在主场景锁错；本周期不修，按 D9 决策后再开自动恢复
  周期。引导模式是当前推荐路径，不是自动模式的替代删除。

- Review 全量改版；本周期只加拆分确认。
- `document` 增强预设（白平衡/去阴影/锐化/对比）作为后续小周期，记录于

## 开放问题

1. 默认框右页比例 0.50…0.98 是否适合大多数折页书？真机 A/B 后可调。
2. “自动对位”是否要长按触发而非单击，避免误触？先按单击 + 可撤销实现，
   真机观察误触率。
3. Review 是否需要对“左页”也提供独立渲染入口，还是仅作为裁切选择？
   本周期先做 `quad` 选择，不新增页面模型。
