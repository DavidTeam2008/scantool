## 3. 归因映射

| 反馈 | 归因 | 机理（对照上轮取证） |
|---|---|---|
| Case A 仍含折起部分 | **R4 修复未达效**（wysiwyg-crop 周期引入 `CropConsistencyGate` 快门门禁后仍未消除） | 折页/摊开书场景检测器偏好整书外轮廓（折页后外轮廓更接近纯矩形）：若呈现框本身锁定的是**含折起的大框**，门禁「呈现框 = 裁切基准」会忠实裁出整书——门禁按契约工作，错在**锁定对象**（上轮假设 H1）；亦不排除门禁侧误纳静帧或路径未命中（上轮假设 H2）。H1/H2 定案需分歧快门的 `cropGate iou=… acceptedStill=…` 日志行 |
| Case B 实线框仍跳 | **R5 修复未达效**（wysiwyg-crop 周期引入 `CandidateSticky` 候选粘滞后仍未止跳） | 摊开书右页 vs 整书双候选面积比 ≈2:1，超 QuadSmoother areaJump 重置阈值；上轮高置信假设：粘滞 v1「池交替」盲区——`CandidateSticky.apply` 仅当**当前候选池中存在**与锚相似（IoU ≥0.60）的候选时才改写，若 VNDetectRectangles 逐帧**交替检出**（存在性交替），无相似帧走 miss 分支 → 呈现仍逐帧交替 = 持续跳动 |
| Case B 手动拍成片左侧大部分是左页图片 | 同 R5 链路（跟踪态呈现帧抢拍语义未兑现） | 快门瞬间呈现框可能正处「整书」帧或无框帧——与上轮假设 1 自洽；`cropGate` 在呈现框为整书时判一致并采纳，成片含左页大半 |
| 总体 WPS 对标未达 | **对标差距仍在**（取景拍照 + 版面还原两部分） | capture 侧 Case A/B 未修复；reconstruct 侧 wps-parity-layout 周期真机验收清单（`spec/wps-parity-layout/device-acceptance.md`）尚「待填」——L1 真机通路疑案（iOS 26.7 结构化通路疑似静默回退）未定案，真机导出质量未系统取证 |
