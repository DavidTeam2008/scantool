# Feature Specification: live-edge-crop（取景实线边框与折页书可靠裁切）

**Created**: 2026-09-20
**Status**: Draft
**Input**: 真机验收反馈（scan-fidelity SC-004 实拍）：四角括号已可见、单页对准正常；但折页厚书难锁定，未对准拍摄时成片退化为全幅不裁切。用户期望：检测取景框里书的边缘 → 边缘处画实线边框 → 成片就是边框内的图。

## Overview

折页厚书的曲面页边缘不满足矩形检测的直线假设，live 严格检测长期 searching、快门重检也失败，成片落回全幅。本轮三项改进：① live 检测增加第三级「放宽矩形」兜底（严格矩形 → 条件文档分割 → 放宽矩形），尽最大可能给出框；② 边框改为连续实线整框（跟随细实线/锁定粗实线），未锁定也显示，裁切边界一目了然；③ 成片保持「快门重检优先 → 回退取景框 → 回退全幅」回退链，全幅时由预览页手动调框兜底。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 折页厚书实时边框可见（Priority: P1）🎯 MVP

扫描折页厚书时，取景器里出现沿书页边缘的实时边框（哪怕没有完全对准锁定），让我预知成片的裁切范围、敢按快门。

**Why this priority**: 本轮核心痛点——看不到框就无法判断裁切范围；检测不到框也直接导致成片不裁（回退链中间层为空）。

**Independent Test**: 模拟器以注入替身帧验证三级兜底触发（严格矩形与文档分割均无候选、放宽矩形有候选 → 框出现）；真机用折页厚书实拍数秒内出框。

**Acceptance Scenarios**:

1. **Given** 折页厚书在取景框内、严格矩形与文档分割均无可信候选, **When** live 检测逐帧运行, **Then** 放宽矩形档条件触发并给出候选，边框显示
2. **Given** 放宽档命中但未达锁定条件, **When** 持续取景, **Then** 边框以跟随态持续显示，提示不误报「已对准」
3. **Given** 平整文档场景, **When** live 检测运行, **Then** 一级严格矩形照旧命中，行为零回退

---

### User Story 2 - 实线整框显示（Priority: P1）🎯 MVP

边框以连续实线绘制：跟随态细实线整框、锁定态粗实线整框，四角括号与框外压暗保留——裁切边界一眼可见。

**Why this priority**: 用户明确要求「实线的边框」；现有虚线（跟随）与无整框（锁定仅角括号）在曲边/杂乱背景场景辨识不足。

**Independent Test**: 注入替身画布断言 tracking/locked 两态的实线整框绘制路径与样式；真机目检边框连续可辨。

**Acceptance Scenarios**:

1. **Given** 跟踪态有框, **When** 渲染, **Then** 细实线整框 + 四角括号 + 框外压暗（0.25）
2. **Given** 锁定态, **When** 渲染, **Then** 粗实线整框 + 四角括号 + 框外压暗（0.45）
3. **Given** 证件模式, **When** 渲染, **Then** idMask 路径完全不变

---

### User Story 3 - 成片按书页边缘裁切（Priority: P1）🎯 MVP

只要取景时看到了边框（任意跟踪态），拍下的成片就按书页边缘裁切——折起来翘起的部分被切掉。

**Why this priority**: 「最后出来的图片就是边框里的图」是用户核心诉求；回退链已有，但中间层（取景框）此前在折页场景为空，本轮三级兜底把它填上。

**Independent Test**: 替身快门链路三分支：重检成功用重检框 / 重检失败回退 live 框 / 双失败全幅。

**Acceptance Scenarios**:

1. **Given** live 有框（跟随或锁定）且快门全分辨率重检成功, **When** 拍摄, **Then** 成片按重检框裁切（精度优先；与所见框 1~3% 细微差异已被用户接受）
2. **Given** live 有框且快门重检失败, **When** 拍摄, **Then** 成片按 live 框裁切
3. **Given** live 与快门重检都无框, **When** 手动拍摄, **Then** 成片保留全幅

---

### User Story 4 - 无框兜底路径不阻塞（Priority: P2）

三级检测后仍完全检测不到边缘的极端场景（极端曲面/光照），手动快门照拍全幅，预览页可拖拽四角手动调框。

**Why this priority**: 兜底保障，防极端场景完全无法拍摄；能力已存在，本轮保护其不回退。

**Independent Test**: 既有 CropCanvas / userAdjustedQuad 行为回归测试全部保持。

**Acceptance Scenarios**:

1. **Given** 无任何框, **When** 手动快门, **Then** 拍下全幅，预览页可进入裁切编辑器
2. **Given** 用户已手动调过某页的框, **When** 自动 refine 触发, **Then** 该页 userAdjustedQuad 语义不变（不被覆盖）

---

### Edge Cases

- 放宽档命中整幅误检（桌面纹理等）→ 既有两级面积兜底（0.96 上限 → ≤1.0）与包含降权照常择优，语义不变
- 放宽档逐帧触发的算力 → 仅「严格+分割双失败」帧条件触发；检测器 actor 忙时丢帧机制不变
- 放宽档命中但 quad 近满幅/贴边 → 可疑锁定门禁照常抑制自动快门并提示后退（安全语义全链路一致）
- 折页书边框长期停在跟随态 → 自动快门不触发（锁定条件不变），提示保持「跟随/寻找」语义不误报

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: live 检测 MUST 增加第三级放宽矩形兜底：严格矩形无可信候选且文档分割无结果时，以与快门 still 路径相同的放宽参数集（置信度下限 0.35、最小尺寸 0.08、直角容差 28°、候选上限 8）再跑一次矩形检测；三级结果 MUST 统一进入既有候选择优（面积下限/两级面积兜底/包含降权语义不变）
- **FR-002**: 放宽档 MUST 仅在「严格矩形无可信候选 且 文档分割无结果」的帧上条件触发，不得逐帧常开
- **FR-003**: 文档模式边框 MUST 以连续实线绘制整框：跟随态细实线（替换现有虚线）、锁定态粗实线（新增）；四角括号与框外压暗 MUST 保留；证件模式渲染路径 MUST 不变
- **FR-004**: 成片裁切 MUST 保持「快门全分辨率重检测优先 → 回退取景框 → 回退全幅」回退链语义
- **FR-005**: 无任何框时手动快门 MUST 照拍全幅；预览页四角拖拽调框能力与 userAdjustedQuad 语义 MUST 不回退
- **FR-006**: 放宽档命中的框 MUST 与既有框同链路参与可疑锁定门禁（近满幅抑制自动快门）；自动快门 MUST 仍仅在锁定态触发
- **FR-007**: 放宽档触发与命中 MUST 经既有检测日志通道记录并区分来源档位，供真机验收核对触发率与命中质量

### Key Entities

- 无新增实体。复用 `Quad`（照片空间检测框）、`QuadTrackState`（searching/tracking/locked）、`CaptureGeometry`、`PageDraft`（含裁切 quad 与 userAdjustedQuad 标记）；放宽矩形参数集与快门 still 路径同源（单一参数源）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 折页厚书场景（真机验收清单定义），取景器数秒内出现实线边框，边框贴合书页可读区域边缘
- **SC-002**: 平整文档场景行为零回退：锁定/自动快门/四态提示/震动与上一版一致；自动化测试基线（280）只增不减
- **SC-003**: 所见即可裁：看到边框（任意跟踪态）时拍摄，成片为按书页边缘裁切的结果，折起翘起部分被切除
- **SC-004**: 极端无框场景不阻塞：手动快门可拍全幅，预览页四角调框可用
- **SC-005**: 三级兜底可观测可验证：真机日志可见放宽档触发记录；模拟器替身测试覆盖三级触发条件组合与回退链三分支

## Assumptions

- 实线样式：跟随态约 2.5pt 细实线、锁定态约 3pt 白色实线+暗描边（与角括号同风格）；具体线宽可在实施中微调
- 放宽档参数直接复用 still 路径 relaxed 参数，不另造参数集
- 证件模式（idCard）完全不在本轮范围
- 引导提示文案与四态语义本轮不变
- 曲边页「精确贴合」受矩形检测器物理上限约束：放宽档提高命中率但不保证曲边 100% 贴合，极端场景由 US4 手动调框兜底

## Open Questions

- 无——四项关键决策（三级检测兜底 / 快门重检优先 / 拍全幅+预览调框 / 目录名 live-edge-crop）已在澄清阶段确认。
