# Feature Specification: scan-fidelity（扫描保真：还原缺陷修复 + 取景边框可靠性）

**Created**: 2026-09-20  
**Status**: Draft  
**Input**: layout-engine 真机验收不通过的取证结论（SC-001 预览 / SC-002 Word 导出，根因 R1~R7，详见 `spec/layout-engine/device-acceptance.md`）+ 用户实拍反馈（取景器边框不可见、引导提示不随方向变化）。

## Overview

上一轮 layout-engine 交付后真机验收发现：布局引擎几何层健康（文本框零重叠、行距 exact、消解正常），但**上游行聚类与字号/行距推导存在缺陷**，导致 Word 导出与预览出现行叠字、孤儿碎片块、乱序拼接与"缺词"体感；同时拍摄环节的实时边框在真机取景器中始终不可见（检测与锁定实际正常工作），引导提示不随拍摄距离/位置变化。本特性一轮修复两侧：**还原保真**（行几何同源、分段行合并、下划线占位、聚类稳定、搜索数据回填）与**拍摄保真**（边框可见且对齐、方向感知提示）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 行几何保真：预览与 Word 不再叠字 (Priority: P1)

用户扫描包含大标题、多级字号混排的页面后打开预览和导出的 Word 文档，每一行文字的字号与行距互相匹配——不再出现上一轮"标题字号 19.5pt 挤在 13.1pt 行槽里"导致的行行叠字。预览看到的行距与 Word 打开的行距一致，因为两端共用同一套行几何推导。

**Why this priority**: 行叠字是本轮验收最重的缺陷（R5，块级字号与行级行距推导源不一致），直接导致"布局乱"的第一观感；修复它是还原可用性的前提。

**Independent Test**: 用取证同款双栏英语练习册页扫描→重建→导出，打开 Word 检查标题块、正文块、混排块的行间隙——无叠字即可独立验收。

**Acceptance Scenarios**:

1. **Given** 含大标题与正文混排的页面，**When** 重建并导出 DOCX，**Then** Word 中任意行的文字下缘不与下一行文字上缘重叠（字号不超过该行行槽高）
2. **Given** 同一页面，**When** 在 app 内打开还原预览，**Then** 预览行距与 Word 行距视觉一致（同源推导）

---

### User Story 2 - 对话/填空行完整还原：分段合并、顺序正确、空隙有下划线 (Priority: P1)

用户扫描英语练习册（对话填空题：一条视觉行被印刷空隙拆成多段）后，导出的文本按视觉行完整还原：同一行的各分段合并为一行、按视觉位置排序、分段间的填空空隙渲染为下划线占位。不再出现"the maths problems?"漂在栏中间的孤儿碎片块，不再出现"physics exercises for homework. three hours doing those"这类跨行乱序拼接，"Yesterday I ______ physics"的空隙清晰可见且可在 Word 中直接填入答案。

**Why this priority**: 碎片块与乱序（R1/R2）是"布局乱"的第二主因；填空空隙（R3）是"缺词"体感的主要来源——用户已确认要下划线占位。

**Independent Test**: 扫描同款练习册页，检查对话段落：每个视觉行只有一条文本、语序正确、空隙处有下划线——可独立验收。

**Acceptance Scenarios**:

1. **Given** 一条视觉行被 OCR 拆成多个分段（段间为空白下划线），**When** 重建导出，**Then** 这些分段聚合为同一行且按视觉横向位置排序，不产生独立碎片块
2. **Given** 相邻分段间空隙超过阈值，**When** 预览/导出，**Then** 空隙以下划线占位呈现，宽度与视觉空隙成比例；低于阈值按普通空格处理
3. **Given** 不同视觉行的分段，**When** 重建导出，**Then** 不会被串接到同一行（乱序消除）

---

### User Story 3 - 聚类稳定：多次扫描结构均合格 (Priority: P2)

用户对同一页连续扫描三次，三次导出的块结构都满足"无孤儿碎片块、无行叠字、无乱序"。不要求三次导出字节级一致（OCR 本身逐次有噪声差异），但结构性缺陷不得复现——上一轮同页三扫出现 6/5/11 块的剧烈波动且两次带缺陷，本轮必须收敛到"三次都合格"。

**Why this priority**: 稳定性（R6）决定修复是否可靠——单次通过但复扫翻车等于没修好；排在 P1 之后因为先要有正确的聚类规则才能谈稳定。

**Independent Test**: 同页扫描 3 次，逐次导出检查结构三项（碎片/叠字/乱序），三次全过即验收。

**Acceptance Scenarios**:

1. **Given** 同一页面连续扫描 3 次，**When** 逐次重建导出，**Then** 每次导出均满足 US1/US2 的结构要求（允许 OCR 字符噪声差异）

---

### User Story 4 - 全文搜索可用：重建后内容可搜、标题自动更新 (Priority: P2)

用户完成扫描与重建后，在文档列表搜索页面内容关键词（如 "Yesterday"）能命中该文档；标题从"扫描 · N"自动更新为首行摘要。上一轮发现 `ocrSearchBlob` 从未被重建流程回填（只有手动 OCR 页路径回填），导致全文搜索对重建过的文档永远失效。

**Why this priority**: 这是取证中顺带发现的独立数据缺陷（R7），修复成本低、用户价值直接（搜索是文档管理的核心路径），但不阻塞核心还原体验。

**Independent Test**: 扫描任一页面→重建完成→退出到文档列表搜索内容关键词——命中且标题已更新即验收。

**Acceptance Scenarios**:

1. **Given** 文档完成重建（识别文本已生成），**When** 用户在文档列表搜索该文档内容关键词，**Then** 该文档出现在搜索结果中
2. **Given** 文档标题仍为默认"扫描 · N"，**When** 识别文本回填，**Then** 标题自动更新为首行摘要（沿用现有自动标题规则）

---

### User Story 5 - 取景器实时边框可见且对齐 (Priority: P1)

用户在拍摄模式下对准书本/纸张，取景器实时显示检测到的边框：检测中为虚线角标、锁定后为实线（或等效视觉区分），边框四角有粗括号强化、框外区域压暗，边框位置与预览画面中书页的真实边缘对齐。上一轮真机取证表明检测与锁定实际工作正常（提示语与震动会触发）但边框始终不可见——映射链路（照片空间→屏幕）与视觉对比度是双嫌疑，两者都要修。

**Why this priority**: 边框可见是拍摄对准体验的核心（用户本轮明确提出）；检测已经在工作意味着修复是"让已有的东西被看见"，价值立现。

**Independent Test**: 真机对准一本书：取景器出现角标边框、移动手机时边框跟随书页、边框与书页边缘肉眼对齐——可独立验收。

**Acceptance Scenarios**:

1. **Given** 拍摄模式且检测到书页，**When** 用户查看取景器，**Then** 边框角标实时可见（任何常见明暗背景下可辨识），框外区域压暗
2. **Given** 检测中与锁定两种状态，**When** 状态切换，**Then** 边框有明确视觉区分（虚线/实线或等效）
3. **Given** 边框显示在屏幕上，**When** 与预览画面中书页实际边缘对比，**Then** 两者对齐（探针映射与回退映射路径均须对齐）
4. **Given** 证件模式，**When** 取景，**Then** 现有固定取景窗行为不变（回归保护）

---

### User Story 6 - 方向感知引导提示 (Priority: P3)

用户拍摄时引导提示随实际状态动态变化且方向正确：书页贴边/近满幅（疑似被裁切）→提示往后移；检测框过小（太远）→提示靠近一点；目标偏出取景→提示移回取景框；对准锁定→"已对准，轻点快门"。不再出现"不管该往前还是往后都只提示往后移"的死文案。临界距离有滞回去抖，提示不闪烁。

**Why this priority**: 提示升级改善拍摄效率，但依赖 US5 的边框先可见（用户先看得见框，提示才是第二引导层）；作为体验增强排 P3。

**Independent Test**: 真机分别制造太近/太远/偏移/对准四种情形，核对四种提示文案各不相同且方向正确。

**Acceptance Scenarios**:

1. **Given** 书页贴近视场边缘（疑似裁切锁定），**When** 用户查看提示，**Then** 提示后退
2. **Given** 书页太远导致检测框过小，**When** 用户查看提示，**Then** 提示靠近
3. **Given** 在太远与合适距离临界值附近小幅移动，**When** 连续取景，**Then** 提示文案不频繁闪烁（滞回去抖）
4. **Given** 对准锁定，**When** 用户查看提示，**Then** 提示轻点快门

---

### Edge Cases

- 分段间空隙极窄（字符间距级别，低于阈值）→ 按普通空格处理，不渲染下划线
- 重建流程中途失败（识别未完成）→ 搜索数据不回填（避免半截文本污染搜索）；已有旧值不覆盖为空
- 检测框瞬时抖动（单帧误检）→ 边框显示沿用现有平滑器去抖，不闪现闪灭
- 表格/结构化档页面 → 现有表格导出模板不变；单元格内文本的分段空隙与普通文本行同规则处理
- 暗光/强反光背景 → 边框角标与压暗层保持可辨识（角标用高对比描边）
- 同一文档既有旧空 blob 又完成新一轮重建 → 回填新值并触发标题规则一次，不重复改写用户已手动改过的标题

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 行级字号与行距必须同源推导——任意行的渲染字号不得超过该行行槽高；预览渲染与 DOCX 导出共用同一行几何推导源，两端行距视觉一致
- **FR-002**: 同一视觉行的多个 OCR 分段必须聚合为同一文本行（按垂直重叠/基线邻近判定），不得拆散为独立文本块
- **FR-003**: 行内分段必须按视觉横向位置顺序拼接且段间空隙保留；不同视觉行的分段不得串接到同一行
- **FR-004**: 分段间空隙超过阈值时，预览与导出均以下划线占位呈现（Word 中可编辑），占位宽度与视觉空隙宽度成比例；低于阈值按空格处理
- **FR-005**: 同一页多次扫描的每次导出结构均须满足：无孤儿碎片块、无行叠字、无乱序（不要求字节级一致）
- **FR-006**: 文档完成识别/重建后，识别全文必须回填至全文搜索数据；默认标题"扫描 · N"按现有首行摘要规则自动更新（重建流程与手动 OCR 流程行为一致）
- **FR-007**: 拍摄取景器中检测到目标时必须实时显示边框：四角括号强化 + 框外压暗；检测中与锁定态有明确视觉区分
- **FR-008**: 边框屏幕位置必须与预览画面中目标真实边缘对齐——探针映射（预览层实测）与回退映射（宽高比推算）两条路径均须对齐
- **FR-009**: 引导提示必须方向感知且动态更新：疑似裁切→提示后退；检测框过小→提示靠近；目标偏出→提示移回取景框；锁定→提示轻点快门；检测中→提示寻找边框
- **FR-010**: 提示状态判定必须有滞回去抖（临界值附近不闪烁），状态切换后文案即时更新
- **FR-011**: 证件模式的现有取景窗、提示与拍摄行为保持不变（回归约束）
- **FR-012**: OCR 字符级混淆（I/l/1、o/u 等）维持现状不做自动改写（已知限制，须记录于用户可见的项目文档）

### Key Entities *(include if feature involves data)*

- **视觉行（Text Line）**: 由一个或多个 OCR 分段聚合而成；携带行槽高（行距推导源）与行级字号（同源），分段序列含段间空隙宽度
- **空隙占位（Gap Placeholder）**: 视觉行内分段间的空隙表示；超过阈值映射为下划线占位（宽度成比例），否则为空格
- **搜索数据（ocrSearchBlob）**: 文档级识别全文聚合，供全文搜索与首行摘要标题规则消费；由识别/重建完成事件触发回填
- **引导状态（Guidance State）**: 拍摄取景的提示判定状态机（疑似裁切/过远/偏移/锁定/寻找），由检测框几何（面积占比、边距）驱动，带滞回

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 取证同款双栏英语练习册页扫描→重建→导出，Word 打开检查：0 处行叠字、0 个孤儿碎片块、0 处乱序拼接；填空空隙以下划线呈现；预览与导出行距视觉一致（用户肉眼验收通过）
- **SC-002**: 同一页连续扫描 3 次，3 次导出全部满足 SC-001 的三项结构要求
- **SC-003**: 重建完成的文档，在文档列表搜索其内容关键词可命中；标题自动更新为首行摘要（非"扫描 · N"）
- **SC-004**: 真机对准书本取景：边框角标可见、移动时跟随书页、与书页边缘肉眼对齐；暗光与亮背景两种环境均可辨识
- **SC-005**: 真机制造太近/太远/偏移/对准四种情形，四种提示文案各不相同且方向正确；临界距离附近提示不闪烁
- **SC-006**: 既有测试基线（255 passed + 1 known issue + 0 failed）不回退；FR-001~FR-011 均有对应自动化测试覆盖

## Assumptions

- 验收基准页为用户已有的双栏英语练习册页（本轮取证同款样张）
- 下划线占位在 Word 中以可编辑的下划线空格实现（用户可直接在空上填入答案），不锁定、不用图片
- "检测框过小（太远）"的判定基于检测框面积占取景区比例的阈值，具体数值在设计阶段确定并写入滞回区间
- 布局引擎既有能力（溢出阶梯、split 重定基、消解、结构化档表格模板）保持不变，本轮只改聚类与推导规则
- SC-003 密集试卷页 / SC-004 简单页的加测（上一轮未测项）视用户方便选做，不阻塞本轮交付判定
- 方向感知提示新增文案沿用现有本地化 key 体系；五项澄清决策（下划线占位、I/l/1 接受为已知限制、四角括号+外压暗样式、方向感知提示本轮做、目录名 scan-fidelity）均已确认

## Open Questions

- 无——全部决策已在需求澄清阶段确认；唯一开放项为 SC-003/SC-004 页型加测与否，属验收选做项，不阻塞设计与实施
