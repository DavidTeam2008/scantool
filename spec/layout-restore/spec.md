# Feature Specification: 版面还原（Layout Restore）

**Created**: 2026-09-18
**Status**: Draft
**Input**: 用户报告还原版面不符合预期：带图片的页面布局乱掉、一个二维码变 2 个、图片全部竖排、艺术字体/画出来的字被识别成乱码文本。用户参考方法：带底图的页面用底图做还原底座；无法准确识别为纯文本的区域截图作为图片放回对应区域；排版按拍摄原图；导出的 Word 也要还原版面。五项澄清已确认：整页原图统一底座 / 新档位默认选中（保留结构化档）/ DOCX 浮动文本框 / 本轮不动 PDF / 目录 spec/layout-restore。

## Overview

新增「版面还原」档位（默认选中）：以矫正后的整页原图为统一底座，文字/表格区域净化覆盖后按原始坐标重排干净文本，图画/艺术字/手绘字/条码等无法准确识别为纯文本的区域保留原像素——预览与导出的 Word 文档都与拍摄的原始版面同构。同时根治三类既有缺陷：条码/二维码多通道重复表示、图片竖排堆叠、艺术字乱码混入正文。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 版面还原档：整页底座 + 按原图绝对定位 (Priority: P1)

用户拍摄一个图文混排页面（宣传单/试卷/教材页，含照片、二维码、艺术字、双栏文字），进入还原页。默认「版面还原」档的预览：整页以原图为底座，文字与表格出现在原始位置（原字迹被净化覆盖、替换为识别出的干净文本），图片/艺术字/二维码区域保留原图像素。整体观感与拍摄的原始版面一致，而不是所有图片竖着排在文字流里。

**Why this priority**: 「按原图版面还原」是本轮的核心诉求，其余故事（去重/乱码治理/Word 同构）都依附于这个档位成立。

**Independent Test**: 用带图片的夹具页还原，检查预览中各元素坐标与原图 bbox 对应（图片不再竖排、双栏位置保真）；切回结构化档行为与现状一致。

**Acceptance Scenarios**:

1. **Given** 一个含图片+文字的页面，**When** 版面还原完成，**Then** 预览呈现整页底座，图片元素位于其原始位置（与原图 bbox 对应），不出现竖排堆叠
2. **Given** 文本/表格区域，**When** 版面还原渲染，**Then** 原字迹被覆盖，该区域显示识别出的干净文本，无重影
3. **Given** 双栏/混排布局，**When** 版面还原，**Then** 元素相对位置与原图一致（绝对定位天然保真，不依赖分栏算法）
4. **Given** 用户切换到「结构化」档，**When** 查看，**Then** 现有结构化行为完全不变（回归保护）

---

### User Story 2 - 无法识别区域按图保留（乱码消灭） (Priority: P2)

艺术字体、手绘字、图画、图章等无法准确识别为纯文本的区域：不再以乱码文本混入还原结果，而是整块区域保留原像素（底座上不覆盖、文字层剔除该区域的乱码文本行），导出时以图片形式出现在对应位置。

**Why this priority**: 乱码文本直接破坏成片可用性（用户原话「识别成了乱码」）；且现有图片检测机制因「被文字盒覆盖即排除」恰好把这些区域排除在图片通道外，是双重缺陷。

**Independent Test**: 用含艺术字/图章的夹具页还原，断言：该区域保留原像素、乱码文本行不出现在文字层；正常文本行零误杀。

**Acceptance Scenarios**:

1. **Given** 艺术字区域被 OCR 识别为乱码文本行，**When** 版面还原，**Then** 该区域显示原图像素，乱码文本不出现在还原结果与导出文档中
2. **Given** 正常文本行，**When** 非文本区域判定，**Then** 不被误判为图片（判定保守，宁可个别乱码残留也不误删正常文本）
3. **Given** 一个区域整体是图画但边缘混有少量正常说明文字，**When** 判定，**Then** 判定粒度不把邻近正常文本一并吞掉

---

### User Story 3 - 二维码/条码单份表示 (Priority: P3)

同一个二维码/条码在还原结果与导出文档中只出现一次。现有三通道（图片通道、条码通道、URL 文本降级通道）对同一码各产出一份表示的缺陷必须根治。

**Why this priority**: 「一个二维码变 2 个」是用户直接点名的缺陷；根因是图片检测把条码 bbox 当图片输出 + 条码通道再裁一份 + URL 文本降级第三份，通道间无交叉去重。

**Independent Test**: 夹具页含 1 个二维码 + 下方 URL 文字，断言还原结果中该码的表示恰好 1 份（且导出文档同样 1 份）。

**Acceptance Scenarios**:

1. **Given** 页面含 1 个二维码，**When** 版面还原，**Then** 预览与导出中该码恰好出现 1 次
2. **Given** 二维码下方印有 URL 文本，**When** 还原，**Then** 不产生额外的重复文本表示（URL 并入该码的说明或按去重规则处理，不重复出现）
3. **Given** 版面还原档中的条码区域，**Then** 保留原像素（底座）或单份裁图，不与条码说明重复渲染

---

### User Story 4 - DOCX 版面还原导出（与预览同构） (Priority: P4)

导出的 Word 文档与版面还原预览同构：整页底图衬底、文字以浮动文本框按原坐标摆放（可编辑）、图片元素浮动定位、表格位于原始位置。多页文档逐页对应；导出不受临时文件清理影响而缺图。

**Why this priority**: 用户明确要求「导出的 word 文档也要还原版面」。现有导出是段落流 + 衬底源错误（用最大 figure 裁图充当底图），必须与预览统一。

**Independent Test**: 版面还原档导出 DOCX，在 Word 中打开断言：底图/文字框/图片位置与预览一致，文字可点击编辑；多页文档每页元素归属正确。

**Acceptance Scenarios**:

1. **Given** 版面还原档，**When** 导出 DOCX，**Then** Word 打开后版面与预览一致（底图、文字位置、图片位置）
2. **Given** 文字块，**When** 在 Word 中点击，**Then** 文字可编辑（浮动文本框，非图片化）
3. **Given** 多页文档，**When** 导出，**Then** 每页底图与该页元素对应，无跨页错位
4. **Given** 还原完成后系统清理过临时目录，**When** 用户导出，**Then** 导出文档不缺图（图片资源生命周期与文档可用性绑定）

---

### User Story 5 - 表格原位保真呈现 (Priority: P5)

表格在版面还原档中按原始位置呈现：区域净化覆盖后，行列内容按原位渲染；导出的 Word 中表格位于原始位置且内容与结构化档一致。

**Why this priority**: 表格是已识别的正确内容（用户确认「文字和表格内容识别出来了」），版面还原不能丢失这块能力；但绝对定位下的表格呈现（尤其 Word 浮动表格）复杂度独立成故事。

**Independent Test**: 用表格夹具页（营养成分表）在版面还原档断言：表格位于原 bbox、行列内容与结构化档一致；导出 Word 中表格位置与内容正确。

**Acceptance Scenarios**:

1. **Given** 含表格的页面，**When** 版面还原，**Then** 表格位于原始位置，行列内容与结构化档一致
2. **Given** 版面还原档导出，**Then** Word 中表格位于原始位置，内容完整可读

---

### Edge Cases

- 纯文字页（无任何图片）→ 底座退化为「白底 + 原位文本」，效果等同或优于现状，不产生多余图片块
- 检测全部失败的页面 → 底座整页保留原图、无覆盖无重排，不崩溃、不输出空文档
- 近拍大图（单图占满页面）→ 不把整页当图片块重复叠放（底座已是原图）
- 多页文档 → 每页独立底座与元素集，页间不串
- 艺术字与正常文本紧邻 → 保守判定：宁可保留个别乱码，不误删正常文本（误杀率趋零优先于乱码清除率）
- 结构化档/可搜索 PDF 导出 → 行为与现状完全一致（本轮零回归）
- 条码检测在模拟器恒为空 → 相关断言在真机验收（既有约定维持）
- 文本覆盖填充色 → 与周边背景色自适应（白纸页纯白、带底色页取局部背景色），避免「白补丁」突兀

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 版面还原档 MUST 以矫正后的整页原图为统一底座，所有元素按原始坐标绝对定位呈现（预览与导出同构）
- **FR-002**: 文本/表格区域 MUST 净化覆盖（填充色与局部背景自适应）后重排识别文本；文字层 MUST NOT 残留原字迹重影
- **FR-003**: 无法准确识别为纯文本的区域（图画/艺术字/手绘字/图章等）MUST 保留原像素；其乱码文本 MUST NOT 出现在还原结果与导出文档中
- **FR-004**: 非文本区域判定 MUST 保守：正常文本行的误杀率趋零；判定机制的具体实现由方案阶段决定
- **FR-005**: 同一条码/二维码在还原结果与导出中 MUST 恰好一份表示（图片/条码/URL 文本三通道交叉去重）
- **FR-006**: 版面还原档 MUST 为默认档位；结构化档 MUST 保留、可切换、行为与现状完全一致
- **FR-007**: DOCX 导出（版面还原档）MUST 与预览同构：整页底图衬底 + 浮动文本框定位文字（文字可编辑）+ 浮动图片
- **FR-008**: 表格 MUST 按原始位置呈现（预览与 DOCX），行列内容与结构化档一致
- **FR-009**: 多页文档 MUST 逐页对应底座与元素集，导出分页正确
- **FR-010**: 图片资源生命周期 MUST 与导出可用性绑定：还原完成后的任意时刻导出，MUST NOT 因临时目录被系统清理而缺图
- **FR-011**: 还原过程 MUST NOT 阻塞 UI（页面级异步，进行中可交互）；单页还原耗时用户可接受
- **FR-012**: 结构化档的预览与 DOCX/PDF 导出 MUST 零回归；可搜索 PDF 导出本轮 MUST 保持现状
- **FR-013**: 现有测试基线 MUST 保持通过；本轮 MUST 新增覆盖以下场景的回归测试：条码去重、非文本区域判定（保守性）、绝对定位渲染（预览画布与 DOCX 结构断言）、底座覆盖、多页对应、图片资源生命周期
- **FR-014**: 全文搜索既有行为 MUST 不受影响（搜索索引在采集侧生成，与还原档位无关）

### Key Entities *(include if feature involves data)*

- **版面还原档（新档位）**: 输出形态枚举的新成员；默认选中；与结构化档并存
- **底座（base image）**: 矫正+增强后的整页 rendered 图，版面还原的唯一视觉基座（预览与 DOCX 衬底同源）
- **覆盖区域（mask）**: 文本/表格区域的净化覆盖矩形集合 + 自适应填充色；覆盖之外的底座像素原样保留
- **非文本区域**: 保留原像素的区域集合（图片 + 乱码区域 + 条码），与覆盖区域互斥且并集覆盖全部已检出内容
- **元素绝对定位模型**: 块级 bbox → 页面坐标的定位关系（预览画布与 DOCX 浮动元素共用同一坐标源）
- **条码去重规则**: 同一码的图片表示/条码表示/URL 文本表示三通道合并为单份的判定规则
- **既有实体不变**: ReconstructBlock/ReconstructPage/ReconstructDocument 语义向后兼容（新增字段不破坏既有解析）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 真机拍摄含「二维码 + 图片 + 艺术字」的页面：版面还原预览中二维码恰好 1 个、图片位于原图位置、无乱码文本块
- **SC-002**: 同页导出 DOCX 在 Word 中打开：版面与预览一致，文字可点击编辑，表格位于原位
- **SC-003**: 双栏教材夹具页：版面还原档元素位置与夹具真值偏差在目视容差内（无竖排堆叠、无跨栏错位）
- **SC-004**: 修复后全量测试通过（现有基线 + 新增回归用例，0 failed；既有 1 条 known issue 维持原状）
- **SC-005**: 纯文本页在版面还原档的效果不劣于现状结构化档（真机目视对比，无多余图片块、无版面劣化）
- **SC-006**: 还原过程不阻塞 UI：进行中可滚动预览、可切换档位；单页还原耗时不超过现状的可感知劣化（无硬性毫秒指标，以用户可接受为准）

## Assumptions

- 底座使用「矫正 + 增强后的 rendered 图」，与现有预览衬底同源；采集侧 quad/增强管线本轮不动
- 艺术字/图画区域成为图片后，其中文字不再可搜索/可编辑（用户已确认此取舍，乱码治理优先）
- 全文搜索索引（采集侧生成）不受还原档位影响，本轮零改动
- 表格来源维持现状：iOS 26 结构化通路优先、几何兜底维持既有降级阶梯；本轮不改进表格检测本身，只做「原位呈现」
- 可搜索 PDF 导出与结构化档 DOCX 本轮保持现状（用户已确认）；版面还原档的 PDF 支持留待后续
- 不引入云/第三方依赖（TextIn 云解析 stub 维持现状）
- 还原结果的持久化架构（全内存、重进重算）本轮不重构；仅修复图片资源的生命周期问题（FR-010）
- 五项澄清决策已锁定：整页原图统一底座 / 新档位默认选中 / DOCX 浮动文本框 / 本轮不动 PDF / spec 目录 layout-restore
