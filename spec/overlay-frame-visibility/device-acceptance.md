## B. 本周期新增验收点

### OFV-001 整框两态可见（US1 / FR-001~004，替代「从未出现实线框」失败基线）

**步骤**：文档模式对任一平整文档取景，观察**跟随态**数秒；等其锁定观察**锁定态**；
再切**证件模式**对身份证取景。

**通过标准**：
- 跟随态：屏幕内出现**朱砂色（约 45% 透明度）约 2.5pt 连续实线整框** + 四角 L 形
  白色粗括号，整框贴合纸边（此前失败基线：整框从未出现，仅四角括号可见）；
- 锁定态：整框变为**白色约 3pt 面线 + 暗色约 5pt 描边的粗双线**（角括号同风格）；
- 证件模式：检测框描边回到屏幕内、贴合证件窗口区域（回归修复）。

**失败时看**：整框仍不可见/位置离谱 → 坐标契约回归（对照
`EdgeOverlayRenderingTests` 是否仍绿 + `overlayProbeAnalytic` 日志的解析式参数）；
整框可见但压暗异常 → 转 OFV-004。

### OFV-002 确认窗节奏与中止（US2 / FR-005~007）

**步骤**：设置确认「自动快门」开启；平整文档取景至锁定，**观察锁定视觉（白双线 +
压暗加深 + 震动）出现到自动快门之间的间隔**；随后在确认窗内（锁定后、快门前）
**移开手机**取消，重复 **×3**；再任其锁定计满观察自动拍摄；最后在另一锁定周期
用**手动快门**验证即时可拍。

**通过标准**：
- 自动拍摄前锁定视觉可感知时长 **≥ 0.4s**（肉眼能分辨「先锁定、后快门」的节奏，
  不再锁定即拍）；
- 确认窗内移开取消成功率 **100%（≥ 3 次验证）**——移开后不产生新页（快门声/白闪
  均不应出现）；
- 重新对准重新锁定后**重新计时**，计满正常自动拍；同一锁定周期最多自动拍一次；
- 确认窗内手动快门**立即拍摄**（不受窗口限制）。

**失败时看**：锁定即拍（无停顿）→ `lockedFrameCount` 确认窗未生效（对照
`AutoCaptureHoldWindowTests` 是否绿）；移开仍拍 → searching/tracking 清零路径失效；
确认窗时长异常（过长/过短）→ 检测帧率波动属预期（窗口按帧计数 ≈ 0.4s@15fps），
但 > 1s 需记录现场。

### OFV-003 折页错误锁定可见可中止（US3 缓解验证 / R3 物理上限）

**步骤**：折页厚书取景（复用 SC-001 场景）；若检测器锁定**整书外轮廓/含折起部分的
大框**（已知物理上限，非缺陷），在确认窗内观察整框实际框住的范围，然后**移开取消**；
另做一次放任其自动拍，进预览页用四角调框修正。

**通过标准**：
- 错误锁定时**整框实际范围清晰可见**（用户能看到框住的是含折起部分的大框，而非
  成片后才发现）；
- 确认窗内**移开即取消**，不产生含折起部分的成片；
- 放任拍摄的成片可由**预览四角调框**修正（既有兜底路径，本周期不新增检测能力）；
- 近满幅/贴边锁定期间出现 `suspiciousLock` 日志与「再后退一点」提示（门禁与
  确认窗协同：提示后退、抑制自动拍）。

**失败时看**：大框不可见 → 转 OFV-001；可见但来不及取消 → 转 OFV-002 节奏核对
（确认窗时长是否异常）；无 suspiciousLock 提示 → 核对 `isSuspiciousForAutoCapture`
门禁（对照 `CaptureFallbackTests/suspicious*` 是否绿）。

### OFV-004 压暗挖孔（US1 / FR-002~003）

**步骤**：文档模式跟随态与锁定态分别观察**框内画面亮度**与**框外压暗**，对比
取景器中框内外明暗层次。

**通过标准**：
- **框内画面不变暗**（挖孔跟随整框，不再是全屏均匀变暗）；
- 框外压暗两档层次可辨：跟随态约 **0.25**、锁定态加深至约 **0.45**（数值不变，
  仅位置回归正确）；
- 压暗边界与整框重合（转动/移动手机时挖孔跟随 quad 变化）。

**失败时看**：框内也变暗 → reverseMask 挖孔未跟随 quad（坐标契约回归，对照
`EdgeOverlayRenderingTests`）；两档层次无差异 → `DocumentFrameStyle` 两态样式
（对照 `DocumentFrameStyleTests`）。

## 验收结果记录（2026-09-21）

**结论：OFV-001/002/004、SC-002/003/004 通过——QuadShape 坐标修复与确认窗生效。
SC-001 失败 2 例，暴露新根因（超出 R3 已知限制范围）。**

### 失败案例

- **Case A（折页拍右页）**：书翻到中间、左边折起，实线整框出现且**锁定在右边书页
  内容上**（屏幕所见正确），但成片**含左侧折起部分**——裁切框 ≠ 显示框。
- **Case B（摊开书拍右页）**：左边平铺、从中线取景只拍右页，实线整框**持续跳动**
  （双候选振荡，始终未锁定），手动拍一张，成片**倾斜且含左页部分**。

### 根因（代码取证）

- **R4（主因，「所见非所得」）**：`CaptureViewModel.capture()` :153-157 回退链
  `detected ?? imageQuad ?? .fullImage`——快门时刻对高清静帧**重新检测**且结果
  **无条件优先**于屏幕上显示的锁定框。静帧路径（`VisionEdgeDetector.detect(imageData:)`，
  `stillImage: true`）在折页/摊开书场景选出**整书外轮廓**这一强矩形候选，再经
  still 专属贴边吸附（`EdgeSnapper`），直接覆盖 live 锁定的右页框。该链路引入于
  scan-edge-accuracy 时代（静帧高分辨率精修本为提升平整文档裁切精度），多候选
  歧义场景下与 WYSIWYG 冲突。
- **R5（次因，双候选振荡）**：摊开书从中线取景时，右页矩形与整书外轮廓两候选
  逐帧交替取胜（面积比 ≈2:1，超 `QuadSmoother` areaJump 0.35 重置阈值）→ 轨道
  反复重置、实线跳动、永不锁定（Case B「实线一直在跳」）。锁定失败转手动拍后，
  静帧检测又选整书 → 倾斜成片含左页。

### 与 R3 的关系

R3（折页曲边非矩形，检测器物理上限）的缓解前提是「错误锁定看得见、来得及取消」。
R4 使该前提失效：用户看到的锁定框是**对的**（右页），取消判断失去意义——成片
仍按静帧检测的整书框裁切。修复 R4 后 R3 缓解链路才真正闭合。
