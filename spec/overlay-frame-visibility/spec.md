# Feature Specification: 取景整框可见性与锁定确认窗（overlay-frame-visibility）

**Created**: 2026-09-21
**Status**: Draft
**Input**: live-edge-crop 真机验收失败反馈（SC-001/002/003 异常）+ 取证诊断结论：
R1 = overlay 渲染坐标空间错配（屏幕点被当归一化坐标，整框与压暗挖孔画到屏幕外，scan-fidelity T019 引入）；
R2 = 自动快门在锁定首帧同帧立即触发（锁定确认视觉 0ms 呈现）；
R3 = 折页场景检测器锁定整书外轮廓（矩形检测器物理上限，本周期不修本体）。

## Overview

live-edge-crop 的「实线整框」在真机上从未可见——根因不是样式而是渲染坐标契约错配：取景 overlay 的两个 Shape 消费不同坐标空间（括号按屏幕点、整框按归一化），整框与框外压暗挖孔被画到屏幕外。同时自动快门在锁定瞬间立即拍摄，用户从未见过锁定确认视觉。本周期修复坐标契约、为自动快门增加 0.4s 锁定确认窗（可见、可中止），并以「测试期间实时抓取日志」的修正流程重验 live-edge-crop 的真机验收清单。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 取景整框与框外压暗真正可见（Priority: P1）

文档模式取景时，用户在跟随态看到连续朱砂实线整框 + 四角括号 + 框外压暗（框内画面不变暗）；锁定态整框变白粗双线、压暗加深。证件模式的检测框描边同样回到屏幕内。

**Why this priority**: live-edge-crop US2 的视觉目标因坐标错配从未生效；「所见即可裁」的信任完全建立在边框可见之上，这是本周期存在的原因。

**Independent Test**: 真机/模拟器对任一文档取景即可验证两态整框在屏幕内贴合目标；单元测试钉死 Shape 的屏幕点坐标语义。

**Acceptance Scenarios**:

1. **Given** 文档模式检测到目标，**When** 跟随态渲染，**Then** 屏幕内出现朱砂色实线整框 + 四角括号，框外压暗约 0.25、框内画面不压暗（不再是全屏均匀变暗）
2. **Given** 目标锁定，**When** 锁定态渲染，**Then** 整框变为白色粗双线（暗描边），框外压暗加深至约 0.45
3. **Given** 证件模式取景到卡片，**When** 检测框描边渲染，**Then** 描边回到屏幕内贴合证件窗口区域（回归修复）

---

### User Story 2 - 自动快门前锁定态可见且可中止（Priority: P1）

自动快门开启时，锁定达成后锁定视觉（白双线 + 压暗加深 + 震动）先呈现约 0.4s，之后才自动拍摄；确认窗内用户移开手机（解锁）即取消本次拍摄；重新锁定重新计时；每个锁定周期仍最多自动拍一次。手动快门不受确认窗限制。

**Why this priority**: 用户必须在快门前看见裁切范围才有机会中止错误锁定；「锁定即拍」让折页场景的错误成片无从避免。

**Independent Test**: 帧序列单元测试（锁定 N 帧不拍、达阈值拍、中途解锁取消、重锁重计时）；真机平整文档自动拍摄出现可感知的确认节奏。

**Acceptance Scenarios**:

1. **Given** 自动快门开启且目标锁定，**When** 确认窗累计约 0.4s，**Then** 锁定视觉呈现后自动拍摄
2. **Given** 确认窗内，**When** 用户移开手机导致解锁，**Then** 本次不拍摄
3. **Given** 解除后重新锁定并稳定，**When** 确认窗再次计满，**Then** 拍摄，且单锁定周期最多自动拍一次的既有语义保持
4. **Given** 任意时刻，**When** 用户手动按快门，**Then** 立即拍摄（不受确认窗约束）

---

### User Story 3 - 折页错误锁定看得见、来得及取消（Priority: P2）

折页厚书导致检测器锁定「整书外轮廓 / 含折起部分的大框」时，用户在确认窗内能清楚看到框住的范围，可选择移开取消，而不是等一张含折起部分的成片；若放任拍摄，既有预览调框能力兜底。

**Why this priority**: R3（曲边页不构成可检矩形）是已记录的检测器物理上限，本周期不修检测本体；「可见 + 可中止」是该限制下唯一可靠的缓解，依赖 US1+US2 达成。

**Independent Test**: 真机折页场景：错误锁定时整框可见、确认窗内移开即取消；或手动快门后预览调框修正。

**Acceptance Scenarios**:

1. **Given** 折页场景检测器锁定含折起部分的大框，**When** 确认窗内，**Then** 用户可见整框实际范围并可在快门前移开取消
2. **Given** 用户放任自动拍或手动拍下含折起部分的成片，**When** 进入预览页，**Then** 四角调框（既有能力）可修正裁切——作为已知限制的既有兜底路径，本周期不新增检测能力

---

### User Story 4 - 坐标契约与确认窗测试钉死、基线只增不减（Priority: P1）

整框渲染的屏幕点坐标约定、确认窗的帧计数行为均以单元测试钉死；既有 295 用例基线只增不减。

**Why this priority**: 回归在 scan-fidelity 引入、到 live-edge-crop 真机验收才暴露——缺测试锚点是坐标错配存活两个周期的根因之一。

**Independent Test**: 全量 `xcodebuild test` 通过，新增用例覆盖 Shape 坐标语义与确认窗计数。

**Acceptance Scenarios**:

1. **Given** Shape 传入屏幕点坐标的 quad，**When** 求 path，**Then** 输出点等于输入点（不再按 rect 缩放）
2. **Given** 伪造帧序列驱动锁定，**When** 帧数未达阈值，**Then** 不触发自动拍摄；达阈值触发；中途解锁重置计数
3. **Given** 全量测试运行，**Then** 用例总数 ≥ 295、failed == 0、known issue 豁免保持不变

---

### User Story 5 - 真机验收闭环与 SC-005 日志证据补全（Priority: P1）

修复版装机后按 live-edge-crop 的 device-acceptance 清单重验 SC-001~005；SC-005 的 `relaxedLiveProbe` 证据必须在测试期间实时抓取（Console.app 勾选 Include Debug Messages），不再事后取证。

**Why this priority**: 上一轮验收因 debug 级日志无实时监听而丢失三级兜底触发率证据；验收闭环是本周期收尾的定义。

**Independent Test**: 真机按清单逐项执行并回填结果；两场景日志可检索且触发率与场景匹配。

**Acceptance Scenarios**:

1. **Given** 修复版已装机且 Console.app 开始流式抓取，**When** 按 live-edge-crop 清单执行折页与平整两场景，**Then** SC-001~004 行为达标，SC-005 日志可检索、折页份 triggered=true 占比显著、平整份 ≈ 0
2. **Given** 验收完成，**When** 汇总结果，**Then** 回填本周期验收记录并引用至任务清单

---

### Edge Cases

- 确认窗期间 quad 微小漂移但未解锁（QuadSmoother 仍报 locked）：计数持续累计，不重置也不跳拍
- 确认窗期间用户手动快门：手动优先，拍摄后既有复位逻辑清空确认窗状态
- 证件模式与文档模式一致受确认窗约束（单一快门策略）；证件模式固定窗口不受坐标修复影响（idMask 走独立路径）
- 压暗挖孔修复后，跟随/锁定两态的压暗层次（0.25 / 0.45）数值不变，仅位置回归正确
- 检测帧率波动（actor 忙丢帧）时，确认窗按帧计数而非墙钟——帧率低时窗口相应拉长，可接受

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 取景整框 Shape 必须以屏幕点坐标语义渲染（path 输出等于输入坐标，与四角括号 Shape 同约定），并在类型文档中明确该坐标契约
- **FR-002**: 文档模式跟随态整框（朱砂约 45% 透明度、约 2.5pt 实线）与框外压暗（挖孔跟随 quad、约 0.25）必须在屏幕内正确渲染，框内画面不变暗
- **FR-003**: 锁定态整框（白色约 3pt 面线 + 暗色约 5pt 描边双实线）与压暗加深（约 0.45）必须在屏幕内正确渲染
- **FR-004**: 证件模式检测框描边必须回到屏幕内（同一坐标契约修复范围）
- **FR-005**: 自动快门前必须有锁定确认窗：锁定达成后累计连续锁定帧达阈值（默认约 6 帧 ≈ 0.4s@15fps）才触发拍摄；阈值可注入供测试
- **FR-006**: 确认窗期间任何解锁（进入 searching/tracking）必须重置计数；重新锁定重新计时；单锁定周期最多自动拍一次（既有语义保持）
- **FR-007**: 确认窗对文档与证件模式一致生效；手动快门不受确认窗限制
- **FR-008**: QuadSmoother、DetectionStrategy、三级检测链、快门回退链、贴边吸附零行为改动（对应既有测试全绿）
- **FR-009**: 测试基线只增不减：用例总数 ≥ 295、failed == 0、既有 known issue 豁免保持
- **FR-010**: 真机验收必须按 live-edge-crop device-acceptance 清单重验，且 SC-005 日志证据须为测试期间实时抓取所得

### Key Entities

- **取景整框 Shape（QuadShape）**: 坐标语义契约变更点——从「归一化 [0,1]² × rect」改为「屏幕点直接消费」；仅取景 overlay 消费，无其他调用方
- **锁定确认窗状态（CaptureViewModel 内）**: 帧计数字段 + 可注入阈值；与 didAutoCaptureThisLock（单周期单拍）协同
- **DocumentFrameStyle**: 样式纯数据不变，仅消费端坐标空间修复

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 平整文档取景 10 次，跟随态实线整框 100% 可见且贴合纸边，≥ 8 次含确认窗节奏一次锁对自动拍
- **SC-002**: 自动拍摄前锁定视觉（白双线 + 压暗加深 + 震动）可感知时长 ≥ 0.4s；确认窗内移开取消成功率 100%（≥ 3 次验证）
- **SC-003**: 折页场景错误锁定（若发生）在确认窗内整框可见且移开即取消；放任拍摄的成片由预览调框兜底并记录
- **SC-004**: 全量单元测试基线只增不减（≥ 295、0 failed）；新增坐标契约与确认窗用例全绿
- **SC-005**: 真机按 live-edge-crop 清单重验 SC-001~005 全部达标；两场景 `relaxedLiveProbe` 日志实时抓取成功，折页份 triggered=true 占比显著、平整份 ≈ 0

## Assumptions

- 确认窗时长 0.4s（约 6 帧@15fps）已经用户确认
- R3 检测本体（曲面展平 / dewarping）不在本周期范围，仅以可见性 + 中止窗缓解
- `relaxedLiveProbe` 保持 debug 日志级别（观测契约不调整，改流程不改设计）
- 自动快门默认开关状态与用户偏好不因本周期改变
- OverlaySpaceMap / FOVLayout 的映射数学已由既有测试钉死且正确（真机括号位置佐证），本周期只修渲染消费端
- 设备保持 iPhone 13（菀墨），iOS 构建签名路径不变
