## 一、项目目标与定位

**纸匣 Zhixia**：把纸上的东西干净地收进 iPhone 的**纯离线**扫描工具。

- 主路径：对着纸 → 自动框边 → 快门 → 透视拉正 + 增强 → 多页 → 入库 → OCR/版面还原 → 导出 PDF / Word。
- 对标：WPS 扫描 / 全能扫描王的主体能力；**不做账号墙、不接云**（铁律 ③ 纯离线）。
- 当前真机主场景：**左侧折起/装订的书本只拍右页**，要求成片只含右页、边界贴合、文字清晰。

## 二、架构

```
App（ZhixiaApp / RootView / AppEnvironment 组装）
  → Features（SwiftUI MVVM：Capture / Edit / Document / Reconstruct / Library / OCR / Settings）
  → Domain（纯函数：Quad、EdgeSnapper、CandidateSticky、QuadSmoother、
            SpreadSplitter、CropConsistencyGate、GuidanceDirective、版面/表格分析…）
  → Services（actor 副作用：Camera / Vision / Image / OCR / Persistence / Reconstruct / PDF）
DesignSystem（Tokens / 组件，横切）
```

- 依赖只向下；Domain 不 import Services/SwiftUI（`ZhixiaLog` 只作为注释提及）。
- 所有副作用经 `Services/ServiceProtocols.swift` 协议注入（**铁律 ①：签名不可动**）。
- 测试：Swift Testing，基线只增不减（**铁律 ②**）；2026-10-21 快照为
  **449 = 448 passed + 1 expected failure + 0 failed**，当前（2026-10-28）为
  **518 total / 507 passed / 1 expected / 10 known failures**（见 [12 §0](12-handover.md)）。

## 三、实现原理（两条主链路）

### 3.1 扫描链路（本阶段主战场）

```
AVCaptureSession 帧流（分析帧长边 1080，视频/照片宽高比 0.75/0.75）
  → VisionEdgeDetector：
      严格矩形 →（无页面档矩形时）文档分割 →（两级都空时）放宽矩形
      → DetectionStrategy 统一择优（viable 池 / 两级面积 / 包含降权 / score=面积×居中×方正）
      → CandidateSticky（相似跟随 / 同池改写 / hold-through-miss / 逃逸）
  → CaptureViewModel 摄入边界：FOVLayout 视频→照片；**预览可见域钳制**；smoother 平滑
  → EdgeSnapper 逐帧贴边吸附（最近峰策略 + s=0 守卫，双线性采样）
  → 锁定 → 冻结框（精修上屏）→ 快门直裁（成片 = 呈现框）
  → 整理页拍后增强：全分辨率重检（身份锚定 IoU≥0.85 且面积≤拍摄框×1.10）
      → 左侧折痕暗条裁切 / 中央书脊暗谷拆分（SpreadSplitter）
  → Review：拖角 / 五档滤镜 → ImagePipeline.renderPage（透视拉正 + 增强含锐化）→ 入库
```

### 3.2 还原链路

iOS 26 `RecognizeDocumentsRequest`（结构化 lines/tables）或几何兜底 OCR →
`StructuredDocumentPage` 统一 → 噪声过滤 / 阅读序 / 表格聚类 / 配图 → 流式 Word
（默认，对标 WPS）或可检索 PDF。金标准端到端套件真实 Vision 链路验证。

### 3.3 关键契约（历次卡点沉淀下来的"不变量"）

1. **WYSIWYG：成片 = 快门瞬间呈现框**（frame-truth）。快门后不再隐藏重检；贴边修正
   在锁定瞬间完成并**显示在屏幕上**（冻结框）。
2. **预览可见域 = 可拍摄内容**（scan-enhance FR-004）：预览 aspectFill 只显示照片
   中央（390×844 视图 / 0.75 视频 → 可见 x∈[0.19,0.81]）；呈现框/裁切逐顶点钳制到
   可见域——**成片不包含用户没看见的内容**；整理页重检不得把内容扩回（≤1.10 面积）。
3. **吸附最近峰**：从检出边向外/向内各找第一个过阈值的亮度边并取峰位，离检出位置
   最近者胜；s=0 守卫（边已在边上不动）。折痕/书脊（近）优先于折脊轮廓（远且强）。
4. **书页拆分两模型**：左侧折痕暗条（暗带→持续明亮列）优先；亮左页摊开书走中央
   书脊暗谷（局部凹陷评分 + V 形 + 贯穿性 + 谷宽 + 分辨率闸）。

## 四、关键实现细节（按模块）

| 模块 | 位置 | 关键点 |
|---|---|---|
| 候选择优 | `DetectionStrategy`（VisionEdgeDetector.swift） | viable 池单一真源；两级面积（0.96/1.0）；包含降权 ×0.35；页面先验页闸 `pageLikeMinArea=0.25` |
| 粘滞 | `CandidateSticky` | 默认 v1 语义；live 调用点：similarity 0.70、missLimit 5、holdThroughMiss、anchorMinArea 0.12、起锚 3 帧确认、跟随面积比 0.8、1s 清锚 |
| 平滑 | `QuadSmoother` | alpha 0.35、epsilon 0.012、areaJump 0.35、missLimit 3；live 解锁迟滞 `unlockEpsilon=0.03` |
| 贴边吸附 | `EdgeSnapper` | 最近峰；s=0 守卫（双线性 G0）；内向相限幅 0.5×、阈值 0.12；四项校验（凸性/越界/位移/面积变化 0.20） |
| 拍摄 | `CaptureViewModel` | FOV 换算；可见域钳制；逐帧吸附；锁定冻结（当前帧检测→吸附→上屏）；closer 无效框不锁定/不自动拍；直裁（不重检） |
| 拍后增强 | `ReviewViewModel` + `SpreadSplitter` | 身份锚定 + 面积闸；透视矫正后左折条/书脊两模型；结果预览可见、可拖角 |
| 增强 | `ImagePipeline` + `EnhancementRecipe` | 五档：original / enhance（锐化 0.35）/ deskewShadow（阴影 0.55）/ grayscale / blackWhite |
| 遥测 | `ZhixiaLog` | capture 级 notice（可持久化）：detectionTier / candidateProvenance / cropGate / cropQuad / snapEdge / snapOnLock / refineStage / sticky* |

## 五、卡点史与根因教训（真实数据）

| # | 卡点 | 根因 | 教训 |
|---|---|---|---|
| 1 | Case A/B：框跳、成片含左页/折起部分 | 检测门控池交替 + 粘滞 v1 盲区 + 快门门禁无真值 | 决策链每层都在"讨好自己的阈值"；不变量优先于调参 |
| 2 | 框只捕获局部文字带 | 任一 ≥0.08 矩形否决分割/放宽（页面候选从未被请求） | 门控口径必须与语义（页面尺度）绑定 |
| 3 | 成片比框大、露背景 | still 全局重选 + 仅 still 吸附 + 门禁 bbox IoU 分不清合法精修与越界 | 成片=框只能靠构造性契约，不靠事后仲裁 |
| 4 | 屏幕框和成片对不上 | **叠加层未 ignoresSafeArea**：框被缩小 ~10% 并下移 47pt | UI 坐标系也是"正确性"；截图反算是有效取证 |
| 5 | 框锁局部带/成片含折痕（第二轮） | 门控一票否决 + 粘滞 raw 池 + 逃逸抽签；已修 | 逐帧遥测（candidateProvenance/refineStage）是止血前提 |
| 6 | 白线/红线高频互跳 | 锁定被 1.2% 级抖动反复打断 | 锁定需要迟滞；"已对准"必须是稳定承诺 |
| 7 | 折起部分"在镜头外"仍进成片 | **照片视野 > 预览可见域**（aspectFill 裁掉两侧） | 取景所见必须成为可拍摄内容的硬边界（可见域钳制） |

| 9 | 取景仍抖、快门时框未贴合 | 平滑参数被既有测试帧预算钉死；噪声中位 2.4%/p90 11.7% | 产品方向已接受"取景=稳定引导框"，可做方向性翻转 |

## 六、完整优化计划（2026-10-21 现状 → 下一步）

> 优先级：P0 = 直接影响当前主场景成片正确性；P1 = 竞品对标的核心体验；P2 = 架构与工程债。

### P0-1 取景稳定性（抖动 / 白线保持 / 快门贴合）

**现状**：逐帧面积变化中位 2.4%、p90 11.7%；最近一次真机会话 1 分钟 14 次锁定转换
（白线仍被打断）；快门瞬间框与书边有偏差。

**计划**：
1. **平滑时序方向性翻转**（用户已明确产品方向：取景框是稳定引导框，不必逐帧精准）：
   - `QuadSmoother` 引入显示死区（顶点移动 <0.8% 不驱动显示）+ 重 EMA（alpha 0.22）；
   - **同步修订 `AutoCaptureHoldWindowTests` 的帧预算断言**（3 处），在
     `spec/scan-enhance/tasks.md` 逐条记录方向性翻转；
   - 锁定迟滞从 3% 复核（配合死区后可能无需那么大）。
2. **锁定即冻结的语义补强**：冻结后仅在**持续位移**（连续 N 帧 >3%）时解锁，
   避免单帧抖动打断；白线（已对准）至少保持到用户明显移动。
3. **快门时框=书边的最后一步**：锁定瞬间已有吸附（最近峰 8% 预算）；若真机仍差
   1–2%，把最大位移预算按边缘证据分档（强边少动、弱边多动），并用导出原图校准。
4. **验证**：同场景 30s 内 `snapOnLock` 次数 ≤2（当前 14/min）、白线连续保持 ≥3s、
   成片四角与书边误差 ≤短边 2%。

### P0-2 拍后裁切校准（场景 1 书脊/装订线；预览钳制回归验证）

**现状**：场景 1（整书入画）仍未拆出右页：实拍日志 `spineU≈0.71、
prominence 0.049–0.055`（低于 0.06）——全局/局部暗谷都指向页面内的深色插图；
真实切点在**装订线/左页条**（u≈0.05–0.10），且在书脊搜索区 [0.12,0.88] 之外。
最近一次快门 displayed x_min=0.159（< 可见域 0.192）——需确认钳制是否真的生效。

**计划**：
1. **用用户导出的原图做逐张校准**（最有效）：请从 App「分享」导出一两张失败原图，
   本地跑列剖面，量出装订线/书脊的真实 u、亮度与宽度，据此重标定：
   - 搜索区间扩到 u∈[0.04,0.96]；
   - 谷宽闸按装订线（暗线+孔）实测调整（可能 1–3%）；
   - 引入**装订线模型**：暗线紧贴左侧、左条为亮纸（印刷内容）→ 切在暗线右缘。
2. **钳制遥测与回归**：`refineStage`/`snapOnLock` 增加 `previewRect` 与 `clamped`
   字段，确认 `onGeometryChange` 在真机上上报（若未上报，改用 overlay 内部回调）。
3. **左右页切换**：整理页提供「整页 / 左页 / 右页」选择（默认右页），拆分误判可一键改。

### P0-3 拍后增强（去皱 / 阴影 / 清晰化）

**现状**：`enhance` 已含锐化 0.35、`deskewShadow` 阴影 0.55；Word 还原链路已存在。

**计划**：
1. **文档默认档**：为扫描件新增 `document` 增强档（白平衡 + 去阴影 + 适度锐化 +
   轻度对比），作为默认候选，A/B 后再决定是否设为默认（保留五档手选）。
2. **折痕/皱痕抑制**：MVP 用「裁切对齐书脊 + 去阴影 + 锐化」；进阶再评估
   形态学/中值去线（避免过拟合）。WPS 录屏显示其“去折痕”主要是裁掉左侧卷边，
   不是内容感知修补（[15 §十一](15-capture-recovery-assessment.md)），暂不做生成式去皱。
3. **验收**：同一页对比 WPS 的清晰度与阴影观感；OCR/还原的识别率（用金标准样张）。

### P1-1 常驻框范式（竞品对标的结构性方案）

**背景**：7 个周期在"检测驱动框"范式内修补仍未达到 WPS 的稳定感；调研报告
（docs/11 §4.2/§7）建议「框常驻 + 用户对位 + 边缘吸附」。

**计划**：
1. WPS 取景录屏已提供（2026-10-21）；结论见
   [15 §十一](15-capture-recovery-assessment.md)：手动快门、单实线自动跟随框、
   拍后重裁 + 滤镜；框会在右页/整页间切换，快门时也不紧。交互基准据此收敛。
2. 新增「引导框」模式：屏幕上固定一个基准四边形，用户移动手机把书页对进框内；
   检测只做**边缘吸附微调**（±3%），不决定框的归属；与现有自动模式并存。
   WPS 实际是自动跟随框，本方案是固定框，用确定性换自动化，不是同款复刻；
3. 成片 = 引导框（经吸附修正）；拍后增强照旧。WPS 式拍后紧裁不进入主路径，
   只作为 Review 可见提案（T041），避免破坏 WYSIWYG；
4. 评估迁移成本与旧模式保留策略，单独周期立项（wps-parity-capture）。

### P1-2 还原与导出对标收尾

- L1 真机通路取证（`reconstructPath`，iOS 26 结构化识别是否静默回退）；
- iOS 18~25 表格兜底阶梯（anchor → 通用数字列）；
- 导出层表格样式（`w:tblPr`/表头加粗/数值右对齐）与 `gridSpan`/`vMerge`；
- 与 WPS 同页对比：还原样式/字体/段落、Word 打开保真。

### P2 工程债与性能

- 取景帧率/耗时：逐帧吸附 + 分割常开在真机的耗时需 signpost 实测（目标 ≥15fps）；
- 整理页大图解码与内存（50 页 ≈ 50–150MB 峰值）；
- `SwiftDataDocumentStore` 零测试、Library N+1、Review tmp 目录清理；
- 遥测分级：notice 级 capture 日志在正式版降为 debug（开发构建保留）。

## 七、参考资料（开源/系统性做法）

- 文档扫描的常见范式并不完全一致：Apple Notes / 部分开源实现偏**固定引导框 +
  边缘吸附 + 拍后重裁**；WPS 录屏实际是**自动跟随框 + 手动快门 + 拍后重裁**
  （[15 §十一](15-capture-recovery-assessment.md)）。两条路都能稳定，差别在
  意图由谁决定；本计划 P1-1 的固定引导框靠近前者，不是 WPS 原样复刻。
- 开源实现多为 OpenCV 轮廓/边缘检测 + 透视变换（如各类 `DocumentScanner`
  项目），其时序稳定常靠固定引导框而非逐帧检测。
- Apple Vision：`VNDetectRectanglesRequest` / `VNDetectDocumentSegmentationRequest`
  （本仓库已用），`CIPerspectiveCorrection`（渲染与书脊矫正同源）。
- 本仓库周期证据：`spec/frame-truth`（框真相）、`spec/scan-enhance`（拍后增强）、
  `spec/folded-page-capture`、`spec/case-b-sticky-v2`、`spec/wysiwyg-crop`。
