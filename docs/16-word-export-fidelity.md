## 一、用户实测的问题（本次的起点）

> 「之前的方案也优化了多轮，但是最后效果还是不好，稍微复杂一点的图片内容，最后生成
> word 的样式会乱掉。」

复现样本：`docs/media/IMG_7544.jpg`——真实拍摄的**教科书右页**（横幅标题 / 圆角
提示框 / 深色表头表格 / 双栏编号列表 / 灰底词框 / 照片 / 页码 / 页脚）。

用户给的验证路径：

```
扫 → 相册 → 收藏里的第一张（IMG_7544.jpg）→ 把图片还原 → 还原版面选「高保真」
   → 导出成 Word → 把 Word 转成图片 → 与原图比相似度 → ≥90% 算通过
```

本周期把这条路径做成了**可重复的闸门**（`make word-fidelity`），并把「样式乱掉」
的根因拆成两件独立的事：

| 现象 | 根因 | 本周期处置 |
|---|---|---|
| 还原/导出里**只剩页面的一小块**（表格框 / 底边条） | 静帧检测在「页面外框检不出」时，**必然**选到页面里的子框 | T001：静帧「页面判定」——**宁可不裁**（见 §三） |
| 生成的 Word **样式乱掉**（文字重复、错位、叠字） | `.restored` 档 = 底图 + 净化 mask + **浮动文本框**原位重排；文本框与底图对不齐 | T002：新增**图片版**档（页面即图片），并成为默认档（见 §四） |

## 二、WPS 参考录屏评估（`docs/media/3ca8ce818cf785798a1661a3eef67730.mp4`）

素材：18.3s · 578×1280 · 60fps 的手机录屏（WPS 万能扫描「扫描完成 → 导出 Word」）。

### 2.1 录屏事实（逐段）

| 时间 | 画面 | 事实 |
|---|---|---|
| 0–1s | 「扫描完成」页：导出 PDF / **导出 Word** / 导出 Excel / 导出 PPT / 导出图片到相册；推荐功能「**提取文字**」 | 导出格式与「提取文字」是**两个并列入口** |
| 1–6s | 弹出「**AI 转换中…**」（带取消按钮） | 导出 Word 触发一次 **AI 转换**（云端），不是本地即时拼装 |
| 6–7s | 「导出预览」页，「正在加载…」 | 导出前有**预览**步骤 |
| 7–10s | 预览渲染出整页；弹出提示「**文档为只读**」 | 预览渲染的是**页面本身**；产物被标记只读 |
| 10–18s | 预览逐块加载：横幅标题、圆角提示框、深色表头表格、灰底词框、照片、页码、页脚 | 预览里**表格/图/色块/文字全部按原样保留**，位置与原片一致 |

### 2.2 结论（对本项目的直接影响）

1. **WPS 的「扫描件 → Word」产物是「页面图」，不是重排后的文本。**
   证据：导出预览渲染的就是页面照片（照片、表格、提示框、页码全在），且文档提示
   「只读」。可编辑文字由**另一个入口**（「提取文字」）承担。
2. **「AI 转换」是 WPS 的云端能力**（本项目纯离线、无云，对标不了也不必对标）。
3. **WPS 没有「文字重排 + 底图叠加」这种混合产物** —— 本项目的 `.restored` 档
   （底图 + 浮动文本框）在竞品里没有对应物，这正是「样式乱掉」的来源。

### 2.3 采纳矩阵

| WPS 做法 | 采纳 | 理由 / 处置 |
|---|---|---|
| Word 产物 = 页面图（只读、保真） | ✅ **采纳为主路径** | 竞品验证过的形态；「样式不可能乱」；本项目离线也能做 |
| 导出前有预览 | ✅ 采纳 | 已有「还原版面」预览；本周期让**预览 = 导出**（同源同形） |
| 可编辑文字（提取文字） | ✅ 保留为**显式第二档** | 本项目的差异化（可编辑、可搜索），但不再默认 |
| AI 云端转换 | ❌ 不采纳 | 纯离线铁律（AGENTS 铁律 3） |
| 文字与图片混合叠加 | ❌ **不再作为默认** | 复杂页面上必然错位（实测 0.77 vs 0.93） |

## 三、根因一：裁切把「整页」变成「页面里的一小块」

### 3.1 取证（`docs/media/IMG_7544.jpg`，2026-10-22）

静帧检测（`VisionEdgeDetector.detect(imageData:)`）的候选池（宽高比=面积）：

| 候选 | 面积 | 是什么 |
|---|---|---|
| 0.9784 | 0.978 | **整页**（文档分割结果，部分运行才给出） |
| 0.2502 | 0.250 | 页面**底边条**（「2 At school」页脚带） |
| 0.1332 | 0.133 | 照片区 |
| 0.0980 | 0.098 | 「Articles wanted!」表格框 |
| 0.0813 | 0.081 | 圆角提示框 |

**页面外框（矩形检测）在任何参数档下都检不出**（实测：置信 0.35/0.20/0.15、
最小边 0.08/0.20/0.30、最多 8/6 个观测，最大面积始终 ≤ 0.133）——书页边缘不直 +
透视 + 页面充满取景，没有可检出的矩形边缘。文档分割则**时好时坏**（部分运行给整页
0.978，部分运行只给底边条 0.248）。

于是「两级面积兜底 + 面积×居中×方正评分」必然落到**页面里的子框** → 整页被裁成
一小块 → 还原/导出只剩那一块。**这就是用户看到的「只识别了右页的一部分」。**

### 3.2 处置：静帧「页面判定」（`DetectionStrategy.stillPageCandidate`）

按优先级（纯函数，可单测）：

1. **大候选**（面积 ≥ 0.5）→ 它就是页面 → 用它；
2. **候选铺满整幅**（候选并集外接框面积 ≥ 0.6）→ 内容铺满画面（页面充满取景），
   任何子框都是错的 → **不裁**（整图当页面，调用方回退 `.fullImage`）；
3. 否则（票据/收据这类**子区域**文档）→ 取面积最大的候选。

「宁可不裁」的取舍：**裁错 = 内容丢失（不可逆）；不裁 = 多了背景（可逆）**——
用户随时可在 Review 拖角裁切，或用引导取景框（`spec/guided-capture`）精确框住。

## 四、根因二：「样式乱掉」= 底图 + 浮动文本框的混合产物

### 4.1 现状（`.restored` 档）

`DocxExportService.restoredPageXML`：底图（behindDoc 铺页）→ 保留区 srcRect 裁剪 →
`LayoutMask` 净化覆盖层 → **浮动文本框**原位重排（字号按页高预缩、行距按实测还原）。
预览（`LayoutCanvas`）与导出同构，但**预览里是 SwiftUI 绘制、导出里是 OOXML 浮动
定位**——两者只要有 1px 偏差就出现「文字压在图上自己的文字上」。

### 4.2 实测（`out-restored.docx` 渲染图）

见 `spec/word-fidelity/device-acceptance.md` §2 的截图：同一行文字出现**两份**
（底图里的原字 + 文本框里的重排字），且互相错位——即用户说的「样式乱掉」。

### 4.3 处置：新增「图片版」档（`.pageImage`），并成为默认档

`DocxExportService.pageImageBodyXML`：每页 = **A4 贴合尺寸的页面 + 一张铺满该页的
整页图**（内联图 `wp:inline`）。**没有浮动文本框 / 没有 mask / 没有重排** → 版面
不可能乱。

实现要点（都是实测踩出来的）：

| 要点 | 原因 |
|---|---|
| 页面尺寸 = A4 内按图片比例**贴合** | 老口径按 96 DPI 换算页面 → 41.5cm×55.9cm 的巨页，预览器按纸面裁切 → 只露出左上角，「看起来是空白」 |
| 图片用**内联图**（`wp:inline`），不用锚定图 | 锚定图（`behindDoc`）在部分预览器上不落图（实测渲染出空白页） |
| 承载段落的**行高钉成图高**（`lineRule="exact"`） | 行高被段落标记字号压扁 → 内联图被裁成一条线（空白页）；行高比图高 → 整页图被挤到第二页（预览只显示空白的第一页） |
| 段落标记**不设 1pt 字号** | 同上：行盒被压扁 → 图被裁 |
| 页面尺寸 = 图片尺寸（不留余量） | 余量造成图与页差 1%，比对时变成整体错位 |

档位体系（`R2OutputTier` / `ExportTier`）：

| 档位 | 形态 | 可编辑 | 默认 |
|---|---|---|---|
| **图片版** `pageImage` | 整页图铺满页面 | ✗ | ✅ **新默认** |
| 版面还原 `highFidelity` | 底图 + mask + 浮动文本框 | ✓ | 可选 |
| 流式 `flow` | 段落流 | ✓ | 可选 |

默认翻转的依据：① WPS 实测（§二）；② 用户实测「复杂页面的 Word 样式会乱」；
③ 文字检索由 App 自身 OCR 索引承担（`applyOCRBlob`），不依赖 Word 里的可编辑文字。

## 五、验证闸门（`make word-fidelity`）

```
make test-only T=WordFidelityExportTests   # 产出 build/word-fidelity/{page.jpg,out-*.docx,reference.jpg}
./Tools/word-fidelity/check.sh              # 渲染 docx → 算 SSIM → 对门限
```

- 渲染：**macOS QuickLook（`qlmanage`）** —— 系统自带的 Word 预览器（无需 Word/LibreOffice）；
- 指标：**SSIM**（ffmpeg），口径固定为「缩放到 800×800 + 高斯模糊 sigma=3 后比较」
  （模糊 = 亚像素错位容差；不模糊时同一张图也只有 0.6——SSIM 被文字笔画边缘吃掉）；
- 门限：**导出保真度 SSIM ≥ 0.90**（渲染图 vs 页面图）；
  同时打印**用户口径**（渲染图 vs 原始照片）。

### 5.1 实测结果（2026-10-22，IMG_7544.jpg）

| 产物 | SSIM(页面图) | SSIM(原始照片) | 判定 |
|---|---|---|---|
| **图片版** `out-pageimage.docx` | **0.914** | **0.919** | ✅ 达标（双口径均 ≥0.90） |
| 版面还原 `out-restored.docx`（对照） | 0.767 | 0.773 | ✗ 明显不达标（「样式乱掉」的量化） |

两档的差距（0.91 vs 0.77）就是「图片版 vs 浮动文本框重建」的直接量化证据。

## 六、遗留与后续（不在本周期）

| # | 事项 | 说明 |
|---|---|---|
| 1 | 页面外框检不出 | 本周期靠「不裁 + 手动裁 + 引导框」兜底；自动页面定位（更强的分割/边缘模型）另立周期 |
| 2 | 图片版不可编辑、不可搜索 | 可编辑两档仍在（显式切换）；后续可做「图片 + 隐藏文字层」的可搜索图片版 |
| 3 | 校验依赖 macOS QuickLook | CI/其他平台需换渲染器（LibreOffice → PDF → 位图）；口径（缩放+模糊+SSIM）不变 |
| 4 | 真实样本语料 | 本周期夹具 1 张（IMG_7544）；应扩到 10–20 张（整书/双栏/表格/票据/手写） |
