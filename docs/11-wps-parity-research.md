## 0. 结论速览

1. **版面还原**：智侠已有与 WPS 同族的「流式重建」产物（structured 档），但用户导出的默认档是
   「底图+遮罩+文本框」像素合成（restored 档）——范式选错是「乱」的根源；假表格来自 v1
   无锚点聚类器；丢字有 4 个代码级候选机制；**iOS 26 结构化通路在真机（26.7）上疑似静默
   回退**，是最高杠杆的疑案。**优化主线：接通真机结构化通路 → 流式档升默认 → 表格/丢字
   防护 → 对标校准**。
2. **取景拍照**：WPS 是「常驻取景框 + 用户对位 + 边缘自适应吸附」范式，用户对位动作就是
   锚点，**结构性不存在候选振荡问题**（Case A/B 病根被绕开）；智侠全自动检测锁定范式经
   7 个周期修补（R1~R5）后仍败，边际收益已尽。**优化主线：文档模式切换为常驻框范式**，
   自动检测降级为吸附辅助。
3. 智侠对比 docx 的「无字体声明」为误判（字体在 styles.xml：Calibri+宋体），观感差异非结构性。

## 1. 对标范围与证据基础

### 1.1 对标物

WPS 扫描（金山）两部分能力：
- **取景拍照**：常驻取景框不跳动，用户把框对准目标（如书右页四角），框自适应物体边缘，
  拍出即框内内容；
- **版面还原**：扫描图 → Word，版面布局好：文本成段可编辑、图片区域抠出嵌入、不造假表格、
  文本完整（含漫画条内文字 "wrong bus!" 以像素或文本形式保留）。

### 1.3 版面管线代码摸底（explore 取证，路径:行号均已核）

- **管线**：拍摄/导入 → `PageDraft{quad}` → `ImagePipeline.renderPage`（透视校正+滤镜，
  最长边 2200px）→ `OnDeviceDocumentParser.parse` → `ReconstructPage` → 预览
  （`LayoutCanvas`）→ `DocxExportService.makeDocx(tier)` → 手写 XML + `ZipArchive`。
- **双 OCR 通路**：结构化（iOS 26+ `RecognizeDocumentsRequest`，产出 lines+**tables**+barcodes，
  `VisionDocumentStructureRecognizer.swift`，**优先**）→ 几何回退（`VNRecognizeTextRequest`
  .accurate 多轮择优，**仅 line 级 bbox**，`VisionTextRecognizer.swift`）。
- **双导出档**：restored（底图+遮罩+文本框+原生浮动表，**默认**）/ structured（标题/段落/
  行内裁图/原生表块流，**架构上与 WPS 同族但不是默认**）。
- **表格检测三级**：Apple 结构化表（真表）→ `TableGridV2Detector`（锚点门控：「营养成分表」
  类关键词，无锚不产出）→ **`OnDeviceTableCluster` v1 兜底（无锚点门控，107 行，
  `TableProfile.swift:6` 自述「看着像表格就当表格」）——假表格实锤源头**。
- **表格/条码框内行剔除**：落表外接框（−0.02）或条码框（−0.012）内的 OCR 行**不进文字层**
  （`OnDeviceDocumentParser.swift:51-52,76-84`）——假表格会连带吞正文。
- **丢字候选机制（按嫌疑排序）**：① 被假表格 bbox containment 剔除（与右下假表格同页强相关）；
  ② Vision line 级漏识（漫画字体/斜体）；③ `OCRNoiseFilter` 页缘剔除（maxY>0.965）；
  ④ `OnDeviceReadingOrder` 页眉短行规则（**文本 <10 字符——"wrong bus!" 恰好 10 字符踩线**，
  `OnDeviceDocumentParser.swift:330-337` 附近规则）。
- **图片区域**：structured 档已把 figure/barcode 裁 PNG 内联（`NormalizedImageCrop`）；
  restored 档靠底图透出 + `a:srcRect` 二次裁嵌。漫画条整条抠图能力未验证
  （`InkFigureDetector` maxTextCoverage 0.35 主判据对细长竖条图形的覆盖未知）。

### 1.4 真机关键事实（本报告最重要的新发现）

- **iPhone 13（iPhone14,5）系统 iOS 26.7**，部署目标 iOS 18.0 → **结构化通路在真机本应可用**。
- 但 2026-09-21 真机导出的 docx：假表格为 v1 几何聚类签名 + 单元格是破碎行级 OCR 文本
  → **该次解析走的是几何回退通路**。
- 结合「结构化通路仅模拟器验证过」（`ReconstructEndToEndTests.swift:26-27` 注释自认）：
  **结构化通路真机接通性从未验证，且在真实输入上疑似静默回退**。
  这是版面周期最高杠杆疑案：Apple 结构化产出（真表格行列+更完整文本）是纯离线条件下
  最接近 WPS 版面引擎的现成能力。

## 2. WPS 扫描技术方案画像（从产物与交互反推）

### 2.1 取景拍照：常驻框范式

用户操作流：框常驻视场（不跳动）→ 用户移动手机让框罩住目标四角 → 框「自适应物体边缘」
（吸附微调）→ 拍出 = 框内内容。

推断技术组件：
1. **引导框**：固定基准位置/大小，不随检测结果跳动（视觉稳定性的根源）；
2. **边缘吸附辅助**：检测到的文档边缘只用于把框角点**微调吸附**（snap），不改变框的主体；
3. **快门语义**：裁切基准 = 呈现框（所见即所得天然成立，无需门禁仲裁）；
4. 用户对位动作 = 意图锚点 → **不存在「检测器选哪个候选」的问题**。

### 2.2 版面还原：语义流式重建

从 WPS docx 证据推断管线：版面分析（阅读序/段落/区域分类）→ 文本区 OCR 成段 →
图形区整块抠图 → 流式文档生成（段落按阅读序、图片内联在原位、**不硬造表格**、
页面按原图比例）。

| # | 差距 | 根因定位 | 严重度 |
|---|---|---|---|

## 4. 技术优化方案

### 4.1 周期 1：wps-parity-layout（版面还原对标，优先）

**总目标**：默认导出对标 WPS 观感——流式可编辑文档、阅读序正确、成段、图片内联、零假表格、
零静默丢字。测试基线 317 只增不减。

| 工作流 | 内容 | 验收标准 | 风险 |
|---|---|---|---|
| **W1 结构化通路真机接通诊断（P0）** | 用本次语法页原图在真机复现：加通路选择日志（structured 成功/失败/原因），定位静默回退点；修复接通；若 Apple 通路对该输入确实失败，固化判定并保证几何回退质量 | 真机解析该页走结构化通路（或失败原因明确可控）；表格来自 Apple 真表或无表 | Apple API 真机行为未知；需真机调试会话 |
| **W2 v1 表格聚类器门控/退役（P0）** | v1 加锚点/场景门控与 v2 对齐，或默认不产出（诊断开关可开）；消除「散排文字→假表」 | 语法页类输入不再产出假表；既有表格测试（营养成分类）不回归 | 几何通路低版本设备不再有表（可接受：宁缺毋假） |
| **W3 丢字防护（P0）** | ① containment 剔除改造：被表格/条码框剔除的行必须有去处（进单元格/并入说明），禁止静默丢弃；② 页眉短行规则边界复核（<10 字符踩线问题）；③ 导出前「墨迹-文本对账」哨兵：原文区域有墨但文字层为空的区域记日志（不阻断导出） | 用语法页原图：导出含 "wrong bus!"（或哨兵明确报告 Vision 漏识）；单测覆盖 containment 改造与页眉规则 | "wrong bus!" 若为 Vision line 级漏识，属检测器上限，哨兵可证 |
| **W4 阅读序/段落对标校准（P1）** | 以 WPS 产物为金标准对照校准 `clusterParagraphs`：行距/缩进/同段合并策略；段落粒度向 WPS 靠拢（42 段量级） | 语法页导出段落结构与 WPS 差距可量化收敛（段数/顺序对照表） | 启发式调参回归风险；用金标准快照测试锁定 |
| **W5 图片区域增强（P1）** | 验证/增强细长竖条大图形（漫画条）检测：`InkFigureDetector`/`FigureRegionsV2` 对 1021×2496 类区域的能力；structured 档内联 | 漫画条在 structured 档整条抠图内联 | 细长区域与文字列混淆风险 |
| **W6 档位重定位（P0 决策项）** | structured 档升默认导出；restored 档降级为可选「高保真」或退役（**评审决策**）；L7 底图重复锚放 bug 一并清理 | 默认导出 = 流式文档；restored 档决策记录在 spec | 老用户预期变化；restored 档测试资产处置 |

**真机验收协议（草案）**：至少 3 类输入，与 WPS 同图对照——① 本次语法练习页（金标准
docx 已存 docs/）；② 真表格页（营养成分表类，验 W2 不误伤）；③ 图文混排页（验 W5）。
Console.app 全程抓取（新增通路选择/丢字哨兵前缀）。

### 4.2 周期 2：wps-parity-capture（取景对标）

**总目标**：文档模式切换为 WPS 式常驻框范式——框常驻不跳、用户对位四角、边缘自适应吸附、
拍出即框内。Case A/B 在新范式下自然消解。

架构草案（spec 阶段细化）：
1. **GuideFrame**：常驻引导框（基准位置/大小 + 视觉态：对齐/未对齐）；
2. **EdgeSnapAssist**：复用 `VisionEdgeDetector` 边缘结果做角点吸附微调（自动检测降级为
   吸附辅助，不再决定框位置）；
3. **快门语义**：裁切 = 呈现框（透视校正到矩形），`CropConsistencyGate`/`CandidateSticky`/
   `QuadSmoother`/确认窗在该范式下大幅退役或简化；
4. **迁移**：文档模式默认新范式；旧自动锁定是否保留为可选模式（评审决策）；证件/导入路径
   不动；Case A 根因取证（H1/H2）并入本周期（诊断价值，不阻塞新范式）。

风险与待取证：WPS 交互细节需录屏确认（框固定还是弹性？吸附时机？有无自动快门？多页连拍
交互？）——**开放问题 Q3**。
