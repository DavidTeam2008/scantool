## 一、结论

`docs/14` 的诊断质量很高，但**优先级是反的**。项目现在不是“框还不够稳”，
而是三个更底层的问题：

1. **管线没有“我要拍右页”的意图表达**——候选择优天然偏向整书；右页即使
   被检出，也可能被包含降权压掉。
2. **锁定/解锁判据是逐帧差，不是累计位移**——慢速移动时系统会锁在旧框上；
   越调角度越不恢复，快门时框与书边有偏差。
3. **没有端到端真值/回放**——449 个单测证明不了真机成片正确；每轮修复都
   在“单测绿、真机败”之间循环。

如果按 `P0-1 → P0-2 → P1-1` 执行，大概率是第 8 个周期继续在同一范式里调
阈值。建议先做 **3–5 天的引导框 MVP**：把“锁谁”交给用户，把 WYSIWYG 变成
构造性事实；自动检测降级为“一次自动对位”和兜底。

### 基线核实

2026-10-21 实测：

- `make test` 直接执行会失败在 destination：`iPhone 17 Pro` 只有 iOS 26.4.1，

- 指定 `OS=26.4.1` 后：`total=449 passed=448 failed=0 expectedFailures=1

**先修基线，否则后面所有“全绿”都不可复现。** 该任务已列入

## 二、对 `docs/14` 的评价

### 2.1 对的部分

- **证据文化**：逐帧遥测、根因表、真机复测记录，是后续所有工作的基础。
- **WYSIWYG 契约**：成片 = 呈现框、快门后不隐藏重检，方向完全正确。
- **架构分层**：Domain 纯函数、协议注入、测试只增不减，给重构留了空间。
- **竞品方向**：`P1-1` 的“固定引导框 + 用户对位 + 边缘吸附”与 Apple Notes /
  部分开源实现同族，判断是对的；但 WPS 录屏实际是**自动跟随框**，不是固定框
  （见 §十一），不能把它当作同款证据。
- **拍后增强 / 还原链**：Word 还原金标准、`SpreadSplitter` 的两模型思路，
  都是可复用资产。

### 2.2 需要纠正的判断

#### ① 根因不是抖动，是“锁谁”

`DetectionStrategy.bestCandidate` 对所有**被外框包含**的候选乘
`containmentPenalty = 0.35`；`Quad.score = 面积 × 居中 × 方正`。

在摊开书里，整书是外框，右页是内部矩形。只要整书候选在池里，右页就会被
×0.35 压下去，整书赢是**评分结构决定的**，不是阈值问题。`CandidateSticky`
的“先稳者胜”又会把整书稳定下来——稳定地锁错。

`docs/14` 说“候选池里只有整书一个候选”，但 `candidateProvenance` 目前只记
数量/最大面积，没有把全部候选四角落盘。因此现在无法区分：

- **右页没检出** → 只能拍后拆或引导框；
- **右页检出了但被评分压掉** → 可以改评分 / 加意图。

这两个结论对应完全不同的修法。下一步先把所有候选（四角、面积、score、
containment）打进 trace，再决定。无论哪种，引导框都能解决。

另外，文档把“预览四角调框”当作缓解，但：

- `EdgeOverlayView` 当前是 `.allowsHitTesting(false)`；
- `CaptureView` 没有可拖角；
- 真正的手动兜底只在 Review。

**用户目前没有表达“我要右页”的入口。**

#### ② 锁定判据有一个慢漂移 bug

`QuadSmoother.ingest`：

```swift
smoothed = previous.interpolated(toward: incoming, alpha: alpha)
let distance = previous.meanVertexDistance(to: incoming)
if distance < stableThreshold { stableTime += frameDt }
```

它比较的是**上一帧平滑值**和**本帧观测**，不是冻结框。后果：

- 用户以 1%/帧慢速平移：tracking 阈值 `epsilon = 1.2%`，`distance = 1% < 1.2%`；
  按固定 `frameDt = 1/15` 计 0.55s（真实 ~30fps 约 0.28s）后判定“稳定”并锁定；
- 锁定后阈值是 `unlockEpsilon = 3%`，每帧仍 1% < 3%，永远不解锁；
- `frozenQuad` 停在锁定那一刻，页面继续移动，框不跟。

这正好解释“调角度也不恢复”“快门瞬间框与书边有偏差”。

`docs/14` 提出的“连续 N 帧 >3% 才解锁”如果仍是**逐帧阈值**，还是漏掉慢
漂移。正确做法是：

- 锁定判据看**稳定窗口内的累计范围**（最老观测 vs 最新观测），不是逐帧差；
- 解锁判据看**相对冻结框的累计位移**（例如 >3% 持续 150ms，或 >2% 持续
  500ms）；
- 用 `VideoFrame.timestamp` 算 dt，不要写死 `frameDt = 1/15`。

顺带一个硬事实：真机检测约 29.5fps，但 `frameDt` 写死 1/15。所谓 0.55s
锁定实际约 0.28s；6 帧自动快门确认窗实际约 0.2s，不是文档写的 0.4s。

**所以 P0-1 的“alpha 0.22 + 显示死区”先不要做。** 它会把“稳定”做成
“滞后”，而且不解决冻结框不跟手的问题。先修状态机，再谈滤波系数。

#### ③ 坐标系仍然没有真值

`CaptureViewModel.visiblePhotoRect` 是解析式计算出来的，依赖 `previewSize`
和 `geometry.videoAspect`。`docs/14` 自己指出 `displayed x_min=0.159 <
可见域 0.192`——这说明要么钳制没生效，要么坐标系假设不成立。在确认之前，
P0-1/P0-2 的调参可能都发生在错误的坐标上。

还有两个隐患：

- `clampedToPreview` 逐顶点钳制后没有重新校验凸性，可能把四边形钳成
  非凸/退化；
- `CameraPreviewBinder.overlayTransform` 的注释叫“照片空间”，但
  `layerRectConverted(fromMetadataOutputRect:)` 的输入是 metadata/预览
  空间；视频与照片宽高比不一致时，它和 `OverlaySpaceMap` 的
  photo→video→screen 不是同一空间。

**1 小时就能验**：在屏幕左边缘贴一个亮标记，拍一张，看成片左边缘是不是
这个标记。如果标记出现在成片里，就是坐标映射错了；如果没出现，再看
`previewSize` 是否在首帧还是 `.zero`。这个测试比再调一轮平滑更有价值。

#### ④ 拍后拆分是在“事后猜意图”

`SpreadSplitter.leftFoldTrim` 找的是“从左侧第一个持续明亮列”。如果真实
场景是“左侧暗线 + 亮左页条 + 右侧书页”，它可能切在**亮条左缘**，而不是
装订线/书页右缘——这样会把左页条保留下来，方向正好反了。`docs/14` 里
“真实切点在装订线/左条、u≈0.05–0.10”的描述，和当前模型并不是同一个
几何位置，需要原图确认。

另外：

- `searchRange = 0.12...0.88` 确实排除了 0.05–0.10；
- 但只把范围扩到 0.04–0.96 不够——全局/局部暗谷可能改选到页边阴影或
  深色插图；
- 最危险的是：`ReviewViewModel` 会自动改写 `drafts[index].quad`，
  **没有分割线 UI、没有撤销、没有“整页/左页/右页”选择**。一次误判就是
  静默裁掉内容。

在引导框模式下，右页由用户框定，拆分根本不在主路径上。自动拆分可以保留
为“提案”，但必须可见、可拖、可撤销。

#### ⑤ 过程问题：没有 trace/replay，测试治理在反噬

449 个测试全绿，但真机仍失败，说明测试的“真值”选错了：大量用例钉的是
**每层阈值/帧预算**，不是用户场景。`AutoCaptureHoldWindowTests` 用固定帧数
钉 0.4s，实际 30fps 下只有 0.2s——这不是测试太严，是测试和产品时间语义
脱节。

“既有断言零修改”在保护资产的同时，也挡住了结构性修复。建议分成两类：

- **契约测试**：WYSIWYG、不可见内容不入片、无效框不自动拍、证件/导入/
  导出不回归——不可动；
- **调参测试**：具体阈值、帧数、候选分数——允许随 spec 修改，在
  `tasks.md` 记录理由。

同时补上：

- `CaptureTrace`（每帧时间戳、全部 viable + top 8 候选四角/分数、sticky/smoother 输出、
  冻结框、previewSize/geometry）；
- 一键导出诊断包（原图 + 最近 5s 低分辨率帧 + JSON + 截图）；
- 12–20 个标注场景的 replay 测试，输出“四角误差 / 禁止内容入片率 /
  锁定延迟 / 转换次数”。

没有这个，下一次修复仍然只能靠猜。

## 三、因果链

```text
缺少“右页”意图
  → 评分偏好整书（包含降权 ×0.35 / 面积×居中×方正）
  → 粘滞“先稳者胜”把整书稳下来
  → 冻结框 = 整书；成片含左页/折痕
  → 拍后拆分用亮度剖面猜书脊
  → 真实切点在 0.05–0.10（搜索区外/亮条）
  → 用户看到“还是卡在卡点”
```

所以主线不是“把检测调得更准”，而是**把意图补进管线**。引导框是最便宜的
意图入口。

## 四、推荐路线：引导框 MVP，而不是继续调平滑

### 4.1 方案对比

| 方案 | 改动量 | 对主场景 | 风险 | 建议 |
|---|---|---|---|---|
| A 继续调自动检测 | 小 | 不确定，已 7 个周期 | 阈值过拟合、继续回归 | 不作为主线 |
| B 引导框 MVP | 中 | 直接解决“锁谁” | 用户多一步对位 | **主线** |
| C 引导框 + 一次自动对位 | 中 | 兼顾效率 | 自动对位可能错，但可撤销 | **推荐** |
| D 只做拍后拆分 | 小 | 事后补救，仍可能含左页 | 书脊模型不稳 | 兜底 |

### 4.2 为什么引导框能一劳永逸地解决 WYSIWYG

- 引导框画在屏幕上，用户只能把它放在**可见预览**内 → 成片不可能包含
  用户没看见的内容，不需要 `visiblePhotoRect` 钳制；
- 裁切 = 引导框映射到照片 → 不需要 `CandidateSticky`、`QuadSmoother`
  锁定、`frozenQuad`、6 帧确认窗；
- 检测只用于“自动对位一次”，不再逐帧决定框的位置 → 不会抖、不会锁错、
  不会白线/红线互跳；
- 右页/左页/整页由用户直接表达 → 不需要从亮度剖面猜书脊。

这不是“放弃自动”，而是把自动降级为辅助；自动模式保留为设置项，先用
A/B 验证，不搞大爆炸迁移。

> **WPS 参考录屏（2026-10-21）** 进一步支持这个判断：WPS 的框在 20s 快门时
> 仍明显松于页边，成片却更紧、更亮；它是自动跟随框，稳定感来自手动快门 +
> 单实线显示 + 拍后重裁/滤镜，而不是逐帧检测零抖动。详见 §十一。

## 五、10 天落地计划

### Phase 0：把真值建起来（2 天）

- 修 `Makefile`：pin 模拟器 OS（或新建 iPhone 17 Pro on 27.0），把基线行
  改成 397；更新 `AGENTS.md` / `docs/12` 的过期数字。
- 加 `CaptureTrace`（debug only）+ 一键导出 zip：原图、最近 5s 帧、每帧
  全部 viable + top 8 候选四角/分数、sticky/smoother/frozen 状态、previewSize/geometry、
  cropQuad。
- 跑 1 小时验证：
  - V1 屏幕边缘标记 → 成片是否包含；
  - V2 全部候选落盘 → 右页到底在不在池里；
  - V3 带时间戳的锁定轨迹 → 实际 fps / 锁定转换 / 慢漂移。
- 用 12–20 张标注图建 `CaptureCorpusTests`：输出四角误差、禁止内容入片率、
  锁定延迟、转换次数。

**产出**：一条命令重放一次真机会话，给出可比较的数字。

### Phase 1：引导框 MVP（4 天）

- `CaptureIntent`（`.auto` / `.rightPage` / `.leftPage` / `.wholePage`）+
  持久化；默认 `.auto`，文档模式可切。
- `GuideQuad` overlay：四角拖拽、重置、一次“自动对位”；手柄 44pt，白线 +
  暗描边。
- `CaptureCanvasMap`：屏幕 ↔ 预览 ↔ 照片的显式映射；用预览层实际
  `videoFormat`，不要假设 `videoOutput` 的 aspect 等于预览 aspect；加
  round-trip 测试。
- 捕获路径分支：引导模式直接用 guide quad 作为 crop，不跑 detector /
  sticky / smoother；相册导入/证件路径不变。
- 边缘吸附只在**松手/点“对位”**时跑，限幅 2–3%，结果上屏；快门时不再改框。
- 真机 20 张：折页书右页 ×10、摊开书 ×5、平整 A4 ×5；填
  `device-acceptance.md`。

**验收**：20/20 成片只含引导框内容；左缘无折痕/左页；四角误差 ≤ 短边
0.5%；单页拍摄 ≤5s。

### Phase 2：Review 兜底（2 天）

- Review 加分割线 + “整页/左页/右页”选择；自动拆分只作为**提案**，低置信
  不自动应用；可撤销。
- 自动拆分的 `u` 误差在标注集上量一遍；再决定是否扩 `searchRange`、是否
  改 `leftFoldTrim` 的切点定义。
- 新增 `document` 增强档（白平衡 + 去阴影 + 锐化 + 轻度对比），与 WPS 同页
  对比后再决定是否默认（独立小周期 T040，不占用本周期验收时间）。
- WPS 式“拍后自动裁边”不进入主路径，作为 Review 可见提案（T041，后续）；
  只有落在框内、置信达标且可撤销时才应用。
- 用户拖角/改分割的结果本地留样（可选、纯离线），作为下一轮校准语料。

**验收**：0 次静默误裁；10/10 可一键修正；8/10 自动提案误差 ≤2%。

### Phase 3：决策与收尾（2 天）

- A/B：引导 vs 自动，各 20 张，比较成片正确率、拍摄耗时、修正次数。
- 如果引导赢：文档模式默认引导，自动保留为可选；停止在 sticky/smoother
  上加分支。
- 如果自动仍要作为主线：按顺序修，不要再调 alpha：
  1. canvas/坐标真值；
  2. 单状态机（稳定窗口 + 累计漂移 + 时间戳 + 单一显示真值）；
  3. 候选意图/页面侧评分；
  4. 最后才是滤波参数。
- 若目标升级为 WPS 式**自动跟随框**（单实线 + 手动快门 + 允许候选切换），
  另立检测/模型/语料周期；不要把它压缩成 sticky/alpha 调参（见 §十一）。
- 并行 0.5 天：跑 `reconstructPath` L1 真机取证，填
  `spec/wps-parity-layout/device-acceptance.md` §A。
- 更新 `AGENTS.md`、`docs/12`、`docs/14`、`spec/scan-enhance/tasks.md` 的
  基线与状态。

## 六、验收指标

| 项 | 指标 |
|---|---|
| WYSIWYG | 20/20 成片 = 引导框；四角误差 ≤ 短边 0.5%；0 隐藏内容 |
| 拍摄耗时 | 折页书 ≤5s；翻页后重复拍摄 ≤3s |
| 引导稳定性 | 框零自动移动；无抖动；用户松手后不漂移 |
| 自动模式（若保留） | 静止场景锁定后 0 次转换；1%/s 慢漂移必须解锁；5% 移动 ≤300ms 解锁 |
| 拆分 | 0 次静默误裁；8/10 提案 ≤2%；10/10 一键修正 |
| OCR/Word | 金标准套件不回归；L1 通路有明确结论 |
| 性能 | 检测+吸附 ≤15ms/帧 @1080p；目标 ≥30fps；50 页内存有基准 |
| 回归 | 平整 A4 / 证件 / 相册导入 / 导出 / 真机条码 |
| WPS 对照（参考，不设门禁） | 同页 5 张：左折边入片 0；记录白底亮度/对比/饱和度差异；OCR/Word 不回归 |

## 七、不要做的事

1. **不要先把 `alpha` 改成 0.22 或加显示死区**——会增加滞后，且不解决冻结框
   不跟手。
2. **不要继续加 sticky 分支/调相似度阈值**——这是在同一范式里加补丁。
3. **不要在没量剖面之前扩 `searchRange`**——可能从“切错一列”变成“切错
   另一列”。
4. **不要自动应用拆分结果**——必须可见、可拖、可撤销。
5. **不要把“448 全绿”当成产品验收**——真机 device-acceptance 空着就是
   没完成。
6. **不要改 `ServiceProtocols` 签名**——需要预览几何就加新协议/闭包，
   不动旧协议。
7. **不要接云**——纯离线是铁律。
8. **不要把 WPS 的拍后自动重裁照搬成静默改 quad**——本周期引导路径仍是
   “成片=框”；WPS 式重裁只能作为 Review 可见提案（T041），不得在快门后
   隐藏换框。
9. **不要把“去折痕”理解成生成式修补**——录屏里 WPS 是裁掉左侧卷边（甚至
   裁掉一点字母），不是内容感知填补；先做裁切，别做生成式去皱。

## 十一、WPS 万能扫描参考录屏评估（2026-10-21）

### 11.1 素材与方法

- 素材：[`docs/media/43f328c65e28765077cf4ea9760b44b4.mp4`](media/43f328c65e28765077cf4ea9760b44b4.mp4)，
  49.39s，580×1280，HEVC 约 28fps（1383 帧），手机屏幕录制。
- 方法：1fps 全片抽帧 + 关键段 10fps 抽帧 + 关键帧全分辨率目视；未分析音频轨
  （与取景无关）。亮度/饱和度只对同页纸面做粗略采样，不作验收数字。
- 边界：屏幕录制不是原始相机帧，无法证明 WPS 的内部算法、检测频率或具体
  滤镜参数；以下均为黑盒行为推断。

### 11.2 录屏事实（时间线）

| 时间 | 观察到什么 | 能说明什么 |
|---|---|---|
| 0–3.5s | 首页 → 万能扫描；无取景框 | 入口 |
| 4–5s | 书打开，左页外缘卷成白边；蓝色实线框出现并随页面移动，覆盖可见页面（含左页），无角手柄 | 框是自动跟随，不是固定框；折页/卷边场景下能框住可见页，但未贴紧卷边 |
| 6–11s | 蓝框自动跟随整摊书；8–9s 的 10fps 抽帧显示框平滑跟随，无明显闪烁 | 高频显示稳定；不等于每帧检测无噪 |
| 12s | 蓝框自动缩到右页 | 候选会在“右页/整页”之间切换 |
| 13–18s | 蓝框在右页/整页间变化；18–19s 有折页/纸片遮挡，框仍可见 | 不是完美的意图识别；用户仍可手动拍 |
| 20–21s | 用户按快门；框覆盖整摊书，上/下留木纹，左边框未贴紧卷边 | 框不要求紧贴；无自动快门/倒计时 |
| 21–25s | “图片处理中” → 成片预览 | 拍后有独立处理 |
| 26–27s | Toast“已自动裁剪画面并应用最佳效果滤镜”；成片透视拉正、左侧卷边消失、白底更亮；左缘“W”被裁掉一点 | 成片比预览框更紧；折痕是裁切去除，不是修补 |
| 28–49s | 导出 PDF/Word、保存图片、分享 | 与取景无关 |

**结论 1：不能从录屏证明“WPS 检测比我们准”，也不能证明“只需调阈值”。**
它是自动跟随框，在 8–9s 的 10fps 抽帧下确实平滑，但 1s 尺度会切换右页/
整页，快门时也不紧。可确定的是：它把检测误差藏在“单实线 + 手动快门 +
拍后重裁/滤镜”的交互里，而不是要求每一帧都完美。继续在自动检测逐帧阈值上
加分支，不是这段录屏支持的路线；但复制它的自动跟随，需要检测/模型层面的
工作，不能只靠平滑参数。

**结论 2：右页检测在折页场景确实成立，但不是稳定的“意图”。** 12s、15–18s
说明 WPS 能框住右页（此时左页折起/只剩单页可见）；6–11s/20–21s 整摊书可见时
又框整幅，成片也包含左右两页。这不等于“整书入镜也能稳定锁定右页”；它更像
“当前最佳页面候选”，不是“用户说要右页”。我们的 `CaptureIntent.rightPage`
比继续猜候选更确定。

**结论 3：成片干净的关键在拍后重裁 + 滤镜。** 20s 框上缘在木纹上，27s 成片
没有木纹，且左卷边消失；Toast 也明说自动裁剪。可以推断（不能证明）WPS 在
快门上/拍后对静帧重做了一次页面检测/裁切。我们 `ReviewViewModel.refineQuads`
已有同方向的身份锚定重检，但拆分模型和静默应用是短板。

**结论 4：“去折痕”是裁切，不是生成式修补。** 27s 成片左缘把“Writing”的
“W”裁掉了一部分，说明它只是把裁切框向内收，而不是内容感知填补。不要为
“去皱”引入生成式模型；先把页面边界裁准。另外，这次成片仍包含左右两页
（只去掉卷边），说明 WPS 的“自动裁剪”不等于“只拍右页”；右页专裁仍需
用户意图/框选。

**结论 5：WPS 不是“固定引导框”，而是自动跟随框。** 录屏里没有角手柄/
拖拽，框随页面移动；它有时框右页、有时框整摊书。我们的 guided 方案是另一种
取舍：用一次对位换确定性，保证右页专裁，不是 WPS 同款。WPS 的自动框证明
“自动路径可以做得更稳”，但录屏不足以反推算法；要复制它需要检测/模型层面的
工作，不是本周期调 `alpha`/sticky 能解决。

### 11.3 采纳矩阵

| WPS 做法 | 判断 | 在本项目的落点 |
|---|---|---|
| 手动快门、无自动拍 | **直接采纳** | 已是默认 `autoCapture=false`；引导模式禁用自动快门（FR-005） |
| 单实线、无红/白锁定态 | **采纳显示原则** | 引导模式白实线 + 暗描边、框零自动移动（FR-002/003）；自动模式本周期不动 |
| 自动跟随页面 | **不直接照搬** | guided 用固定框换确定性；auto 要复制需更好的检测/模型，另立周期 |
| 粗框 + 拍后紧裁 | **改造后采纳** | 引导路径仍“成片=框”；WPS 式重裁只做 Review 可见提案/Toast + 撤销（T041） |
| 拍后“最佳滤镜” | **改造后采纳** | 新增 `document` 预设（白平衡/去阴影/锐化/对比），与 WPS 同页 A/B 后再定默认（T040） |
| 右页/整页候选自动切换 | **不照搬** | 用 `CaptureIntent` + 一次自动对位；不让候选逐帧决定框 |
| 折痕“处理掉” | **按裁切理解** | 先修页面边界/裁切；不做生成式去皱、不静默改 quad |
| 云空间/会员/账号 | **不采纳** | 纯离线铁律，与本项目无关 |

### 11.4 对当前方案的影响

- **主线不变**：`spec/guided-capture` 的引导框 MVP、手动快门、框零自动移动、
  Review 拆分确认仍是正确方向；WPS 录屏反而证明“框不必要每帧都准”。但要说
  清楚：WPS 实际是**自动跟随框**，我们的引导框是**固定框**，二者不是同款；
  本项目用一次对位换确定性，而不是宣称复刻 WPS 检测。
- **新增后续项，不阻塞本周期**：
  - `T040` `document` 预设：白平衡 + 去阴影 + 锐化 + 轻度对比；同页对比 WPS。
    现在 `.enhance` 的 `saturation=0.9` 偏降饱和，不能直接当“WPS 同款”。
  - `T041` WPS 式拍后自动裁边提案：Review 静帧重检，只接受**落在拍摄/引导框内**
    且高置信的页面四边形；显示“已自动裁边”提示 + 撤销；不静默改 quad。
    引导页默认不自动应用；由 Review 的“自动裁边”按钮按需触发一次检测。
- **不改变 SC-001~008**：T040/T041 是后续增强，不进入本周期硬门禁；
  当前验收仍是“引导框=成片、0 静默误裁”。
- **需要补的证据**：WPS 同页成片原图（不是录屏截图），以及彩色封面/插图页，
  才能判断“饱和度”到底是白平衡、对比度还是真的加饱和；录屏里的页面以
  黑白/灰阶为主，粗略采样同页纸面 YAVG 约 157→229、SATAVG 约 8.6→0.7
  （区域不完全对齐，只作方向），说明“更亮更干净”成立，但**不能证明**
  “全局加饱和”；你的观感可能来自白平衡/对比度，需用彩色页复测。

### 11.5 对“稳定框”的工程结论

WPS 的显示稳定可以拆成三层，不应混为一谈：

1. **检测层**：自动跟随页面，允许候选在右页/整页之间切换（录屏已发生），
   且不要求框紧贴；
2. **显示层**：单实线、无状态色，平滑跟随，避免把候选抖动暴露给用户；
3. **结果层**：手动快门 + 拍后重裁/滤镜，允许预览框有误差。

我们的 `QuadSmoother`/`CandidateSticky` 问题在**检测层和显示层耦合**：候选
变化会通过红/白状态和自动快门变成用户可见的“跳/锁错”。引导框把三层拆开：
显示层由用户固定，检测层只在“自动对位”时用一次，结果层由 Review 兜底。
这比继续调 `alpha`/sticky 阈值更能把“显示稳”和“意图对”分开；它不是复刻
WPS 的自动跟随，而是用固定框达到同样的确定性。

### 11.6 建议的验证（不阻塞 T000）

- 同一页、同一光线，拍 5 组：本 App 引导直裁 / 本 App 自动 + Review /
  WPS 万能扫描；记录：左折边入片、白底亮度、对比/饱和度主观、OCR/Word、
  处理耗时、是否手动修正。
- 若 WPS 仍明显更干净，优先做 T041（裁边），不要先做生成式去皱；若只是
  更亮，优先 T040（滤镜）；若右页仍框不住，回到引导框/意图，不要回自动阈值。
