## 一、问题与目标

用户实测：「稍微复杂一点的图片内容，最后生成 word 的样式会乱掉」。

- **图片版**（新增默认档）：整页图铺页 → 实测 **SSIM 0.914 / 0.919** ✅ 达标；
- **版面还原（可编辑）**档：底图 + 净化遮罩 + **浮动文本框**原位重排 →
  实测 **0.785 / 0.792** ✗ 不达标（本轮目标）。

**目标**：把「可编辑 + 保真」这条线推到**可用**：既能在 Word 里改字，又不出现
「同一行字出现两份」「文字压在图上自己的文字上」「表格错位」。

**明确不追求**：可编辑档的 SSIM 与图片版逐像素一致（**原理上不可能**——文字被
擦除后用另一套字体重排，笔画像素必然不同）。因此**门限口径要分层**（见 §四）。

## 二、2026-10-22 取证：差距到底来自哪里

### 2.1 分层归因（`Tools/word-fidelity/attribute.py`）

把 `out-restored.docx` 的 `word/document.xml` 拆成层级变体，各自渲染后与页面图比
SSIM：

| 层 | 含义 | SSIM |
|---|---|---|
| L0 | 底图 + 保留区裁剪（去遮罩、去文本框） | 0.722 |
| L1 | L0 + 净化遮罩 | 0.722 |
| L2 | 完整产物（+ 浮动文本框） | 0.790 |

### 2.2 归因结论（两条，都不是「文字重排」造成的）

1. **L0 渲染出来是空白页**（截图取证）→ 0.722 是「空白 vs 页面图」的分数，
   **不是**「底图摆歪了」。也就是说：**本机渲染器根本不画锚定图片**
   （`wp:anchor` + `behindDoc` 的底图/裁剪图）**。
   → **闸门的渲染器不可信**：QuickLook 只画内联图与文本框，不画锚定图/shape。
   → 用它测「可编辑档」= 测了个寂寞。
2. **L1 与 L0 完全相等** → 净化遮罩（`wps:wsp` 形状）**也没被渲染**（形状没有
   文字体 → 预览器跳过）。

### 2.3 关键发现：**模型是好的，坏在导出层**（2026-10-22 追加）

把「导出模型」本身离屏渲染出来（App 侧 `ImageRenderer` 渲染 `LayoutCanvas` /
`PageImageCanvas` —— 与导出**同源同坐标**，不依赖任何外部渲染器），再和 docx 的
外部渲染结果对比：

| 档位 | 导出模型 SSIM | docx 渲染 SSIM | **导出层损失** |
|---|---|---|---|
| 图片版 | 0.997 | 0.914 | 0.083 |
| **版面还原（可编辑）** | **0.984** | **0.767** | **0.218** |

**结论**：版面还原档的**版面模型是保真的（0.984）**——底图、遮罩、文本框的位置
与原页几乎一致。「样式乱掉」**全部发生在 OOXML 导出/渲染这一层**（损失 0.218），
两个机制：

1. **叠字**：净化遮罩是 `wps:wsp` 形状（无文字体）——**部分渲染器根本不画它**
   （本机 QuickLook 不画；实测 L1 与 L0 分数完全相同）→ 原文字没被擦掉，重排的
   文字又画上去 → **同一行两份字**。
2. **错位**：文本框用 OOXML 字体（styles.xml 里的 Calibri/宋体）→ 渲染端做**字体
   替换**后字距/行高与预览（SwiftUI 用的系统字体）不同 → 文字行整体漂移。

→ **下一步要修的不是「版面算法」，而是「导出层的表达方式」**（见 §五 G3'）。

### 2.4 顺带发现并已修（图片版）：页面尺寸是「巨页」

旧口径按 96 DPI 把 1633×2200 的页换算成 **41.5cm × 55.9cm** 的纸面（比 A4 大
一倍）。后果：Word 里是一张怪大的纸；预览器按自己的画布裁切 → 整页内容只露出
左上角一块。**本轮已改**：`.restored` 档的页面也改成 **A4 贴合**（与图片版同一
口径，`restoredPageSpaces` → `fittedPageEMU`）——相对布局不变（源像素 → EMU 仍是
纯线性缩放），纸面回到正常尺寸。

## 三、缺的是什么：一个**可信的渲染器**（本轮的前置）

没有可信渲染器，就没有「评估 / 取证 / 判断是否达标」的闭环。三条路：

| 方案 | 做法 | 评价 |
|---|---|---|
| A. **LibreOffice** | `brew install --cask libreoffice`；`soffice --headless --convert-to pdf` → PDF → PNG | ⚠️ **本机实测 headless 转换不出文件**（连 WPS 自产 docx 也不出，2026-10-22）→ 阻塞在环境侧，需换机器/换启动方式（GUI 首次启动后可能可用） |
| A'. **App 侧模型渲染**（已落地，**本轮的主力**） | 测试里用 `ImageRenderer` 离屏渲染 `LayoutCanvas`/`PageImageCanvas`（与导出同源同坐标）→ PNG → 宿主算 SSIM | ✅ 不依赖外部渲染器；直接量「**导出模型** vs docx 渲染」的差 = **导出层损失**（0.984 → 0.767），把责任层钉死 |
| B. **WPS Office**（本机已装） | 用 WPS 打开 docx → 导出 PDF → 位图 | **最贴近用户真实观感**（竞品自己的渲染器）；但 macOS 版无 CLI，需 GUI/AppleScript 驱动，脆 |
| C. **真机/桌面 Word 人工取证** | 导出 docx → 在 Word/WPS 打开 → 截图 | 最权威；不可自动化，只能抽样人工做 |

**决定**：以 **A 为主干**（可脚本、可回归），**B/C 作抽样复核**（每轮 1–2 张）。

## 四、口径分层（关键：两个档位用两个门限）

| 档位 | 目标 | 指标 | 门限 |
|---|---|---|---|
| **图片版** | 像素保真 | SSIM(渲染图, 页面图) | **≥ 0.90**（已达 0.914） |
| **版面还原（可编辑）** | 结构保真 + 可编辑 | ① **叠字率**：渲染图中原文字与重排文字**同时可见**的像素占比（目标 ≈ 0）<br>② **文字覆盖对齐度**：重排文字块与原文字块的 IoU 均值（目标 ≥ 0.8）<br>③ 表格/图位置偏差（目标 ≤ 2% 短边） | 见 §五各子目标 |
| 流式 | 可编辑 + 全文 | 段落流文本完整率 | 既有指标 |

> 为什么可编辑档不用 SSIM 门限：它的产物**按设计**就不是原页的像素（文字被擦除
> 后用别的字体重排）——用 SSIM 门限会把「设计如此」判成失败。可编辑档的失败
> 形态是**叠字/错位**，必须用**结构指标**量。

## 八、真机收尾（2026-10-24 / 25）

### 8.1 真机差异根因

同一张 `IMG_7544.jpg`，iPhone 13（iOS 27.0.1）的 `RecognizeDocumentsRequest`
把表格识别成 **3 列 × 4 行**，模拟器（iPhone 18 Pro / iOS 27.0）是 **2 列 × 5 行**：

- 右列被 Vision 从中间劈成两列（列框首尾相接，没有真实 gutter）；
- 第 3/4 行被并成一行，单元格里出现 `3 ... 4 ...`；
- 右上题头相邻两行因负行距、minY 差小于旧“同行阈值”，被按 minX 排序成上下颠倒；
- 右栏续行被 `indentJump` 拆成独立块。

### 8.2 修复

- 新增 `TableStructureRepair`：
  - 列框无间隙 + OCR 行跨过列边界（且正文区也有跨栏）→ 合并假列；
  - 用 OCR 行按 y/x 重建单元格，而不是拼接被劈开的 `cell.text`；
  - 行高 >1.3×中位且一列出现多个行首编号 → 拆回逻辑行。
- `OnDeviceReadingOrder.clusterRows` 改为按视觉中心自上而下排序；`clusterParagraphs`
  只在上一行未覆盖新行左缘时按缩进换段。
- 文本层增加统一 WPS/Word 校准偏移（`LayoutTypography.restoredTextHorizontalOffsetRatio`
  / `restoredTextVerticalLiftRatio`），预览与 DOCX 共用。
- 图片底图保持 2200px 长边、JPEG 1.0；表格仍走原生 `w:tbl` + TableBox。

### 8.3 最终真实 WPS 数字

| 场景 | WPS 渲染 vs 源页 | 证据 |
|---|---:|---|
| 模拟器 `original-base.jpg` | **0.906224** | `build/word-fidelity/realbase-wps-final/out-restored-realbase-wps.png` |
| iPhone 13 rendered 页 | **0.907581** | `build/word-fidelity/device-repro-wps/device-repro-wps.png` |

两口径均 ≥0.90。此前的 0.961/0.965 是 **QuickLook 代理**，不是 WPS 真实验收；
`docs/18` 已改为最终状态，避免把代理分数当门限。

### 8.4 残留问题（已记录，不在本轮继续）

- 背景图原字与可编辑字未严格重合 → 拍摄畸变/折痕造成的重影。用户决定**暂缓**，
  下一阶段先做页面预处理（裁掉页外、去折痕、页边拉直），见
  [`docs/19-page-preprocess-plan.md`](19-page-preprocess-plan.md) 与 `TODO.md`。
- 粗体行（Articles wanted / FUN ACTIVITIES）仍为常规字重；像素墨量推断误判率高，暂缓。
- 表格左/上内边距、右上题头顶部裁切、`Exam advice` 位置仍有小偏差。
