# 21 · 取景稳定性与拍摄意图复盘（2026-10-27）

> 本文回答四个真机体验问题：**取景框为什么跳、右页为什么拍进了左页、左页为什么定不住、
> 粉色封面为什么被洗白**。只做根因和方案，不把本轮当成已经修好。
>

## 一、结论先行

四个现象不是同一个 bug，主因按影响排序：

1. **自动取景没有“拍左页/右页”的意图**：默认 `captureMode = .auto` 走
   `DetectionStrategy` 的“最大/最稳候选”，摊开书天然偏整书或右页；即使检出右页，
   整书外框也会因包含关系胜出。左页没有独立候选，所以视频 4 必然拍成整摊。
2. **候选在“整书/右页”之间存在性交替**：`CandidateSticky` 只能维持 5 帧，
   超过后 escape；`QuadSmoother` 只平滑已选中的单个 quad，无法阻止候选切换。
   用户看到的就是红线框逐帧跳、白线框刚出现又消失。
3. **手动快门没有稳定门槛**：`CaptureViewModel.capture()` 直接读取快门时刻的
   `imageQuad`；跟踪态也能拍。白线锁定框出现且被按下时，成片通常正确；红线跟踪
   或切换瞬间按下，成片就带上左页/背景。用户的两段右页录屏正好对应这两种情况。
4. **`PageEdgeCleaner` 的红色清理越界到封面内容**：红色木纹清理在顶部 7% 高度内
   对**整行**生效，粉色封面属于高饱和红/粉，被当成桌面刷白。顶部粉带变白可以
   直接由这段逻辑解释；左右白边则是裁切框本身带进了桌面，`PageEdgeCleaner`
   只清右/上、不清左，属于第二个问题（彩色封面页面 mask）。

## 三、根因拆解

### 3.1 候选层：整书天然压制单页，且会周期性地切换

`DetectionStrategy.bestCandidate()`（`Zhixia/Services/Vision/VisionEdgeDetector.swift`）：

- 对包含在其他候选里的内部矩形乘 `containmentPenalty = 0.35`；
- 如果未降权最优被降权、降权后赢家反而更小，直接改选最大容器。

摊开书的“整书外框”和“右页内框”同时存在时，右页会被整书压制；右页单独出现时，
右页赢。于是候选池在 **整书 / 右页** 之间交替。`CandidateSticky` 的 v2
`holdThroughMiss` 只能保持 5 帧（约 0.17s），第 6 帧 escape 后重新择优，框就会跳一次。
这不是“平滑参数还不够小”，而是**候选集合和意图没有解决**。

另外，`EdgeSnapper` 在 live 每帧独立贴边（最大 6%），可能在不同帧吸到不同边缘峰；
它改善“贴边”，但不能保证“同一候选的边在时间上连续”。

### 3.2 显示/锁定：红线跟踪直接暴露逐帧变化，白线锁定只冻结一小段

`QuadSmoother`（`Zhixia/Services/Vision/QuadSmoother.swift`）：

- `alpha = 0.35`、`epsilon = 0.012`，单帧变化小于阈值就累计 `stableTime`；
- `frameDt` 固定为 `1/15`，而真机帧率约 30fps，锁定计时和真实时间不一致；
- 只平滑“已经选中的 quad”，候选切换时会重新起轨，轨迹不连续；
- 锁定后的白线用 `frozenQuad` 冻结，但锁定前/解锁后仍是逐帧红线。

用户因此会看到：**红线框一直在动 → 偶尔变白 → 很快又跳回红线**。白线出现的
那一小段时间是冻结的；其余时间取景框没有稳定的“所见即所得”承诺。

### 3.3 快门：手动快门允许在跟踪态拍，且取的是当前帧的框

`CaptureViewModel.capture()`：

- 文档模式下，`displayed = (directive != .closer) ? imageQuad : nil`；
- 只要不是“太远/无效”，就使用当前 `imageQuad`；**没有要求 `.locked`**；
- 只有 `phase == .capturing` 之后才停止帧消费；手动按下快门时，框正好在切换帧，
  就会把这个切换后的框写进 `PageDraft`。

这与用户观察完全一致：白线锁定框出现时按下，`frozenQuad` 是好的；红线跟踪或
“框刚跳”的时候按下，成片带左页/背景。默认 `autoCapture = false`，所以手动快门
是主路径，必须在按下时解决，而不能指望 6 帧自动快门确认窗。

已有一个已知几何问题也会放大边缘体验：自动模式 `previewSize` 来自父层安全区，
overlay 却是全屏渲染（`spec/guided-capture/tasks.md` 的待办），`visiblePhotoRect`
钳制和屏幕映射不是同一尺寸；靠近左右页边时，框可能被多裁/偏移。本轮先记录，
不把它当成四个问题的主因。

### 3.4 左页：没有自动模式意图，也没有左页候选

- `CaptureIntent` 只有引导模式 UI 暴露（`CaptureView.guideControls` 在
  `captureMode == .guided` 时才显示“右页/左页/整页”）；
- 自动模式没有把 intent 传给 `DetectionStrategy`，也没有把整书候选拆成左右页；
- `SpreadSplitter` 已能在矫正图上找书脊并 `split`，但它目前主要用在
  Review 的拆分提案/ImagePipeline 的折页裁切，**没有进入 live 候选**。

所以左页场景不是“框抖”，而是**系统不知道用户要左页**。视频 4 中提示“已对准”
只代表某个候选锁定，不代表锁定的是左页；最终 `F67F…` 是整摊图就是直接结果。

### 3.5 粉色封面：红色清理把“粉”当成“木桌”

`PageEdgeCleaner.cleanedBackground()` 的红色清理段（`PageEdgeCleaner.swift`）：

```swift
let topEnd = Int(Double(height) * 0.07)
...
let isTopEdge = y < topEnd
...
guard isTopEdge || x >= rightStart else { continue }
...
let redBackground = red > 0.18 && saturation > 0.20
    && red > green + 0.06 && red > blue + 0.03
```

- `isTopEdge` 为真时，整行所有 x 都参与红色判断；粉色封面完全满足“高饱和、红大于绿/蓝”；
- 清理段只在**已选中的页面图像**上运行，没有 page mask/内容保护；
- 顶部 7% 恰好覆盖封面顶部粉带，因此粉带被刷成白色。

左右白边不是这段红色清理造成的：`PageEdgeCleaner` 没有左清理，左白边更可能是
`pageBoundary` 选出的裁切框包含了桌面/页外区域；彩色封面没有“白纸”亮度/饱和度特征，
白纸包络和纸张边界模型对它不成立。这需要把“封面/彩色页面 mask”与“白纸页面 mask”
分开处理，不能只调红色阈值。

## 四、优化方案

### 阶段 0：粉色封面热修（先做，低风险，1–2 天）

目标：不再误洗封面；彩色页面宁可留一点背景，也不动页面内部像素。

1. **红色清理限制在页面 mask 外**：`PageEdgeCleaner` 只允许处理
   `pageMask == outside` 的像素；没有可靠 mask 时关闭红色/灰色顶部清理。
2. **顶部红色清理不再整行生效**：只在右边缘条（`x >= rightStart`）或
   “页面框外”区域生效；不要用 `isTopEdge` 横扫全宽。
3. **增加彩色/封面保护**：页面内部平均饱和度显著高于白纸、或红色清理准备修改的
   像素落在页面框内时，拒绝修改；页面内部 7% 粉带不得被改变。
4. **封面裁切用边缘/文档分割，不用白纸包络**：彩色封面允许“不自动裁”或交给用户
   四角/引导框；不要用 white paper envelope 硬套。
5. **回归 fixture**：`pink-cover-result.jpg` 对应原图 + DB quad；断言
   “页面内饱和像素保留、顶部不出现整条白带、成片尺寸不漂移”。同时保留
   round1-4 的 `2`/表格/尺寸断言。

验收：粉色封面成片顶部粉带保留；WPS realbase 仍 **0.906224** 且 PNG
byte-identical；无新增 `PageEdgeCleaner` 回归。

### 阶段 A：把“左/右页意图”变成可见、可执行的产品能力（2–3 天）

1. **自动模式也显示左页/右页/整页**（当前只在引导模式出现），切换后立即使候选
   选择按意图变化；默认右页是现有偏好，但用户必须一眼能改。
2. **左/右页候选合成**：在 live 检测到整书/书脊时，用低分辨率矫正图调用
   `SpreadSplitter` 找 `u`，生成 `left = split(u).left` / `right = split(u).right`；
   书脊不可靠时回退到中心线，但要有置信度并在 UI 上标明“建议框”。
3. **意图优先于容器降权**：`intent == .rightPage/.leftPage` 时，整书外框不能静默
   覆盖对应单页候选；若没有目标页候选，显示“未找到目标页”，不要拿整书凑数。
4. **引导模式作为书本场景兜底**：引导框是静态的，天然没有候选切换和红线抖动；
   左页/右页/整页默认框已有。建议在书本/摊开书场景把引导作为默认路径
   （或首次进入时提示“拍书建议引导”），A/B 后再决定自动/引导默认值。

验收：左页目标准确框左页；右页框不包含左页；用户切换意图的 2 步内可见反馈。

### 阶段 B：自动模式稳定锁定与快门一致性（3–5 天）

1. **候选级滞回**：新候选必须连续存在且优于当前锚点一段确认时间才允许切换；
   `holdThroughMiss` 从 5 帧延长到可感知的窗口（建议 0.4–0.5s），不要每 0.17s
   escape 一次；用户明显移动时仍要能解锁。
2. **用真实 `frame.timestamp` 计算 dt**：替换固定 `1/15`；锁定/解锁按**窗口内累计
   位移**判定，而不是逐帧差（保留现有文档的慢漂移修复结论）。
3. **清晰轮廓快速锁、模糊场景不冒充锁定**：高置信度、单页候选连续 4–6 帧即可锁；
   候选在整书/单页间交替时不显示白线“已对准”，应显示“寻找/左页/右页”状态。
4. **显示去抖**：跟踪框只在角点位移超过约 1% 时更新，或使用低通+死区；线型保持
   单实线，不再让红/白/虚线状态高频切换。锁定后沿用 `frozenQuad`，候选切换不得
   偷偷换框。
5. **按下快门即冻结**：`onTap` 的第一帧锁住呈现框和候选；手动快门若处于跟踪态，
   要么禁止（提示“等框稳定或用引导”），要么使用最近的稳定窗口并在屏上明确
   “按当前框拍摄”；不能把按下之后检测到的另一个候选写进成片。
6. **修复自动模式画布尺寸口径**：让 `previewSize` 与 overlay 使用同一全屏几何，
   避免边缘钳制和屏幕框偏移。

验收：无用户移动时框自动切换 0 次；候选变化不会造成 >2% 的单帧跳；锁定/解锁
在指定时间内可复现；手动快门成片 = 按下时屏幕框。

### 阶段 C：拍后安全网（与 A/B 并行，1–2 天）

1. 用现有 `ReviewViewModel` 的拆分提案，对“整书/左右页”成片默认显示
   “左页/右页/整页”一键提案；用户确认才写 quad，不静默改。
2. 左页误拍成整摊时，Review 第一屏即可选择左页并保存；这不能替代取景修复，
   但能避免用户重拍。
3. 彩色封面/页面不走 `PageEdgeCleaner` 的白色页面清理；Review 中保留手动裁切。

### 验收矩阵（回到录屏）

| 场景 | 目标 | 采样 |
|---|---|---|
| 粉封面 | 页面内粉色不白化；背景可白 | 录屏 1 + 3 个不同角度 |
| 右页、白线锁定 | 成片只含右页；背景不入片 | 10 张 |
| 右页、跟踪/跳框 | 不静默拍；提示稳定或明确冻结；成片可修正 | 10 张 |
| 左页 | 左页框/成片只含左页 | 10 张 |
| 平整 A4/单页 | 框稳定、自动快门（若开）不误拍 | 5 张 |

指标：候选切换次数/s、锁定延迟、屏幕框单帧跳变 p95、成片禁止内容入片率、
左/右页角点误差、用户需要手动修正次数。WPS 图片链路继续以
`0.906224` 和 PNG byte-identical 为不回退门限。
