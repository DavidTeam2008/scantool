# 22 · 取景框跟踪方案：从“单页锁定”转向“整摊包络 + 拍后拆页”（2026-10-28）

> 本文回答三个问题：**WPS 万能扫描的取景框为什么稳、是否值得我们仿、怎样在 Zhixia
> 的离线管线里落地。**
>
> 结论先说：WPS 的稳定感不是来自“每帧都准确识别右页/左页”，而更像是
> **持续跟踪一个整本书/整摊页面的外轮廓（近似包络），拍后再做页面拆分、
> 边界精修和透视矫正**。它允许取景框不完美，但不允许取景框来回消失/跳变。
> 我们当前把“用户选择右页/左页”直接当成“实时必须锁定单页四边形”，这个
> 约束过强，是视频 5 中左右页框频繁消失、最终成片退回全图/整摊的主要原因。
>

## 一、这次真机复现到底发生了什么

### 1.1 视频 5：右/左页框经常根本不出现

录屏 5（约 272s）覆盖彩色书和黑白书，按“右页 → 左页 → 整页”操作。可观察到的
稳定规律是：

| 场景 | 取景框实际表现 | 结果 |
|---|---|---|
| 彩色书右页 | 页面清楚可见，但多数时间**没有实线框**；偶尔出现后不能持续 | 按下快门后容易拍全图/整摊，成片带左页/桌面，透视也歪 |
| 彩色书左页 | 同样很难出现目标页框；整摊反而更容易出框 | 左页无法作为独立目标稳定锁定 |
| 黑白书右页/左页 | 页面黑白但边缘对比弱，目标页框经常不出现 | 手动拍后更容易走全图回退 |
| 整页 | 实线框更容易出现，但有时框很大，包含桌面/背景 | 整摊能拍到，但裁切/透视质量不稳定 |

关键帧：

- `video5-whole-frame.jpg`：整页意图时框出现，但包住整摊/桌面；
- `video5-color-timeline.jpg`、`video5-bw-timeline-*.jpg`：连续时间线；
- `video5-final-timeline.jpg`：整理/保存结果。

这不是“平滑参数还差一点”。页面目标不能出现，说明**目标页候选在检测/意图解析阶段
就被判空**；而整页路径走的是另一条“最大候选”路径，所以整页反而有框。

### 1.2 当前代码为什么会变成“无框 → 全图”

把现象和实现逐层对上：

1. **意图解析层过早返回 nil**
   `PageIntentResolver.resolve()` 在左/右页意图下只接受：
   - 已经符合侧别的单页候选；或
   - 能从整书候选上找到可靠书脊并拆分；或
   - 池中另一个符合侧别的页面候选。

   彩色书的页面边缘、曲面书脊、低对比黑白页都可能让 `SpreadSplitter` 找不到
   贯穿暗谷；此时直接返回 `nil`。这是“宁可回搜索态，也不拿整摊凑数”的
   保守策略，但它没有“保留一个可见的临时包络”的降级层。

2. **检测器把 nil 直接变成无框**
   `VisionEdgeDetector` 在页面意图路径上：
   ```swift
   guard var quad = effective?.quad else { return nil }
   ```
   `intentSelection` 为 nil 后，sticky 可能短暂 hold，但超过 hold 窗就回搜索；
   `QuadSmoother` 连续 miss 3 帧后进入 `.searching`，`imageQuad = nil`，
   `EdgeOverlayView` 就不再画框。

3. **快门没有“整摊包络”兜底**
   `CaptureViewModel.capture()` 在 `displayed == nil` 时走静帧检测；静帧若仍
   找不到目标页，最终落到 `.fullImage`。随后 `ImagePipeline` 的自由页面边界/
   包络可能把整摊、桌面、左页一起带进来，透视也不稳定——这就是用户看到的
   “歪、不是只有右页、没法用”。

4. **整页路径选的是“最大候选”，不是“书/页包络”**
   `DetectionStrategy.bestCandidate()` 的整页路径没有侧别约束，背景/桌面/整摊
   大矩形都可能胜出；视频 5 的整页框时大时小，原因不是帧不稳，而是候选身份
   不同。它能显示，不等于它稳定或正确。

5. **没有真正的“对象跟踪”**
   现有 `CandidateSticky` 是**候选层 IoU 粘滞**，`QuadSmoother` 是**选中 quad 的
   逐帧滤波**；两者都不是“把上一帧的书页轮廓通过光流/单应性传播到当前帧”。
   Vision 每帧重新找候选，候选一旦换成整摊/桌面/文字块，平滑器只能选择
   “跟着跳”或“短 miss 后消失”，没有连续跟踪的中间态。

### 1.3 最终成片为什么会歪

- 无框拍摄 → `.fullImage` 或整摊框；
- `ImagePipeline` 的自由裁切/内容包络没有“整摊/单页”的明确语义，不能保证
  只取右页；
- 彩色页/曲面页的纸张包络和黑白纸模型不一致，白纸阈值、背景清理会误判；
- 拍后没有以**高分辨率整书包络 → 书脊 → 单页**的确定性拆分作为主路径。

> 这不是再调 `epsilon/alpha/containmentPenalty` 能解决的问题。需要改变
> **取景框的语义**和**拍后处理的责任边界**。

## 二、WPS 万能扫描的行为观察

不能从黑盒确认 WPS 的具体模型，但从录屏可以稳定观察到以下行为特征：

1. **蓝色框主要跟踪整本书/整摊页面的外轮廓**，不是每帧都精确切换左页/右页；
2. 框一开始允许略大/略小，随后连续、缓慢地收敛到更贴合书页的位置；
3. 摄像机移动时框跟着移动，**没有每帧重新猜一个对象**的跳变感；
4. 框允许包含少量桌面/背景，也允许略微切掉书边；这不是它追求的第一目标；
5. 按下快门后，结果页是经过**拍后裁切/拆页/透视矫正**的干净页面（视频 6
   的蓝色框覆盖整摊，最后输出的是单页；这就是“取景框 ≠ 最终裁切框”的
   直接证据）。

关键帧：
- `video6-wps-spread-frame.jpg`：蓝色框包围整摊/书外轮廓；
- `video6-wps-result.jpg`：输出为单页；
- `video6-wps-timeline.jpg`：框的连续移动。

### 2.1 对 WPS 原理的合理推断

WPS 很可能采用“**检测 + 跟踪 + 拍后精修**”的组合，而不是单帧矩形检测：

- 检测：文档/书页轮廓或分割 mask，提供低频绝对位置；
- 跟踪：用帧间运动/光流/上一帧框，维持高频连续视觉；
- 显示：低通/滞回后的近似框，避免检测抖动；
- 拍后：高分辨率重新检测、找书脊、拆分页面、去背景、透视矫正。

这是一种非常合理且业界常见的方案：**实时阶段追求“连续、可操作”，最终阶段
追求“准确、可裁切”**。WPS 的框不是“最终裁切真值”，而是一个**拍摄包络**。

### 2.2 业界最佳实践的对应关系

无论 WPS 内部具体用什么模型，它符合业界文档扫描产品的共同结构：

1. **低频检测 + 高频跟踪**：检测负责“相对绝对的位置”，跟踪负责“帧间连续”；
   显示框不直接消费检测器的每帧结果。常见实现是光流/KLT/单应性传播 + Kalman/
   1€ filter，或 Apple `VNTrackObjectRequest` 一类对象跟踪。
2. **候选级滞回，不是逐帧择优**：只有新候选连续多帧与当前目标一致，才允许
   切换；检测短暂丢失时保留上一稳定框并降置信度。
3. **近似框 + 拍后精修**：实时框服务于“对准/构图”，最终页面由静帧上的
   文档分割、轮廓、透视矫正、页面拆分产生。Microsoft Lens/Adobe Scan/WPS
   这类产品都遵循“先拍到，再得到干净页面”的分层，而不是要求预览框就是成片。
4. **状态机与自动快门**：搜索 → 获取 → 跟踪 → 稳定/锁定；只有稳定且运动
   小时才自动拍，手动拍不要求绝对精确。
5. **可回退的交互**：自动框失败时仍有手动框/引导框；不会因为没有检测到目标
   就让快门产出全图。
6. **系统能力优先**：iOS 上先组合 `VNDetectDocumentSegmentationRequest`
   （语义文档 mask/quad）、`VNDetectRectanglesRequest`（直线边）、
   `VNGenerateOpticalFlowRequest`/对象跟踪（帧间运动）；不足时再上 Core ML。

### 2.3 合理性与可行性评估

| 方案 | 稳定性 | 单页准确度 | iOS 可行性 | 结论 |
|---|---|---|---|---|
| 当前：每帧选一个左/右页 quad，准了才显示 | 低 | 依赖单帧 | 高 | 不可作为主路径 |
| 每帧矩形检测 + 强平滑 | 中 | 低 | 高 | 只能做辅助 |
| **整摊/整书包络跟踪 + 拍后拆页** | **高** | **高（拍后）** | **高** | **推荐主路径** |
| 端侧分割模型 + 跟踪 | 高 | 高 | 中高（模型/性能/数据） | 第二阶段增强 |
| 直接实时精确锁单页 + 隐藏拍后裁切 | 中 | 中 | 高 | 用户信任风险，不推荐 |

我的建议是**混合**：

- 第一层：传统几何 + Vision 文档分割/矩形，先解决“框一直在、平滑、不跳”；
- 第二层：用低分辨率书脊/折页估计给左右页提供“输出意图”；
- 第三层：拍后高分辨率做页面拆分/边界精修；
- 只有在真实样本证明传统方案不足时，才引入端侧分割模型。

## 三、目标方案：一个包络跟踪器，三种输出意图

### 3.1 产品语义先改

把“右页/左页/整页”从**实时框目标**改成**输出目标**：

- 实时框：始终围绕**整本书/整摊页面**（或单页）的外轮廓；
- 右页/左页：在框内用书脊线/半透明高亮表示“拍完输出哪一页”；
- 整页：输出整个包络；
- 框不再因为“右页候选暂时找不到”而消失。用户先看到书，再看到目标页高亮。

这与 WPS 的行为一致，也符合用户真实任务：**我要的是页面文件，不是取景框本身。**

### 3.2 数据流

```text
相机帧 (30/60fps)
  → 降采样到 540p/360p
  → 观测层（每 2–3 帧）
      · VNDetectDocumentSegmentationRequest（文档 mask/quad）
      · VNDetectRectanglesRequest（书页/整摊的直线边）
      · 边缘/角点/书脊候选（SpreadSplitter 的低分辨率版）
      · 可选 Core ML 分割 mask
  → 候选整形（面积/内容/边界支持/侧别）
  → 跟踪层（每帧）
      · 用光流/单应性把上一帧包络传播到当前帧
      · 与低频观测做 robust fusion
      · 1€/Kalman 滤波 + 速度/加速度限幅
  → 展示包络（60fps，连续蓝色框）
  → 意图层：整页 / 左页 / 右页（只改变高亮和拍后输出）
快门
  → 全分辨率静帧
  → 包络精修（文档分割 + 边缘 + 纸张/彩色页面 mask）
  → 书脊/折痕检测 → 单页拆分或整摊
  → 内容安全门 + 透视矫正/去背景
  → 可见的 Review 预览（可切换整页/左页/右页）
```

### 3.3 观测层

**目标不是每帧得到最终单页，而是稳定得到“书/整摊”的观测。**

1. **文档分割**：`VNDetectDocumentSegmentationRequest` 提供文档 mask/quad，
   对彩色封面、浅色页面比纯矩形稳；每 2–3 帧在 540p 上跑一次。
2. **矩形检测**：`VNDetectRectanglesRequest` 补充直线边界，候选按面积、边界
   对比、覆盖内容过滤；拒绝文字块/表格块。
3. **边缘/书脊**：在包络 ROI 内找书脊/折页；**只在包络稳定后**用于高亮/输出
   意图，不作为每帧主候选。
4. **可选分割模型**：如果传统方案对彩色/曲面/低对比仍不足，引入轻量
   Core ML mask 模型（只输出 mask/quad，不生成页面像素）；离线、ANE、
   体积/时延 A/B 后再决定。

观测结果统一为：
```text
EnvelopeObservation {
  quad: Quad
  confidence: 0...1
  source: documentSegmentation | rectangle | edge | model
  timestamp
}
```

### 3.4 跟踪层

关键原则：**检测低频、跟踪高频**。

- **传播**：用 `VNGenerateOpticalFlowRequest` 或 `VNTrackObjectRequest` 估计
  帧间运动，把上一帧包络四角传播到当前帧；相机移动时先“跟着走”。
- **融合**：有观测时，以传播后的包络为先验，和观测 quad 做加权融合；观测
  与先验差异过大时先不切换，连续 K 帧一致才接受。
- **滤波**：每个角点用 1€ filter/Kalman（dt 使用真实 `frame.timestamp`）；
  限制单帧位移/加速度；显示层可以再插值到 60fps。
- **状态机**：
  ```text
  searching ──有观测──> acquiring ──稳定 250–400ms──> locked
       ↑                     │                         │
       └──持续无观测 >0.5s───┘←──用户明显移动/遮挡──────┘
  ```
  - `locked` 后不因单帧 miss 清框；保留最近包络 0.3–0.5s 并渐隐/标记“重新搜索”；
  - 重新捕获时从当前可见位置平滑收敛，不要从 fullImage 重新猜。
- **候选切换**：只有当新观测与当前包络 IoU/面积/中心连续性通过，并且连续
  N 帧优于当前，才允许换；换框时用动画收敛，不瞬移。

### 3.5 意图层：只做“输出语义”

- 整页：输出包络；
- 左页/右页：在包络内找书脊/折痕，输出对应半边；
- 单页/无书脊：左右意图都输出包络（或提示“未找到另一页，按整页输出”）；
- 实时只画一条书脊线/半边高亮，不把框切成两个独立候选；
- 用户切换意图时，包络不重建，只改变高亮；这样不会触发候选重选/框消失。

### 3.6 快门与拍后精修

1. **快门快照**：按下第一帧冻结包络 + 意图，不再更新屏幕裁切框；
2. **全分辨率精修**：
   - 在静帧上重新跑文档分割/矩形/边缘，得到更贴边的包络；
   - 用高分辨率 `SpreadSplitter` 找书脊/折页；
   - 右/左页按书脊拆；整页保留；
   - 彩色页面使用颜色/边缘 mask，不套白纸阈值；
   - 内容安全门保证不裁掉标题/页码/表格/插图；
3. **可见 Review**：预览页显示最终裁切结果 + “整页/左页/右页”切换；用户确认
   才保存。这样“拍后精修”不是隐藏换框，而是可见、可撤销的确定性步骤。
4. **意图要随页面保存**：给 `PageDraft`（或 session 元数据）增加 `outputIntent`
   （whole/left/right），拍后拆分按它选择默认结果；没有这个字段，Review 只能
   默认右页，用户拍左页仍会得到右页或手动再选。字段需兼容旧数据（默认 whole）。
5. **拍后失败回退**：如果书脊/页面不明确，回退到包络（整页）并提示用户选择，
   不再回退 `.fullImage` 后自由检测。

### 3.7 视觉与交互

- 采用 WPS 风格的**蓝色/白色细实线 + 暗描边**，不再用红/白两态高频切换；
- 框一直可见，用透明度/细线表示置信度，而不是“没找到就消失”；
- 状态文案从“已对准/搜索中”改为“已找到书页 / 正在微调 / 请移动远一点”；
- 保留手动拖框/引导模式作为兜底，但引导模式不再是唯一能获得稳定框的路径。

## 六、验收指标（建议先量化再调参）

| 指标 | 目标 |
|---|---|
| 首帧后框可见率 | ≥95% 的页面帧 |
| 无框连续时长 | ≤150ms（完全无页面除外） |
| 单帧框跳变 p95 | ≤短边的 0.5% |
| 候选身份切换 | ≤1 次/5s，且连续 3 帧确认 |
| 锁定延迟 | 清晰页 ≤0.6s |
| 右页输出正确率 | ≥90%（彩色/黑白各） |
| 左页输出正确率 | ≥90% |
| 内容丢失 | 0（标题/页码/表格/插图） |
| 背景残留 | 先允许少量，Review 可修；目标 <5% 页边 |

> “框可见率”必须高于“框绝对准确率”。WPS 的体验已经证明：用户更怕框消失/跳，
> 而不是框边缘偶尔多 1–2% 背景。

## 七、为什么这比继续调当前方案更可行

- 当前方案的上限是**单帧检测器**：彩色/曲面/低对比页面每次都可能给出不同候选，
  单靠平滑无法弥补“根本没有目标候选”的帧；
- 包络跟踪把问题变成**连续对象的时域估计**，符合视觉跟踪的经典假设；
- 单页意图不再要求实时精确，改由拍后高分辨率拆分，降低实时算力与误判；
- WPS 的录屏已经验证了这条产品路径：框近似、平滑、可见，结果页由拍后处理；
- 仍然完全离线，不需要云端/LLM；可选分割模型只输出 mask。

## 八、明确不做/暂不做

- 不继续围绕 `containmentPenalty`、`epsilon`、`alpha` 微调，期待单帧候选变稳；
- 不要求实时显示“精确左页/右页四边形”后才允许拍摄；
- 不在无框时静默用 `.fullImage` 落盘；
- 不把整摊/桌面最大矩形当作整页真值；
- 不引入生成式修复/LLM 像素；
- 不在没有 20+20 场景 A/B 前切换默认模式。
